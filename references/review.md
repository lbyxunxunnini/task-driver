# 审查与修复

输入包括当前有效目标、当前产物、实际验证证据和有效权限。被用户新范围取代的旧目标必须标为 `superseded`。本模块必须输出逐项目标的判断、证据缺口、回归问题及处理路径。验证负责取得事实，本模块判断事实是否足以证明结果，最终完成状态由主控决定。

## 审查发现的范围判断

验证、自查、独立复核和用户验收反馈共用同一范围，涵盖当前验收目标及适用约束，以及本次改动引入的新问题或加重的既有问题。即使受影响功能未列入目标或已排除独立验收，改动造成的回归仍必须处理。必须用差异、调用路径、日志或实际观察说明关联和影响，并定向核实有具体依据的疑点。禁止仅因同处一个文件、页面或模块，或仅凭假设的触发路径扩大检查。

- **范围内**。缺少证据时必须补证。确认缺陷后必须按授权做最小修复。对回归必须优先修正引发问题的改动，消除本次造成的退化，再定向复验。回归属于本次完成缺口，无需增列验收目标。超出权限的修复必须按异常分类处理。
- **范围外**。必须保留已有事实供[完成后汇总](#完成后汇总范围外问题)，并继续原任务。禁止据此触发补测、修复或复审。用户另行指定验证时，必须按其要求取证和报告，并沿用原约定的修复权限和通过条件。

补测、修复或复审前，必须说明要处理的范围内缺口或因改动失效的证据，再按[取证顺序](verification.md#验证前限定范围)判断该发现是否阻塞下一项验收。必须在完成前补齐仍必要的处理。证据和审查齐备后必须按主控收口。禁止仅因有剩余额度继续检查。

## 完成后汇总范围外问题

必须在当前对话或已有任务记录中合并重复发现，简述问题、已有依据或影响及修复状态，并标明尚未核实的疑点。

最终回复必须先报告原目标结果，再按交付范围汇总已有发现。空清单必须省略。可以询问是否另行处理及处理哪些，最多一次，问后必须结束本轮。用户只要求只读核对或报告、明确要到此结束或要求不提问时，交付允许报告的发现后必须直接结束。只读核对缺少必要信息且仅用户掌握时，可在交付前询问该信息。实际修复必须由另行明确发起的任务承接。

## 主模型审查

无论是否开启独立复核，主模型都必须按当前有效验收目标逐条审查最终产物及实际交付证据。尚未交付时，必须先审待交付的最终内容并完成当前可做的验证。禁止因关闭子代理、产物已生成或需要主观验收而跳过检查。无法核实时必须说明。禁止用生成指令、计划、参数、文件存在或局部检查代替实际结果证据。

```text
主模型审查实际交付或待交付的最终内容
├─ 范围内可修复问题 → 打回 → 修复 → 重新审查 ↺
├─ 证据不足、待必要验收/授权或受阻 → 异常分流 → 条件变化后承接
└─ 已完成实施，当前可做的自检通过
   ├─ 未开启独立复核 → 主控按当前目标复查
   └─ 已开启独立复核 → 未参与实现的子代理按授权范围复审
   → 主控修复及复验受影响部分，补齐必要证据并判定完成
```

必须逐项依据当前有效目标、产物和证据判断质量，禁止新增标准或扩大检查范围。必须保留用户以新范围明确取代的旧目标原文和 `superseded` 关系，禁止继续把旧目标用作当前审查标准。必须将结论交给主控，由主控决定完成转换。质量判断分为达标和未达标。

| 判断 | 标准 |
|---|---|
| 达标 | 必须有证据支持全部必要结果，并确认范围内无已知缺陷或回归破坏 |
| 未达标 | 目标未满足，存在范围内瑕疵、体验问题、覆盖不足或必要证据缺失。必须先分类。禁止包装为完成、基本达标或残余风险 |

### 异常分类

未达标或无法判断时，必须先区分产物缺陷与证据缺口。仅缺尚未执行的必要验证，且现有环境和授权足够取证时，必须返回[验证取证](verification.md)，禁止计入修复次数，取得证据后必须重新审查。存在实际缺陷或无法直接取证时，必须按当前阻断条件进入下列路径。同一目标有多个缺口时，必须保留其余缺口并在处理后重新判断。

| 路径 | 触发条件 | 必须动作 |
|---|---|---|
| 可修复 | 已确认属于当前范围且授权内能处理的缺陷，例如实现、测试、参数、路径、格式或引用错误 | 必须打回修复并重新审查。必须计入修复次数 |
| 需要用户验收 | 主观感受、真实设备、私有账号或无法访问的环境决定结果 | 必须先完成自身检查，再按验收通知取得反馈。禁止计入修复次数 |
| 需要用户授权或决定 | 缺权限、凭据、费用授权、范围选择或其他用户决定 | 必须立即停止相关执行并请用户决定。禁止计入修复次数 |
| 受阻 | 外部服务无替代路径、必要条件无法满足或无可靠方案 | 必须说明原因与状态，停止机械重试。禁止计入修复次数 |

用户明确指定本任务循环上限时，必须采用该上限并记录。用户未指定时，同一最终目标的修复次数禁止超过 8 次。上限无须用满。每次修复必须改变策略或修复内容，并记录失败原因、相对上轮的调整、复验证据与结果、是否复现。相同原因与处理方式反复失败时，必须停止盲试并检查计划。无可靠方案时必须标为受阻。

最后一次允许的修复后仍必须完成复验。复验成功时必须核对其余完成条件。用尽额度后的处理见[达到上限后的结论](#达到上限后的结论)。修复与独立复核必须分别累计次数。角色切换、中断、恢复或更换模型时禁止重置任一计数。任一额度先耗尽时，禁止借另一额度继续无法闭合的循环。

| 打回原因 | 返回位置 |
|---|---|
| 实现或产物未做到 | 必须按授权修复并重新审查 |
| 计划步骤不足，最终目标不变 | 必须检查并调整受影响步骤，重新展示并取得确认。旧执行回执必须失效，随后必须重新 `begin` |
| 验收目标本身有误 | 必须停止相关执行并返回验收目标讨论 |

### 统一异常通知

异常通知必须使用“当前结果、原因、已完成、下一步”。发出前必须读取或复用[统一异常通知骨架](templates.md#统一异常通知骨架)的分类补充与展示限制。

[进度锚点](state-recovery.md#进度锚点)用于执行途中的只读路线复查。结果必须仅作为主控判断的输入。禁止用其替代本模块的目标判断、异常分类或完成门槛。无论是否执行，禁止表述为已独立检查或独立审查。

## 独立复核要求

用户已开启独立复核，或明确委托模型决定子代理设置且模型按收益和条件选择开启独立复核时，实施完成、主控当前可做的自检通过后，必须由未参与实现的子代理追加独立复核。其他情况下由主控自检后复查，再修复及复验范围内缺陷。执行阶段是否使用过子代理不改变本节。

主模型完成当前可做的自检后，独立首审可核查待交付的最终内容及已有客观证据。通用复核必须一并核查已取得的用户验收和交付证据，尚未发生的必须标为待补。App、H5 采用下一段规定的静态复审范围。禁止把预审通过写成整项目标达成。必须先交付才能取得用户验收时，交付后必须按实际反馈承接。产物变化时，必须按[修复后证据有效性](#修复后证据有效性)复审。若宿主发送最终正文后无法调用工具，必须先复核待交付内容，再按主控交付并保留待同步。禁止声称已独立核查尚未发生的送达或验收。审查中新发现的缺口必须按[异常分类](#异常分类)处理。

App、H5 的独立复核只读源码、改动和相关静态材料，核对实现逻辑、代码缺陷和本次改动可能造成的回归。子代理必须报告审查范围、覆盖缺口、具体问题及依据，或说明覆盖内未发现问题；禁止运行 App、设备、浏览器或测试，禁止代判整项目标或用户验收。界面与交互实际效果、用户反馈及最终达成由主控核对。相关运行证据在复审前后由有权的一方取得，不影响当前代码复审范围。

| 要求 | 必须遵守的规则 |
|---|---|
| 职责与标准 | 子代理必须仅负责审查，主模型必须负责修复。必须先按[范围判断](#审查发现的范围判断)限定检查。遇到具体范围外问题时，必须将已知事实另附给主模型，禁止为此扩大检查或写入目标状态、阻断原因或回归破坏 |
| 上下文 | 首审和复审均必须使用独立上下文。宿主不支持、启动失败或代理无法完成时，必须先核实原代理及现场。确认不可用且接手不会重复操作后，主模型必须按目标和原验证标准继续审查，禁止再次询问是否开启。最终必须说明未独立复核及原因。原代理仍运行或状态未知时，禁止接手同一工作。禁止把代理不可用当作审查通过、降低标准或声称独立复核通过 |
| 材料交接 | 首次交接必须读取或复用[独立审查交接模板](templates.md#独立审查交接模板)。首审必须仅省略“本次变更（仅复审）”字段，并把判断回归所需的基线和当前差异归入客观证据。范围与限制必须包含影响判断的已确认业务口径、验收边界及来源。必须仅提供当前审查所需内容，禁止附完整讨论历史或审查结论 |
| 目标与权限 | 必须原样提供目标，为流程事实提供可核实的消息记录。禁止附达成状态或扩大核实权限 |
| 规则交付 | 必须交付范围判断、本节输入检查和输出要求原文，或明确要求先读取可访问协议位置 |
| 输入检查 | 禁止提供执行者自评和前次审查结论。子代理必须先检查输入。违规时必须仅报告“无法判断：审查输入不合规”，禁止继续判断目标达成 |
| 输入纠正 | 必须保留原记录，相关目标必须保持未完成。移除违规内容后必须以全新独立上下文重审，并计入审查次数。禁止删改原审查报告冒充通过 |

### 审查维度

通用独立复核对每条目标必须输出以下字段。App、H5 只按上节输出静态代码结论，由主控填写目标结论。

| 字段 | 输出要求 |
|---|---|
| 状态 | 整项必要结果有证据支持时为达成，已证实不满足时为未达成，必要证据不足时为无法判断。定向补审必须仅对本轮覆盖的必要条件给结论并标明范围。主模型必须合并适用于当前产物的独立证据后再判断整项 |
| 证据 | 必须写明来源、实际覆盖和未核实部分，证据必须支持该状态。未找到时必须写“未找到” |
| 阻断原因 | 未达成或无法判断时，必须写明具体缺口与对应验收项、明确约束或本次改动引起的回归。分类为受阻时还必须说明无法取得必要条件的原因 |
| 回归破坏 | 无 / 有 / 无法判断。必须说明依据及覆盖范围，不适用时必须说明原因。无法归入单个验收项的改动回归必须另列为本次缺口 |

### 结论承接

主模型必须逐条核对正文与证据，禁止只采信汇总。预审中仅因尚未交付或等待必要验收而无法判断时，必须在证据正文说明内容审查覆盖及结果，保留有效证据，按主控实际交付或等待反馈。禁止把预审写成整项目标达成。其他未达成、回归或无法判断必须按本模块分类。达成且无回归时，必须回到[主控完成门槛](../SKILL.md#完成门槛)。修复及复审必须遵守[证据有效性要求](#修复后证据有效性)。

独立复核完成要求当前产物上应由独立复核核对的必要结果和相关回归检查全部通过。App、H5 必须核对代码静态复审覆盖且无待修复的范围内代码问题，由主控独立核对目标证据。原报告总评为未通过时，采信完整有效的逐项结论来满足该门槛，必须先核实唯一否决原因属于范围外，且项目和宿主均未要求总评通过。必须保留原报告及调用次数，交付时必须如实说明原总评、否决原因和当前范围内的独立判断。若仅缺必要独立判断，必须按原要求定向补审。范围内失败、原因未明或存在更严格门槛时，必须按[异常分类](#异常分类)处理，无法满足时必须说明受阻。

未另有明确约定时，独立审查次数禁止超过 8 次。首审、复审及输入不合规后的重审均必须计入独立审查次数，与修复次数分别累计。已审查内容发生变化时，必须按[修复后证据有效性](#修复后证据有效性)复审。达到上限仍未通过时，必须按下节收口。每次修复后是否还有复审额度，以实际计数为准。

## 达到上限后的结论

达到相应修复或独立审查上限，且完成当次必要复验后仍未达成时，必须停止该循环，禁止继续盲修。

必须说明已完成内容、未达成目标、无法继续的原因、需要用户提供或选择的事项，以及当前代码/分支/文件状态。禁止包装成完成或声称通过。

## 修复后证据有效性

修复后必须自检并补做受影响的验证。独立复核已开启且可用时，必须复核该改动、直接受影响的结果及尚未闭合的必要缺口。确认不可用且可安全降级时，必须由主模型重新审查，仍必须遵守宿主和项目更严格的完成要求。即使只改文案或测试，也必须核实影响。未受影响的有效证据可复用。任务记录必须保存实际修复次数、策略变化和复验证据。

仅补充证据且产物未变化时，必须针对原缺口核查新增证据及其与当前产物的对应关系，并复用未受影响的审查结果。禁止声称未经独立核查的新证据已通过独立复核。独立复核开启时，针对新增证据发起的复核必须计入既有审查次数。已通过内容预审后补到的实际交付或必要用户验收证据，必须由主模型按[独立复核要求](#独立复核要求)及[主控完成门槛](../SKILL.md#完成门槛)核对。禁止仅因补到这类证据就自动重新独立复核。

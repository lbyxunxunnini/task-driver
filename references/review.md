# 审查与修复

输入：目标原文、当前产物、实际验证证据和有效权限。输出：逐项目标是否满足、证据缺口、回归问题及处理路径。验证负责取得事实，本模块判断事实是否足以证明结果；最终完成状态由主控决定。

## 主模型审查

无论是否开启子代理，主模型都必须按最终验收目标逐条审查实际交付，完成自身可做的验证。不得因关闭子代理、产物已生成或需要主观验收就跳过检查；无法核实必须说明，生成指令、计划、参数、文件存在或局部检查不能代替实际结果证据。

```text
主模型审查实际交付
├─ 可修复问题 → 打回 → 修复 → 重新审查 ↺
├─ 证据不足、待必要验收/授权或受阻 → 异常分流 → 条件变化后承接
└─ 可执行检查通过 → 补齐必要交付/验收及证据 → 复核整项目标
   → 独立复核【开启且首审前提满足时】 → 共同完成判定
```

问题来自主模型、子代理或用户验收，都适用本节；独立复核章节只追加独立复核要求。

每项目标按原目标、产物和证据给质量判断，不得新增标准或超出检查范围；结论交主控，完成转换不在本模块重复定义。质量判断分两档：

| 判断 | 标准 |
|---|---|
| 达标 | 全部必要结果有证据支持，已确认范围内无已知缺陷或回归破坏 |
| 未达标 | 目标未满足，存在范围内瑕疵、体验问题、覆盖不足或必要证据缺失；必须先分类，不得包装为完成、基本达标或残余风险 |

### 异常分类

未达标或无法判断时，先区分产物缺陷与证据缺口。只有必要验证尚未执行、现有环境和授权足够取证时，直接返回[验证取证](verification.md)，不计修复次数；取得证据后再审查。存在实际缺陷或无法直接取证时，按当前阻断条件进入下列路径。同一目标有多个缺口时保留其余缺口，处理后重新判断，不漏条件。

| 路径 | 触发条件 | 必须动作 |
|---|---|---|
| 可修复 | 实现、测试、参数、路径、格式、引用错误，约定范围内可自行补齐的覆盖遗漏，或有明确替代方案 | 打回修复，再审查；计入修复次数 |
| 需要用户验收 | 主观感受、真实设备、私有账号或无法访问的环境决定结果 | 先完成自身检查，再按验收通知取得反馈；不计修复次数 |
| 需要用户授权或决定 | 缺权限、凭据、费用授权、范围选择或其他用户决定 | 立即停止相关执行，请用户决定；不计修复次数 |
| 受阻 | 外部服务无替代路径、必要条件无法满足或无可靠方案 | 说明原因与状态，停止机械重试；不计修复次数 |

用户明确指定本任务循环上限时采用该上限并记录；未指定时同一最终目标最多修复 3 次；上限不要求用满。每次修复必须改变策略或修复内容，并记录失败原因、相对上轮的调整、复验证据与结果、是否复现。相同原因与处理方式反复失败时必须停止盲试、检查计划；无可靠方案则受阻。

最后一次允许的修复后仍必须完成复验；成功则核对其余完成条件，仍未达成才停止继续修复并进入“达到上限后的结论”。独立复核次数另按独立复核章节计算，两者不因角色切换或恢复而重置；额度先耗尽时，不借另一计数继续无法闭合的循环。

| 打回原因 | 返回位置 |
|---|---|
| 实现或产物未做到 | 执行修复，再审查 |
| 计划步骤不足，最终目标不变 | 检查并调整计划，继续执行 |
| 验收目标本身有误 | 停止相关执行，返回验收目标讨论 |

### 统一异常通知

异常通知必须使用“当前结果、原因、已完成、下一步”，发出前读取或复用[统一异常通知骨架](templates.md#统一异常通知骨架)的分类补充与展示限制。

## 独立复核要求

仅在用户已开启时追加；未开启仍必须走本模块闭环与完成判定，不得擅自分派子代理。首审必须在主模型自检整项目标达标后自动触发：所需实际交付、必要用户验收与证据均已具备；不得在已知必要证据缺失时机械发起。审查中新发现的缺口仍走异常分流。

| 要求 | 必须遵守的规则 |
|---|---|
| 职责与标准 | 子代理只审查，主模型修复；依据原目标及客观证据，不以自评代替证据，不降标 |
| 上下文 | 首审和复审均使用独立上下文；无法提供或工具不可用时说明并走异常路径，不静默关闭或声称已审查 |
| 材料交接 | 首次交接读取或复用[独立审查交接模板](templates.md#独立审查交接模板)；仅“已确认目标、范围与限制、当前产物与客观证据、本次变更（仅复审）”四字段，首审不附变更，不另附背景 |
| 目标与权限 | 目标原样提供、不附达成状态；不扩大核实权限，流程事实提供可核实消息记录 |
| 规则交付 | 必须交付本节输入检查和输出要求原文，或明确要求先读取可访问协议位置 |
| 输入检查 | 禁止执行者自评和前次审查结论；子代理先检查，违规只报告“无法判断：审查输入不合规”，不得继续判断目标达成 |
| 输入纠正 | 保留原记录；移除违规内容后以全新独立上下文重审，相关目标保持未完成；不得删改原审查报告冒充通过，重新发起仍计审查次数 |

### 审查维度

每条目标必须输出：

| 字段 | 输出要求 |
|---|---|
| 状态 | 达成：整项必要结果有证据支持；未达成：已证实不满足；无法判断：必要证据不足 |
| 证据 | 来源、实际覆盖、未核实部分；未找到写“未找到”，必须支持该状态 |
| 阻断原因 | 未达成或无法判断时填写具体缺口；分类结果为受阻时同时说明无法取得必要条件的原因 |
| 回归破坏 | 无 / 有，说明原有功能是否受损 |

### 结论承接

主模型必须核对每条正文与证据，不只采信汇总。达成且无回归时返回[主控完成门槛](../SKILL.md#完成门槛)；未达成、回归或无法判断均按本模块分类。按下述证据有效性要求处理修复及复审。

未另有明确约定时，独立审查最多 3 次，首审、复审及输入不合规后的重审均计入，与本模块修复次数分别累计。达到独立审查上限仍未通过时进入“达到上限后的结论”；不是保证可修复三轮。已审查内容发生变化时按本模块复审，未受影响的有效证据可复用。

## 达到上限后的结论

达到相应修复或独立审查上限，且完成当次必要复验后仍未达成时，必须停止该循环，不继续盲修。

必须说明已完成内容、未达成目标、不能继续的原因、需要用户提供或选择的事项，以及当前代码/分支/文件状态。不得包装成完成或声称通过。


## 修复后证据有效性

修复后自检并补做受影响验证；独立复核开启时，对改动及其影响重新复核。即使只改文案或测试，仍核实影响，不能直接沿用旧版本结论；未受影响的证据可复用。任务记录保存实际修复次数、策略变化、复验证据；中断、换代理或换模型不重置额度。

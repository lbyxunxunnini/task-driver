# 按参考稿实现与验收

按[主控路由](../SKILL.md#协议结构与模块路由)读取。把对照基准、实施方法和实际证据带入对应环节，沿用已确认的授权与验收范围。

## 开工前核对

- 确定当前参考版本、目标页面或控件、基准画布宽度、目标环境和对应页面状态。区分设计逻辑尺寸与截图像素尺寸。HTML 原型要实际打开，观察相关交互与宽度变化。静态稿未展示的行为或状态，先查交互标注、项目实际行为和已确认要求。
- 先看完整画板和相关状态，定位本次区块与上下游区域、同组控件、共用样式及有意差异，再逐层查实际实现。开工前把本次适用的设计差异带入现有分析与计划。核对尺寸、位置、对齐、内外间距、图标、颜色，字体资源、字号、字重、字距和行高，以及渐变的颜色、方向和色标，遮罩的边界、层叠和透明度。记录具体设计值、对应实现位置及待核实项。参考没有定义且会影响本次结果时，按实际缺口处理。
- 参考稿的相关状态出现内容被裁切、渐隐、覆盖或只在指定形状内显示时，查该状态的设计图层或原型实现，识别遮罩作用的对象、可见范围和滚动或切换状态后的行为。在开工分析写明这些边界及对应现有实现，并带入真机或预览验证。
- 素材缺失时先查项目资源和设计源文件，能取得或导出的自行补齐。仍缺关键素材且会改变结果时，在改动受影响部分之前告知用户。说明具体资源及版本、影响位置和结果、用户需要提供的文件或有效访问方式，并说明其他能独立推进的部分。新要求与参考稿明显冲突且优先级未定时，指出具体差异和对结果的影响，由用户决定采用哪项要求。

## 计划与实施

- 在现有计划中明确涉及的页面、组件和相关状态，预留实际对照、修正和复查的步骤。涉及多屏适配时，写明基准宽度、代表性的其他宽度及各自要观察的结果。将用户要求的渲染或交互结果列入对应目标的通过条件。组件选择、尺寸换算和取证动作进入实施方案或内部验证。
- 按参考值落实相应层级和属性。字号、字重、字距、行高及控件间距分别核对。定位差异时，沿外层约束、组件默认值和最终计算结果找到产生偏差的位置，再修改该处。
- 涉及同组控件时，先对照参考稿与当前页面中的同级入口。首次向用户给出具体改法时，在已有答复中点名目标控件和已对照的同组入口，说明共用样式、各状态或现状与参考有差异的地方。共用的图标、箭头、颜色、尺寸、位置和状态样式优先采用同一套组件或实现。修改共用实现时核对直接受影响的调用处，按已确认范围处理发现的问题。

## 多屏适配

- 开工前以基准画布和项目适配规则为依据，明确哪些文字、宽高和间距等比缩放，哪些固定、随容器伸缩或按断点重排。参考只给一个宽度时，先查同类页面的适配行为。
- 开工前在源码中定位现有排版组件、尺寸换算工具和同类调用，确认基准宽度、缩放系数来源及输入值口径。新增或修改缩放文字时，先核对项目是否已有接收设计字号的组件。适用时在计划中列明组件和字号输入并直接接入。宽高和间距也分别写明所用封装或换算方法及输入值。确需统一缩放且项目缺少相应能力时，在计划中纳入公共层的共用工具或组件，并让本次涉及的控件实际接入。
- 采用同一等比例策略的文字、控件宽高和间距必须使用同一设计基准和对应系数。交付前沿实际调用链核对选定封装是否接入，确认组件接收原始设计值或换算值的口径，以及每个设计值只换算一次。

## 交付验收

- 从正常入口打开当前界面，在同一基准宽度和页面状态下，对开工前识别的适用属性逐项取实际渲染证据。对照间距、位置、图标、颜色、渐变的可见方向和颜色分布，以及遮罩实际覆盖、裁切或淡出的位置。结合最终渲染或测量核对字号、字距、行高与控件尺寸，沿实际字体引用或打包资源核对家族、字重和指定版本。把每项观察落回现有验证结果，证据不足时注明具体属性。
- 将直接受影响的同组控件放在一起复查，切换相关状态并实际触发改动涉及的交互。涉及多屏适配时，在基准宽度与有代表性的其他宽度下核对实际页面，检查缩放、伸缩或重排是否符合约定。
- 有依据且具备条件的差异在交付前修正，再复查受影响的范围。按[验证模块](verification.md)记录实际观察、证据及覆盖。仍存在差异或无法取证时，说明具体位置、参考要求、实际结果或未能观察的内容、阻碍和需要用户协助的事项。

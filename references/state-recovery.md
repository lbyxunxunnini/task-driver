# 状态记录与恢复

输入：主控状态、有效决定与来源、计划目标、实际操作及证据。输出：同一份可恢复任务记录，或恢复后的状态与下一动作。主控决定何时调用；讨论、执行、验证模块提供变化；本模块保存并核对，不替用户确认或授权。

## 何时建立记录

用户要求长计划、记录或防丢失、讨论超过 20 轮或决定与依赖多到难以可靠承接、预计长执行或跨轮执行、多模块或外部系统任务、重要副作用操作、可能上下文压缩或已发生中断时，进入持续记录模式。任一条件满足即采用；普通短任务不新增记录。用户禁止写文件时不写，说明持久恢复限制，在对话内保留必要状态。

复用 `.task-driver/{任务标题}-{时间戳}-计划摘要.md`，同一任务仅一份；已存在则继续更新，不因换环节、压缩或重启另建副本。记录不保存凭据或秘密，只记录安全引用。用户指定已有记录位置时沿用。路径未知时先枚举任务记录，结合记录内目标、工作目录和最近未决事项定位；不能只凭相似标题选定。多个候选无法唯一确认时只问用户要续接哪项，不擅自新建或合并。

进入记录模式时告知用途，无需再索取已授权的记录许可。格式见[轻量计划摘要模板](templates.md#轻量计划摘要模板)。长计划是否需要记录优先依据用户要求和跨轮、依赖复杂、外部副作用等实际条件，不设机械的文件数阈值。先保存并核对成功，再进入依赖该记录的下一动作。

## 变化与保存时机

| 时点 | 必须保存的变化 |
|---|---|
| 记录模式中的每次用户回答 | 实际回答对象、决定的来源/性质/适用范围、未答部分、派生事项和下一问题；保存后再提问 |
| 长计划开始编制前 | 先保存有效需求、已决事项、计划待编制部分和续接位置；编制过程中更新草案进度，未授权时不得记为可执行 |
| 长计划开始执行前 | 有效计划、目标、通过条件、授权范围、各步骤状态和首先执行的动作 |
| 计划项完成或验证产生结论 | 实际产物、安全证据引用、步骤状态、目标验证状态以及下一项 |
| 改变需求、计划、授权或证据 | 新决定的依据、失效部分与仍然有效部分；不静默改写用户原要求 |
| 准备执行重要副作用动作 | 动作对象、授权、执行意图与可查询的进程/任务/结果标识；返回后补记结果与阶段检查点 |
| 等待、受阻、主动暂停或预计中断 | 原环节、暂停原因、恢复条件、未确定的动作结果、恢复后第一步、剩余次数 |

事件更新为主；一个步骤持续很久时，在取得有意义的阶段结果或准备上下文交接时补记，不能只等整个步骤结束。保存失败时保留旧有效记录并说明，先尝试可逆修复；不能假称保存成功后继续执行依赖恢复记录的高风险动作。安全修复后仍无法保存时，记录能力标记受阻；保留对话内状态并说明限制。用户要求持久恢复时请其决定可写位置或是否接受仅对话续接，不自行放弃该要求；独立且不依赖持久记录的已授权调查可继续。

## 计划进度与目标状态

记录消费已发生的操作回执：先执行步骤，取得实际结果并核对，再把对应 `[ ]` 改为 `[x]`、附证据；准备执行或只有调用请求时仍记“进行中”。文件路径写入计划不证明文件已生成，开始命令或生成骨架也不证明步骤完成。一个旧计划项同时包含制作与交付时，在原编号下拆成可分别核实的子项，保留原目标：

```markdown
- [ ] 4. 生成并交付结果
  - [x] 文件生成：结果路径及验证证据
  - [ ] 正文交付：待提供必要结论与获取路径
```

正文尚未提供时保留这个状态；不要在已打勾的父项后追加“交付待完成”来抵消勾选。交付事件实际发生后，才能勾选交付子项和父项；宿主同步另按下文处理。

目标单独记录“未验证/未达成/受阻/达成”；审查“无法判断”表示证据未足，暂记未验证并保留原因；若必要证据确实无法取得且无替代路径则记受阻。审查未达成只有存在实际缺陷才进入修复，不把证据缺失机械计为实现失败。步骤全部打勾不等于目标达成。目标证据绑定实际产物版本或可辨识状态。变更后只撤销受影响部分的结论，其余有效证据复用；文字相同但数据或环境不同也要检查适用性。

多代理由主线程维护同一记录，子代理只回报结果，避免同时改写状态。宿主任务状态按[执行工具](execution.md#宿主目标工具协议)同步；任务记录不替代工具实际状态。

## 中断恢复

先读最新要求与唯一记录，恢复决定来源及性质、最终范围、当前环节、允许动作、计划、暂停原因和已消耗次数。作废要求不复活。核对实际文件、进程、任务及结果标识；记录不是现场证据的替代品。

默认继承有来源且仍适用的决定。文件名看起来不贴切、模型另有偏好，不是重新确认的理由；文件丢失、相关内容变化、最新要求冲突才处理受影响部分。来源不清时先查可用对话和项目证据，仍有影响下一步的必要缺口才问一项。

恢复返回“现场状态、观测时间、已完成部分及证据、可查询操作标识、尚缺结果”。现场状态按下表核实，不直接重试、制作报告或宣布整项完成，后续动作由[主控阶段转换](../SKILL.md#阶段转换)决定。

| 现场状态 | 核实方法与证据 |
|---|---|
| 已完成 | 检查实际结果/回执与当前产物是否对应，说明尚缺哪部分交付 |
| 仍运行 | 连接原任务或有间隔查询，保存阶段检查点；不另起任务 |
| 明确失败 | 定位失败步骤和已产生影响，区分已成功与尚未执行部分 |
| 结果未知 | 结果未知先核查，终端断开不代表进程停止；可能重复扣费、发送、发布或覆盖时不盲目重试 |

观察按宿主能力、预计耗时及已有时限有间隔进行，不忙轮询或无限等待。独立工作结束后、准备报告等待或受阻前，重新核实可能变化的现场；第一次看到running或文件名像门禁不能证明需要用户授权。查询失败且无替代路径时保留未知；观察窗口用尽则给仍运行状态、下一查询入口及宿主续接限制，不改写成失败。

有效授权、宿主目标ID、作业ID和次数继续有效；两种ID分别跟踪最终目标与实际操作，不能互代。主控承接这些结果，明确暂停仍需用户恢复；只重开有真实变化的决定。

## 完成同步

完成判定及顺序唯一见[主控完成门槛](../SKILL.md#完成门槛)。记录分别保存实现/验证证据、实际交付消息或渠道、宿主同步结果，不预写已交付。

反例：Write报告 → 把“写报告并交付”勾选、TaskUpdate completed → 最终正文。文件生成不等于正文已交付；没有交付事件时保留待交付。

宿主只能最终正文交付且此后无法调工具时，本轮记录“正文待交付、状态待同步”；自然续接后向主控提供已发生的交付证据，再同步，不为此单独请求用户回复。

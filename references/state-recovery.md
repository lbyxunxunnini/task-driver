# 状态记录与恢复

输入包括主控状态、有效决定与来源、计划目标、实际操作及证据。本模块保存并核对这些信息，必须返回同一份可恢复任务记录，或恢复后的状态与下一动作。主控决定何时调用，讨论、执行、验证模块提供变化。禁止用记录或恢复代替用户确认或授权。

## 何时建立记录

目标理解确认前在上下文维护；确认后默认在当前项目创建或续用唯一的任务摘要。用户明确只读时，仅在对话上下文维护同等状态和恢复点。满足下列任一条件时，必须进入持续记录模式。

- 用户已确认本次目标理解，准备展示第一轮方案讨论。
- 用户要求保存记录、防丢失，或任务需要跨会话继续。
- 已中断、需要恢复，或上下文即将压缩。
- 需要依赖较早决定，但不能从当前可用对话或材料可靠确认其内容和来源。
- 预计长执行或跨轮执行、多模块或外部系统任务、重要副作用操作。

切换前必须从可用对话和材料补齐已问问题、回答、决定、来源、适用范围与未决事项。无法确认的必须保留未知。进入后必须维持记录模式，直至任务结束或用户要求停止写入。用户、项目或宿主限制写入摘要路径时，禁止写入，必须说明持久恢复限制并在对话内维护同等状态。用户明确禁止创建或修改任何文件时，禁止新建或更新摘要和项目外记录。触发记录条件不产生写入许可，恢复后必须沿用有效限制。若仅限制业务文件，禁止自行扩大或缩小限制范围。写记录的许可确实不明时，必须继续在对话内维护，需要持久保存时才必须询问。

获准持久记录时，同一任务必须维护唯一的 `.task-driver/{任务标题}-{时间戳}-计划摘要.md`。已存在的摘要必须继续更新，用户指定已有记录位置时必须沿用。禁止因换环节、压缩、重启或出现新问题另建副本。禁止保存凭据或秘密，必须仅记录安全引用。路径未知时，必须先枚举任务记录，结合目标、工作目录和最近未决事项定位，禁止只凭相似标题选定。多个候选无法唯一确认时，必须只问用户要续接哪项，禁止擅自新建或合并。定位问题必须先在对话内记录，选定后必须纳入唯一摘要。

进入记录模式时必须告知用途，无需再索取已授权的记录许可。每个独立问题必须单列，保留原文或足以辨认的完整内容、送达及回答状态。一个提问含需分别回答的独立问题时必须分条。对完整计划或方案的一次整体确认必须保留为一个问题，答案必须体现实际确认范围。同一事项必须用共同事项关联，分条仅用于记录，禁止据此新增用户追问。禁止在更新后把历史问题合并或压缩成只有编号。

更新前必须读取最新记录，仅修改受影响条目。发现其他会话或用户已修改记录时，必须重新读取并核对，禁止覆盖并发变更。格式见[轻量计划摘要模板](templates.md#轻量计划摘要模板)。判断长计划是否需要记录时，必须优先依据用户要求和跨轮、依赖复杂、外部副作用等实际条件，禁止设定机械的文件数阈值。获准持久记录时，必须先保存并核实成功，再提问或进入其他依赖该记录的动作。

### 同一份任务文档中的图与表

在同一 Markdown 的一个 `mermaid` 代码块维护讨论推进图（flowchart TD）。对齐初步目标后，用已有事实、Agent 能自行得到的答案和仍需用户选择的事项画出主干：从起点出发，用实线依次连接推动目标的具体决定、逐项核对、收口确认、最终交付；独立决定按讨论优先级排列，次序不表示技术依赖。节点写明已知结论或待决问题。业务操作顺序放在要求表的做法栏。图上恰有一个“当前位置”。
偏离当前议题时，保存原主干待答点。相关临时事项从该点引出；完全无关的事项在同一图中独立记录，与主干之间不连线。按实际结果判断归属：
- 结果改变主干决定、实施范围或验收时，用标明具体影响的箭头并入受影响节点，先更新决定及其下游，再继续主干。
- 与当前目标完全无关时，末节点标“无意义分支（与当前目标无关）”，不画返回或合并箭头。完成、推演完或取消该事项后，先交付结果，再单独询问“是否回到〈目标〉，继续〈原待答问题〉？”，当前位置标为等待返回确认；不得同轮追问主干。只有用户明确同意返回才把当前位置移回保存的节点，保留无关支线的终点。否定、继续聊旁支或沉默均不推进主干；同意返回也不等于回答原问题。
每次收到回答先读取当前图，把该问题改为已答并附决定摘要；沿依赖更新受影响的问题，确定下一问，移动当前位置。沿用现有节点 ID。答复只改一个决定时，直接编辑原节点及其依赖的验法、待答点；其余节点逐个原样保留。读回时对照上轮图，若原节点被并成一句业务步骤或被重新编号，先修复再提问。在原代码块就地更新并读回确认，之后才问下一题；仅在对话重画、追加第二张图或改表都不足以完成更新。旧文档只有业务箭头时，按历史问题及来源重建讨论图。
这棵树只有一个 Markdown Mermaid 表示。节点的决定、依据、做法和验法沿用同一摘要内的记录，四列表由这些记录投影；表格与决定记录不符时先核对原话并更新记录，再刷新该行，禁止另立状态或用表格反推用户已同意。
要求表使用「你确认的要求｜当前做法或待决问题｜怎么验｜状态」四列。决定保留用户原话或可定位消息；项目事实、模型建议和委托内决定分别注明来源。流程图、表格和后续计划复用同一记录中的稳定编号。图上的依赖边标明哪个决定影响哪些动作、问题或验收。归档插问时，沿用该分支在 Mermaid 中的节点 ID 作为分支记录的 id；origin 和 target 填原图节点 ID。相关分支用 `origin -.-> branch` 和 `branch -->|具体影响| target`，边上的具体影响与 impact 一致。恢复旧记录时先按原讨论找到对应节点，再补齐编号和边。
文档中的图和表各保留一份当前版本。答复后就地改写受影响的图节点、边、表行和当前位置，并读回这两处核对；仅在文末追加聊天或修订说明不能替代更新。旧决定保留来源和被替换关系。首次续用旧文档时检查四列是否齐全；旧表缺状态列就据已有证据补齐，有缺口的行标为待核实，沿用原有结论。每次回答后先更新回答直接涉及的节点，再沿依赖边重算直接和间接受影响的节点，直到下游结论稳定。新证据可新增或撤销依赖；只有重算后仍需用户取舍才提问，其余节点沿用原状态。图与表供内部维护。正文按[讨论规则](discussion.md#讨论完成门禁)说明首轮全貌，后续说明本轮解决、仍待决及新增事项，默认不附摘要链接。用户明确要看图、表或摘要位置时，按所问展示当前内容或提供已有文档入口。

## 引用与展开

长期记录必须仅保存摘要与可寻址引用，无法回取的内容按下列例外保真。禁止另存完整正文的副本。

- 必须为需要跨表引用或按需回取的对象编号，禁止给其他对象强制编号。同表内未被引用的条目可不编号。禁止仅为填满格式新增记录。
- 编号必须使用规定前缀。`D` 表示决定/问题，`P` 表示计划项，`G` 表示验收目标，`E` 表示证据，`O` 表示操作，`A` 表示进度锚点，`R` 表示独立复核，`F` 表示事实、规则或建议。编号在同一摘要内必须唯一，条目被引用后禁止改号。
- 每个编号条目必须保存摘要（一句话或足以辨认的短内容）、可寻址位置、状态及引用的其他编号。位置可用文件路径与标题或行、消息引用、宿主 ID，必须能在同一任务后续轮次实际定位。
- 能寻址的内容必须仅保存摘要与位置，原文、日志和长证据留在原处。内容无法回查时（如即将被压缩的对话原话或无法回查的外部消息），必须保存足以辨认的原文片段。
- 恢复或交接上下文时，必须先内联当前环节、最近 3 条有效决定、未决项、当前计划项和目标及其直接引用的证据。其余条目必须仅保留编号，沿引用按需展开，禁止整段重读历史。
- 引用必须指向仍存在的编号。删除或替换条目时，必须同步更新受影响的引用，禁止保留悬空引用。被引用条目变化时，必须仅核对并更新受影响的引用方结论，保留其余仍有效的证据。
- 旧摘要无需一次性重写。首次更新旧条目时必须补编号，未触及的条目必须保持原样。
- 旧摘要中的已展示目标缺少 `included`、`excluded`、`evidence_map` 或 `goal_scope_baseline` 时，首次续接必须仅迁移该目标条目，补录当前有效范围、用户排除来源、已有证据映射和当前范围基线，再继续。迁移前状态检查返回 `repair_state`。禁止把旧目标直接标成完成。
- 旧快照的字符串证据仍可用于定位已有观察。续接时必须复用已完成步骤，禁止重跑。完成前必须按[取证规则](verification.md#执行验证)核对并补录仍有效的真实记录。补取证据必须限于缺失或失效的部分。
- `D/P/G/E/O/A/R/F` 是记录内部索引，禁止在用户正文展示或用其代替原话、证据原文或用户确认。用户选项、验收步骤和计划展示中的编号必须沿用原规则。

## 变化与保存时机

下表适用于获准维护持久记录的情况。禁止写入时，必须在对话内维护相应状态，禁止把持久保存当作提问前提。

| 时点 | 必须保存的变化 |
|---|---|
| 准备向用户提问（含计划、目标等确认问题） | 必须先读取同一记录，以事实、已决事项和待答问题核对候选，增量保存各候选及其对象、范围和状态。准备输出的问题必须标为拟提，禁止冒称已交付。必须核实保存成功后再提问 |
| 问题交付或用户回答后 | 可核实问题已交付时，必须记为待答。收到回答后，必须更新实际覆盖的全部事项及新增约束，记录答案、来源、范围和状态，保留未答及其他决定。必须先保存有效变更再提问 |
| 长计划编制前与编制中 | 编制前必须保存有效需求、已决事项、计划待编制部分和续接位置。编制中必须更新草案进度，未授权时禁止记为可执行 |
| 长计划开始执行前 | 有效计划、目标、通过条件、授权范围、各步骤状态、execution_scope、目标跟踪依据、execution_receipt 和首先执行的动作 |
| 计划项完成或验证产生结论 | 实际产物、安全证据引用、步骤状态、目标验证状态以及下一项 |
| 改变需求、计划、目标、授权或证据 | 新决定的依据、适用范围、失效及替代关系与仍然有效部分。旧目标原文、宿主 ID、`superseded` 关系及替代目标。必须核对已授权维护的计划和记录，禁止静默改写用户原要求 |
| 准备执行重要副作用动作 | 动作对象、授权、执行意图与可查询的进程/任务/结果标识。返回后必须补记结果与阶段检查点 |
| 等待、受阻、主动暂停或预计中断 | 原环节、暂停原因、恢复条件、未确定的动作结果、恢复后第一步、剩余次数。局部插问或调查完成后，必须按主控实际续接，禁止用阶段标记或承诺代替动作 |

等待讨论收口答复时，必须保留实际问题来源及提问时的有效决定，供恢复[待答状态](workflow-control.md#首次从讨论转入计划)核对。获准持久记录时必须保存在原摘要，其他情况下必须在对话中维护。讨论收口动作必须遵守[主控入口](../SKILL.md#接到任务后的第一步)。

记录必须以事件更新为主。步骤持续很久时，必须在取得有意义的阶段结果或准备上下文交接时补记，禁止只等整个步骤结束。保存失败时，必须保留旧有效记录、说明失败并先尝试可逆修复。禁止假称保存成功后继续执行依赖恢复记录的高风险动作。安全修复后仍无法保存时，必须将记录能力标记为受阻，保留对话内状态并说明限制。用户要求持久恢复时，必须请其决定可写位置或是否接受仅对话续接，禁止自行放弃该要求。独立且不依赖持久记录的已授权调查可继续。

## 计划进度与目标状态

勾选步骤前必须实际执行、取得结果并核对操作回执，再把对应 `[ ]` 改为 `[x]` 并附证据。准备执行或只有调用请求时，必须保持“进行中”。禁止用计划中的文件路径证明文件已生成，或用开始命令、生成骨架证明步骤完成。旧计划项同时包含制作与交付时，必须在 `P{n}` 下拆成可分别核实的子项并保留原目标。

```markdown
- [ ] P4 生成并交付结果
  - [x] 文件生成：结果路径及验证证据
  - [ ] 正文交付：待提供必要结论与获取路径
```

正文尚未交付时，必须保持待交付。禁止用“交付待完成”附注抵消父项勾选。勾选交付子项和父项前，必须核实交付实际发生。宿主同步必须按[完成同步](#完成同步)处理。

必须单独记录目标状态“未验证/未达成/受阻/达成”。审查“无法判断”且证据不足时，必须暂记未验证并保留原因。必要证据确实无法取得且无替代路径时，必须记为受阻。审查未达成时，必须先确认存在实际缺陷再进入修复，禁止把证据缺失机械计为实现失败。禁止以步骤全部打勾判定目标达成。目标证据必须绑定实际产物版本或可辨识状态。变更后必须仅撤销受影响部分的结论，并复用其余有效证据。文字相同但数据或环境不同时，仍必须核对证据的适用性。

多代理任务必须由主线程维护同一记录。子代理必须仅回报结果，禁止同时改写状态。主线程必须把[子代理管理](subagents.md#分派与交接)的运行对应关系并入现有操作与交接内容。恢复时必须核对原代理和实际产物，禁止重复派发。宿主任务状态必须按[执行工具](execution.md#宿主目标工具协议)同步。禁止用任务记录代替工具实际状态。

## 进度锚点

进度锚点是记录模式下的只读复查，用于长任务途中核对路线是否仍指向当前有效目标。禁止用进度锚点代替审查或修复，或据此改变阶段、授权或完成判定。默认由主控核对，有独立授权时按[只读检查代理](subagents.md#只读检查代理)规则处理。恢复时必须复用已有结论，禁止重复核对。

本节仅在执行环节且最终目标已确认后适用。讨论期暂停、恢复或压缩时禁止触发。满足下列任一条件时，必须核对频次上限。达到条件且未超过上限时，由主控核对，或在有单独授权、宿主能力且收益足够时派发只读检查代理。已达上限时记录未执行及原因。

- 执行环节已连续完成 3 个及以上计划项，或跨过 1 次上下文交接或压缩。
- 同一目标进入第 2 次修复。
- 单步骤预计耗时长、准备分段前。
- 用户暂停后恢复、首次继续。

默认频次必须遵守两个上限。每 3 个阶段结果最多 1 次，同一任务最多 5 次。阶段结果指一次计划项完成、一次验证结论或一次有意义的阶段产物。禁止把锚点结果计入下一次触发。用户明确要求增加时，必须采用调整后的上限并记录来源。增加次数只调整上限，禁止据此产生或恢复子代理授权。未授权派发时仍按主控核对。

输入必须仅取四类锚，禁止附完整历史。目标锚提供当前有效目标原文与通过条件，被取代的旧目标必须标为 `superseded`，禁止附达成状态。路线锚提供当前计划项与最近 3 条阶段结果。动作锚提供最近若干次实际动作及结果。边界锚提供当前环节、允许动作、已用次数与用户限制。

输出必须使用固定的四个字段，分别为判定（在轨/偏离/无法判断）、依据（对应输入中的哪一条）、建议（继续/回到某项/补证据/交回讨论）和限制。

判定与建议必须仅作为主控的判断输入。禁止自动修改计划、目标或授权。确需变更时，必须按[主控](../SKILL.md#阶段转换)走原讨论或确认路径。禁止计入修复次数、独立复核次数或执行分派额度。必须将结果作为一条记录写入「操作与交接」，以 `A{n}` 引用。禁止另建文件或将记录条目作为用户正文输出。已执行且判定非“在轨”时，最终报告必须说明判定、建议及未采纳原因。

必须如实记录主控核对、代理核对或 `A{n}: 未执行（原因）`。禁止把锚点写成已独立检查或独立审查。

## 局部插入与恢复

收到需单独处理的临时请求时，必须先按实际原状态调用[轻量检查](workflow-control.md)，等待返回并保存简短恢复点后，再调用临时事项的工具。禁止并行。同一消息也回答原问题时，必须先按实际覆盖范围更新原决定。必须在对话内维护这些内容，达到记录条件且获准写入时必须增量保存在同一摘要，禁止另建文件。后续又插入请求时，必须依次保留上一层，禁止覆盖未完成事项。

临时事项完成或用户取消后，必须先据恢复点核对结果、最新用户要求及现场，更新受影响的决定、证据与授权，在正文交付实际结果或说明取消，再依分支归属合并结果或等待用户同意返回。禁止在实际送达前记录正文已交付。原问题经核对仍需用户回答时，必须保持等待，禁止把插问当成回答。新证据已解决事实缺口或用户取消该问题时，必须记录依据并继续。原任务仍运行或结果未知时，必须按下节核实，禁止重复操作。临时事项受阻或需要用户决定时，必须保持等待，禁止冒称完成。用户明确取消时，必须记录依据并按分支归属处理返回。用户要求继续且实际权限允许时，必须继续临时事项。用户明确暂停全部工作时，必须保持暂停。仅暂停原任务后另行要求临时事项时，可以处理该事项，恢复原任务仍必须由用户明确要求。

## 中断恢复

必须先读取最新要求与可用对话。已有唯一记录时，必须读取并对照记录之后的对话，以较新的有效决定与限制修正恢复状态。没有唯一记录时，必须从可用对话和材料恢复决定来源及性质、最终范围、当前环节、允许动作、计划、暂停原因和已消耗次数。必须把无法确认的事项保留为未知，仅当事项影响下一步且无法自行核实时可以询问。禁止因恢复突破仍有效的写入限制或恢复已作废要求。必须核对实际文件、进程、任务及结果标识，禁止用记录代替现场证据。

默认必须继承有来源且仍适用的决定。禁止仅因文件名看起来不贴切或模型另有偏好重新确认。文件丢失、相关内容变化或与最新要求冲突时，必须仅处理受影响部分。来源不清时必须先查可用对话和项目证据，仍有影响下一步的必要缺口时才可以问一项。

完成上述现场核对后，若现有记录或宿主保留了同一任务最后一份有效完整状态，必须优先[复用快照并提交本轮变化](workflow-control.md#复用已有状态)。缺少有效快照时，必须据已核实资料恢复完整状态，并按原有门槛检查。必须沿用已有记录和写入许可。

恢复必须返回“现场状态、观测时间、已完成部分及证据、可查询操作标识、尚缺结果”。必须按下表核实现场，由[主控阶段转换](../SKILL.md#阶段转换)决定后续动作。禁止从恢复直接跳到重试、制作报告或宣布整项完成。

| 现场状态 | 核实方法与证据 |
|---|---|
| 已完成 | 必须核对实际结果或回执与当前产物是否对应，并说明尚缺哪部分交付 |
| 仍运行 | 必须连接原任务或有间隔地查询，保存阶段检查点。禁止另起任务 |
| 明确失败 | 必须定位失败步骤和已产生的影响，并区分已成功与尚未执行部分 |
| 结果未知 | 必须先核查原操作。终端断开不代表进程停止。可能重复扣费、发送、发布或覆盖时，禁止盲目重试 |

必须按宿主能力、预计耗时和已有时限有间隔地观察，禁止忙轮询或无限等待。独立工作结束后、准备报告等待或受阻前，必须重新核实可能变化的现场。禁止仅凭首次看到 `running` 或类似门禁的文件名判定需要用户授权。查询失败且无替代路径时，必须保留未知。观察窗口用尽时，必须报告仍运行状态、下一查询入口和宿主续接限制，禁止改写成失败。

恢复时必须沿用有效授权、宿主目标 ID 和作业 ID，继续累计已用次数。宿主目标 ID 跟踪最终目标，作业 ID 查询实际操作。仍影响推进、完成或可能产生副作用的未决操作，必须保留原 ID、引用和已有副作用标记，并按[状态检查规则](workflow-control.md#操作结果与依赖)记录结果或依赖的新证据。原操作仍阻塞下一步时，独立工作必须沿用现有独立动作路径。若要取消未决操作对完成的阻塞，必须有更新且已确认的目标范围，或有新证据证明原只读检查无需计入完成。必须依据失败回执进入异常处理。必须保留原操作并核实实际处理结果后再解除相应阻塞。用户确认的新范围改变完成要求时，必须按新范围判断完成。每次明确暂停后，必须等用户针对本次暂停作出恢复指示。禁止重开未发生真实变化的决定。

## 完成同步

完成判定及顺序必须遵守[主控完成门槛](../SKILL.md#完成门槛)。记录必须分别保存实现/验证证据、实际交付消息或渠道及宿主同步结果。禁止预写已交付。

反例：Write报告 → 把“写报告并交付”勾选、TaskUpdate completed → 最终正文。文件生成不等于正文已交付。没有实际交付事件时，必须保持待交付。

宿主只能通过最终正文交付且此后无法调用工具时，本轮必须记录“正文待交付、状态待同步”。下一次自然续接后，必须向主控提供已发生的交付证据再同步。禁止为同步单独请求用户回复。

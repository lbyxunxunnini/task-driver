# 调查分析并逐项讨论

进入讨论时必须按主控读取策略加载或复用本模块。共同授权边界见[主协议](../SKILL.md#确认与授权)，任务类型的方法与多轮对照见[场景](scenarios.md)。本模块负责形成问题、语义复核以及收到回答后的续接，收口动作必须遵循[主控入口](../SKILL.md#接到任务后的第一步)。

## 输入与交接

必须依据[调查与分析](analysis.md)所得事实、方案和依赖形成问题。事实不足时必须交回主控补查，禁止仅因收到回答而重读分析模块。输入是当前任务、未决事项与有效决定，输出是本次回答覆盖的决定、未答部分、新分支及讨论核对结果。跨环节推进由[主控](../SKILL.md#阶段转换)决定，禁止因处理完一次回答就把任务标成完成。

## 决策项与提问

必须按[从做法选出下一问](analysis.md#从做法选出下一问)筛选待决项，先剔除模型额外设想的可选改进。用户在探索目标、审美或使用偏好时，尚未委托且会改变交付的偏好必须由用户决定。

提问前必须核对上下文和材料。已定、未定及下一问必须按[记录条件](state-recovery.md#何时建立记录)维护。记录保存时机及无写入许可时的处理必须遵守[回答后的推进](#回答后的推进)。事实、建议、用户决定和委托必须分别记录，注明决策项、状态、依据、范围和下一动作。委托内自行判断的内容必须标为委托决定，禁止写成用户亲自确认。答复的判定和更新必须遵循[回答后的推进](#回答后的推进)。

整理决定或生成计划前，必须逐项用用户原话、适用规则或明确委托核对对象、动作和限定条件。禁止把依据不支持的新增条件、关联实现或偏好记成用户决定；已定规则的后果在其实际范围内有效。模型推论必须标为推论，禁止用示例、建议、沉默或推论充当确认。遇到真实冲突或必要缺口时，处理必须限于受影响部分。

用户明确要求逐项讨论时，先从用户原话提取具体要解决的问题，按其点名或列举顺序推进。用户已给定的范围、目标和保留要求是当前问题的约束，不得把它们改写为排在前面的新议题。明知现状和改法时，只围绕当前问题交付依据与建议；未指定且不受当前改动影响的既有行为照常沿用，不追加统一策略。其他问题可简短登记，方案和问题留到相应轮次。确实依赖另一事项时，先说明该前提怎样改变当前改法或验收，再问必要取舍。

在当前讨论范围内已有可交付的建议时，必须先说明实际做法、依据、关键验收方法和可调整的假设。仍有真实取舍时，必须单列未决口径，说明可行选项、各自影响、推荐和理由。结尾的问题必须聚焦当前最需要用户决定的一项。仅用户掌握的必要事实或理解核对可以直接问。当前项无待决取舍时，按用户要求给出结论，再判断是否接续下一项，禁止补造取舍。

讨论回复的提问对象和免问条件必须遵循[状态检查的最终回复契约](workflow-control.md#讨论最终回复)。有实质缺口且用户要求先看方案、计划草案或详细设计时，可按[主控范围规则](../SKILL.md#阶段转换)交付标明缺口的讨论稿；契约要求交付缺口稿时必须随正文交付。仅要求先看且未限定本轮范围时，必须以当前必要问题承接讨论；明确限定本轮只交付该稿时，必须交付后停止本轮并保留恢复点。讨论稿禁止充当正式计划或执行授权。

### 提问语义复核

交给 `final` 前，必须对当前问题或免问结论做一次语义复核，禁止用问号数量代替。

- `decision` 必须核实待决项有依据、仍需用户回答且现在能答，尚未被回答、排除或委托。涉及方案取舍时，选项、影响、推荐和理由必须已在正文交付。问题的影响必须限于一个独立事项。用户指定逐项讨论时，`target_is_current` 必须把待发问题和本轮建议对回用户原话中的当前问题，禁止只和主控拟定的事项编号相互校对；用户已给定的结论、其他事项或额外统一策略不得冒充当前问题。涉及另一事项时，只有正文已说明它为什么是当前事项的必要前提，且确需用户决定，才可标记通过。
- `plan_transition` 必须按[主控入口](../SKILL.md#接到任务后的第一步)核实没有待决项，并核实正文确实在询问用户是否结束讨论、开始展示正式计划和验收目标。
- `waived` 必须核实免问来源明确，正文没有仍需用户回答的问题。
- `tool_wait` 必须核实实际观察支持当前等待、没有阻塞讨论的待决项，正文只说明实际状态与续接点，禁止新增用户问题。复核来源必须引用实际查询或回执，禁止虚构用户暂停来源。

问题交接必须以一个问题结束，禁止在问题后追加选项、补充说明或其他正文。

复核结果必须写入 `discussion_handoff.semantic_review`。`reviewer` 必须为 `independent` 或 `main`，`target` 必须与交接类型一致，`source` 必须指向实际复核依据；任何适用检查未通过时禁止将 `status` 填为 `pass`。问题交接必须填写对应的 `decision_id`。使用 `independent` 时还必须填写实际 `review_id` 和 `authorization_source`。缺少独立只读复核能力或授权时，必须用 `main` 并保留自检限制，禁止把主模型自检写成独立复核。脚本检查字段和状态，复核内容的真实性由实际证据支持。

必须按交接类型填写检查项。`decision` 使用 `target_is_current`、`not_already_decided`、`not_delegated`、`answerable_now`、`single_question`、`no_trailing_content`，计划请求仍有缺口时必须另加 `incomplete_plan_delivered`。`plan_transition` 使用 `transition_intent`、`no_blocking_pending_decisions`、`single_question`、`no_trailing_content`。`waived` 使用 `waiver_source_is_explicit`、`no_user_question`、`no_trailing_content`，仅交付缺口稿时按[最终回复契约](workflow-control.md#讨论最终回复)补充核对。`tool_wait` 使用 `tool_wait_is_current`、`no_blocking_pending_decisions`、`no_user_question`。

用户刚澄清结果或尺度时，必须说明哪些差异不能通过、哪些可以接受；已有明确判据必须直接沿用。用户要求保留且已核实的行为必须沿用，即使新材料未展示；禁止重问该行为或把改变它列为选项。

**反例：**用户要求改版但保留原交互；已查明按钮点击后在下方展开，设计稿没有展示展开状态。

**错误：**询问“保持下方展开，还是改成底部弹层？”

**正确：**沿用下方展开，继续讨论真正未决定的事项。

可以说明已定规则的后果，禁止换一种说法重复索取确认。重开决定必须限于仍未决定且影响结果的独立取舍、用户明确要求复核或修改、或真实冲突涉及的部分。用户指出已讨论过时，必须先查可用记录；查不到必须保留未知，必要答案无法恢复时才必须请用户补充。现有实现只说明当前做法，禁止自动作为新需求的保留约束；用户要求改变或存在真实冲突时必须讨论差异，禁止错判为重复或因去重遗漏必要问题。

实现细节只改变内部做法，且不影响用户可感知行为、费用、权限、安全、隐私、兼容性或已确认约束时，必须由模型自行处理。核心选择未决时，必须保留符合已定约束的真实替代方向。禁止把假设当事实、夹带无关功能或把未确定的建议当默认决定。

形成新问题前必须回看原目标、既有机制及累计代价。讨论必须限于有依据且与目标相关的取舍，禁止以派生问题无依据地扩张方案。相关专业建议可注明依据供用户判断；事实不足时必须补查或保留未知。

原生提问必须遵循[回复提交门禁](../SKILL.md#回复提交门禁)及[宿主适配](faq.md#原生选择器怎样使用)。等待答案只暂停依赖该答复的动作；禁止因预选、关闭、跳过、超时或未反对而把事项写成已决。

## 回答后的推进

收到回答的同一轮，必须先核对用户实际回答的对象、动作、条件和范围，按下表更新决定，再按[回答后重算下一步](analysis.md#回答后重算下一步)分析影响并交回主控。禁止把用户的选择视为推荐理由已验证，或用模型汇总创造确认。事实、现状、有效规则、用户决定、委托内决定、建议与待证推断必须按[分析模块](analysis.md#事实推断与约束)区分，禁止因写入摘要改变性质。明确的项目约束必须直接沿用，禁止为分类重复提问。

### 委托的承接

必须从自然语言核对委托对象、动作、范围及限制，无需追加授权表单。例如只委托名称或措辞，允许改表达，不同时决定分组、内容取舍；这些属于不同动作。必要内部实现必须限于完成该委托所需的操作，禁止将效果更好的相邻方案自动归入委托。整体方案委托时，必须在已定目标与约束内作决定，禁止逐项重问已委托细节或把方案决策权当成执行许可。

例如“优先级分类你来判断”允许决定分类标准及归类，不允许顺带决定“低优先级只抽样”。“测试方案专业取舍都由你决定”可以包含范围内的组织及执行策略设计，但实际运行前必须核对授权。仍需决定的委托外选择必须保留待决，并按[决策项与提问](#决策项与提问)记录委托和模型决定。

| 实际回答 | 状态更新 | 当轮下一步 |
|---|---|---|
| 回答了当前事项 | 更新必须限于实际回答对象。明确接受完整已展示方案时，必须确认其覆盖内容。示例和确认对象之外的附带建议仍待定。用户表示某项不需要时，禁止据此确认另一方案 | 处理必须限于仍需用户决定的缺口。仅确认一项、其余仍是建议时，必须复用适用规则。必要取舍闭合后，必须遵循[主控入口](../SKILL.md#接到任务后的第一步)收口，再交整套方案评审。用户明确要求逐项讨论时必须遵从 |
| 只回答了部分内容 | 必须分别保留已答和未答状态 | 必须只就仍必要的未答部分继续讨论，禁止重问已答内容 |
| “不知道”“不确定” | 必须记为未知，禁止记作否定、不可用、取消或委托 | 能查必须查；不能查时，必须分析取证路径或讨论一个替代取舍，禁止循环逼问同一事实 |
| 只认可方向、例子或顺序，或只说“值得做/不错/可行” | 必须保留评价的实际范围；未回答当前选择、范围或确认对象时，相关事项必须仍记为待决 | 必须延续当前待决取舍，禁止据评价认定已决或开始执行 |
| 明确延期或排除 | 必须记录决定及其对当前方案的影响 | 当前方案仍依赖该事项时，必须先处理依赖，禁止仅以延期判定讨论闭合 |
| 改变或撤回之前决定 | 必须只重开受影响部分，核对方案、示例和验收中的旧决定，保留其他有效决定并同步获准维护的记录和计划 | 必须说明实际影响，讨论下一个仍需用户决定的受影响事项 |
| 解答了执行中的必要澄清 | 必须补齐有关事实或决定，保留仍有效的原授权 | 必须交回主控，按原环节恢复条件继续 |
| 当前问题待答时，用户插入指代不清的简短问句 | 先核对最近对话中有无可确定的指代。只能回应已有依据的含义，不得自行列举业务解释、提出改法或调用工具调查。问句可以理解为确认当前聊天能否收到消息时，只说明本条消息已收到 | 没有明确要另做的事时，保留并接回同一个待答问题。确实提出了独立请求但缺少关键对象时，仅澄清该对象，并按临时事项保留原问题 |
| 只是任务中的解释性插问 | 必须按用户的原意回答插问并保留任务状态；用户已澄清插问的对象或表示无需处理时，只简短承接已知事实，禁止宣布未核实的故障已解决或把先前猜测扩成新调查 | 直接接回原事项；当前问题尚待答复时简短重述即可，无需重讲已有分析。用户明确暂停时必须保持暂停 |

从讨论转入计划必须遵循[主控入口](../SKILL.md#接到任务后的第一步)和[阶段转换](../SKILL.md#阶段转换)。禁止用单项答复补足其他确认或执行条件。

保守行动与事实判断必须分别处理。扣费情况未知时可以暂停可能扣费的动作，但禁止据此断言必然扣费或取消测试覆盖。需要调整方案时，必须先给出具体建议，禁止写成“你已决定”。

未限定本轮只做局部事项时，局部交付后必须接回原任务，从剩余事项中去重并筛选下一步，禁止停在“已记录”“已修改”或“之后继续”。补查、形成当前问题或收口必须遵循[主控入口](../SKILL.md#接到任务后的第一步)。纯工具等待、明确暂停或限定本轮交付时必须按[主控阶段转换](../SKILL.md#阶段转换)处理；其他外部阻塞必须按异常分类处理。

同一任务必须维护当前环节和问题、事实及证据、有效决定和委托及其来源、未决及延期事项和依赖。保存时机必须遵循[记录与恢复](state-recovery.md)。已启用持续记录且获准写入时，提问前必须读取唯一摘要，收到答复后必须先保存本轮有效变化，再问下一项。禁止另建记录文件。无写入许可或无法持久记录时，必须在对话内维护。中断后必须先恢复这些内容再按本表续接，禁止因“确认、1、继续”重置任务。

## 讨论完成门禁

首次接手已有讨论时，必须按[开场分析](analysis.md#分析的组织)恢复目标结果及其判据。禁止以问答轮数、旧清单问完、撤下或纠正上一问、已有计划稿代替下列核对。

1. **覆盖核对**：必须沿约定场景核对必要操作、异常、结果及验收方法，补齐方案遗漏。准备承诺且会改变交付或验收的结果，必须核实由谁触发、用什么条件触发，以及这些条件在本次交付中是否可用。参考材料依赖范围外的角色、入口或环境时，必须先查范围内的等效路径。有路径时必须按已有范围承接；无等效路径且是否交付仍需用户取舍时，必须在当前建议中说明缺口和影响，并就是否纳入提问。已约定或委托的必要结果仍有可行性缺口时，必须按下文未知处理规则核对。
2. **决定核对**：必须逐项核对关键口径来源，区分适用规则、用户实际决定和委托内决定。必须先定出委托内取舍的做法并保留依据；未决口径必须保持可见，并按答复实际覆盖范围更新。
3. **未知处理核对**：不改变当前选择且有可行核实路径的未知事实，必须列为计划前置。会改变方案的待查事项必须先调查，仍需用户决定的事项必须按[决策项与提问](#决策项与提问)讨论。禁止以延期移除当前依赖。

覆盖和决定核对结果必须交给[状态检查](workflow-control.md#首次从讨论转入计划)。仍有待决项时，必须按[决策项与提问](#决策项与提问)形成建议和当前问题。收口动作必须走[主控入口](../SKILL.md#接到任务后的第一步)，各类等待、暂停或本轮限定必须遵循[阶段转换](../SKILL.md#阶段转换)。范围变化并重开讨论时，必须保留旧展示和有效决定，清除面向旧范围的收口问答，再按同一入口处理；有效执行状态的续接必须遵循[状态恢复](state-recovery.md)。

编制和发出计划前，必须按[计划模块](planning.md#输出计划)核对决定来源。新发现独立取舍时，必须更新待决项并回到相应讨论路径，禁止把新问题放在正式计划末尾并约定未回答就默认执行。有效授权和委托必须继续复用，禁止要求有效且未变化的决定重新确认。

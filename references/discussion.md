# 调查分析并逐项讨论

进入讨论按主控读取策略加载或复用本文件。共同授权边界见[主协议](../SKILL.md#确认与授权)；任务类型的方法与多轮对照见[场景](scenarios.md)。本模块负责从分析到讨论收口，以及每次收到回答后的续接。

## 输入与交接

使用[调查与分析](analysis.md)所得事实、方案及依赖形成有价值的问题；事实不足时交回主控补查，不因每次收到回答重读分析模块。输入是当前任务、未决事项与有效决定；输出是本次回答覆盖的决定、未答部分、新分支及讨论是否闭合。跨环节推进由[主控](../SKILL.md#阶段转换)决定，不能因完成一个回答就把任务标成完成。

明确要求直接落实，不能把用户已定的运行行为换成更宽或更窄的“实现口径”，也不能用“你可以纠正”代替必要确认。可查事实自行核实；只能用户提供的事实逐项问；未定偏好和范围取舍逐项讨论；不改变用户可感知行为的内部实现自行处理；明确委托的事项在委托范围内判断。较小偏好不因影响小而省略，不为模板空白制造问题。

## 一轮一个独立问题

穷举当前目标内所有相关且模型无权代定的事项；依赖和影响决定先后顺序，不决定是否省略。问题由决策项生成，不直接从整套方案生成选项。没有固定问答轮数；答案产生新分支时继续展开，不为填表增加需求。

### 先形成决策项

在已有上下文或唯一任务记录中维护下表，不另建文件，不把表格当问卷交给用户。一个短问题可以只维护一条；复杂任务复用稳定编号或名称，避免改写原决定。记录的是可检查的结论与依据，不是内部推理过程。

| 决策项 | 当前值与状态 | 来源及适用范围 | 依赖与下一动作 |
|---|---|---|---|
| 一个可分别选择的对象和动作 | 待查 / 待用户 / 委托可决 / 已决 / 排除 / 延期 | 用户原话、适用规则、证据或明确委托；模型建议单列 | 哪项答案会影响它；查证、提问、委托内决定或不阻塞当前计划 |

事实缺口先查；不影响当前方案且有后续核实路径的缺口可以保留。现状和建议不能自动变成已决项。局部委托按下文识别，不能仅因相关就合并两个决定。

### 再生成并检查当前问题

先选择一个依赖已满足的待用户项，写出它的变量名与裸取值；其他决策项保持原值和状态。分别代入这些取值比较实际后果，最后才写推荐和用户问题。若比较必须同时改变另一项，先拆开可选设计；确实存在依赖时先处理前置项，不把两个决定包成一个套餐。

发出的选项只承载当前变量的取值；分析可以说明已证实的后果，但不附带另一个可拒绝的选择。整条回复只保留这一项回答请求，表格、括号、末尾补充和自由输入提示也属于同一次回复。发现新的用户取舍就加入待决区，不能追加“也可以一并说”。已决、已排除和委托内已定事项不重问。

| 决策项 | 错误选项 | 可发给用户的问题 |
|---|---|---|
| 学习资料采用哪种查找方式 | 按章节；按主题并隐藏进阶内容 | 只比较章节与主题；内容保留和展示权重另列 |
| 哪些任务需要人工检查 | 全部浅查；重点深查、其他跳过 | 先确定当前一类的覆盖边界，再处理深度及其他类别 |

判断不靠问号数量：用户能接受一个选项的前半句却拒绝后半句，往往说明它改变了两个项。用户主动回答多项时，按实际内容更新多项；单问限制不限制用户主动补充或整体委托。

正文按“实际决定变化、当前事项分析与推荐、一个回答请求”组织。可比较方案给真实选项及取舍；事实、经历、原文直接问，不编造选项。较小偏好不因影响小省略；不改变用户范围、结果、费用和风险的内部实现自行处理。

原生提问按[回复提交门禁](../SKILL.md#回复提交门禁)及[宿主适配](faq.md#原生选择器怎样使用)。等待答案只暂停依赖动作；预选、关闭、跳过、超时或未反对均不更新为已决。

## 回答后的推进

收到回答的同一轮完成“对照原问题与实际回答 → 识别来源、性质与适用范围 → 单独推演影响 → 返回主控”。用户选择不代表验证了推荐理由；模型自己的汇总不创造确认。事实、现状、有效规则、用户决定、委托内决定、建议与待证推断按[分析模块](analysis.md#事实推断与约束)区分；不因写入摘要改变性质。明确项目约束直接沿用，不为分类重复询问。

### 委托的承接

按自然语言识别用户委托的对象、动作、范围及限制，无需追加一轮授权表单。例如只委托名称或措辞，允许改表达，不同时决定分组、内容取舍；这些属于不同动作。必要内部实现是完成该已委托动作所必需的操作，不是模型认为效果更好的相邻方案。整体方案委托则充分承接，在已定目标与约束内作决定，不继续逐项问已委托细节；方案决策权与实际执行许可仍分开。

例如“优先级分类你来判断”允许决定分类标准及归类，不允许顺带决定“低优先级只抽样”。“测试方案专业取舍都由你决定”可以包含范围内的组织及执行策略设计，但实际运行仍须核对授权。派生选择未在委托内时留在待决区；记录“用户委托什么、模型据此决定什么”，不改写为用户亲自选择。

| 实际回答 | 状态更新 | 当轮下一步 |
|---|---|---|
| 回答了当前事项 | 只确认该事项；示例细节与附带建议仍待定 | 检查派生影响，然后提出下一项；已达到收口条件则收口 |
| 只回答了部分内容 | 保留已答部分与未答部分 | 针对仍必要的未答部分只问一项，不重问已答内容 |
| “不知道”“不确定” | 记为未知；不是否定、不可用、取消或委托 | 能查则查；不能查则分析如何获得证据或讨论一个替代取舍，不循环逼问同一事实 |
| 只认可方向、例子或顺序 | 保留其实际范围，不认定未讨论细节 | 延续具体取舍，不以方向确认开始执行 |
| 明确延期或排除 | 记录用户决定及对当前方案的影响 | 当前方案依赖该事项时先处理依赖；不能把阻塞项搬到以后就宣布闭合 |
| 改变了之前决定 | 只重开受影响部分，其余有效决定保留 | 说明实际影响，讨论下一个受影响事项 |
| 解答了执行中的必要澄清 | 补齐相关事实或决定，保留原授权 | 返回主控，按原环节的恢复条件继续 |
| 只是任务中的解释性插问 | 回答解释，不清空任务状态 | 返回主控处理原任务续接；明确暂停时保留暂停状态 |

保守行动与事实判断分别处理：扣费情况未知时可以暂停可能扣费的动作，但不得据此断言必然扣费或取消测试覆盖。需要调整方案时先提出具体建议，不把建议写成“你已决定”。

同一任务在对话中维护当前环节、当前问题、事实及证据、已确认或委托决定及来源、未决和延期事项及依赖。按[记录与恢复](state-recovery.md)判断保存时机；已启用持续记录时，先保存本轮有效变化，再问下一项。中断后先恢复这些内容再按本表续接；不因“确认、1、继续”重新初始化。

## 讨论完成门禁

收口是决策项核对的结果，不以问答轮数、最初清单问完或“已生成一份计划”作为依据。

1. **覆盖核对**：沿实际使用、质量、异常、交付与验收检查缺项和新分支；只保留当前目标内的相关事项。
2. **决定核对**：影响当前方案的项均有用户决定、适用规则或范围内委托作为依据。委托可决项先由模型形成明确决定并保留来源；不能一边宣称已收口，一边请用户对这些项再次点头。
3. **未知处理核对**：不改变当前选择且有可行核实路径的事实，列为计划前置；会改变方案的待查项先调查，必须用户决定的待决项继续逐项问。延期不能搬走当前依赖。

核对结果只走一条路径：

| 结果 | 返回主控的产物与下一动作 |
|---|---|
| 仍有影响方案的未决项 | 当前一项问题；不同时请求执行 |
| 无上述未决项，用户按主控“确认与授权”规则已要求生成计划 | 已决项及依据 → 本轮实际交付计划；无需再确认汇总 |
| 无上述未决项，用户未要求计划 | 汇总已决项与依据，请求确认结束讨论并生成计划；无明确确认对象的推进词不构成交付计划的要求 |
| 用户提前要看计划，但仍有缺口 | 标明缺口的讨论稿；不宣称完整、不推定执行许可 |

本表适用于讨论收口，包括范围变化后重开的讨论。执行中断恢复且范围、决定和授权仍有效时，按恢复规则承接原工作，不重新请求确认结束讨论。

计划编制与发出前按[计划模块](planning.md#输出计划)检查决定来源。若新发现独立取舍，更新决策项并返回上述对应路径；不能把新问题塞在正式计划末尾，再约定未答就默认执行。已有完整授权与委托继续有效，不强制重走讨论。

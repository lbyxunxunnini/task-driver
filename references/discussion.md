# 调查分析并逐项讨论

进入讨论按主控读取策略加载或复用本文件。共同授权边界见[主协议](../SKILL.md#确认与授权)；任务类型的方法与多轮对照见[场景](scenarios.md)。本模块负责从分析到讨论收口，以及每次收到回答后的续接。

## 输入与交接

使用[调查与分析](analysis.md)所得事实、方案及依赖形成有价值的问题；事实不足时交回主控补查，不因每次收到回答重读分析模块。输入是当前任务、未决事项与有效决定；输出是本次回答覆盖的决定、未答部分、新分支及讨论是否闭合。跨环节推进由[主控](../SKILL.md#阶段转换)决定，不能因完成一个回答就把任务标成完成。

## 决策项与提问

列为待用户决定前，先把自己额外设想的改动拿掉：按用户原要求、已有决定和授权内的专业判断推进，是否仍有一项影响交付或验收的取舍必须由用户作出？没有就沿用适用做法，或在授权内自行决定，不把可选改进变成阻塞。若仍有取舍，说明具体卡在哪一步、不同回答会让用户得到什么，给出建议再问。用户正在探索目标、审美或使用偏好时，尚未委托的偏好本身可以决定交付，不因已有可行做法而代选。可查事实先查；只有用户掌握的必要事实直接问，不硬凑选项。

轻量模式在对话内维护已定、未定和下一问；提问前核对上下文和材料。达到[记录条件](state-recovery.md#何时建立记录)且获准持久记录后，提问前读取并更新唯一摘要，回答后保存变化；无写入许可或无法持久记录时维护对话内状态。维护决策项、状态、来源和范围及下一动作；事实、建议、用户决定和委托分别记录；委托范围内自行判断的内容标为委托决定，不标为用户已确认；不另建文件。收到回答先核对用户的回答对象、动作、条件和范围，再仅更新原话实际覆盖的内容；未回答的内容保持原状态。明确接受完整已展示方案时，其覆盖内容一并确认；用户表示某项不需要，不等于接受另一方案。用户修改或撤回时只重开受影响部分，并核对方案、示例和验收中的旧决定；其他有效决定继续沿用，同步获准维护的记录和计划。

整理决定或生成计划前，逐项用原话、适用规则或明确委托核对对象、动作和限定条件：依据不能支持的新增条件不得列为已决定。已决定规则的后果不自动决定其他相关行为；不要把关联实现或偏好记作用户决定。模型推论只能标为推论，示例、建议、沉默及推论不产生确认；有真实冲突或必要缺口时只处理受影响部分。

提问时先交付当前决定所需的事实和依据；需要用户决定已有成果如何调整且存在真实方案取舍时，结合当前问题说明已核实的原有情况、新要求或候选方案、相关变化与影响，再给推荐及理由，提出仍需用户决定的取舍。新版未确定时只称建议；原有情况无法核实则说明未知，不反复铺陈无关历史。其他方案取舍同样说明关键差异、推荐及理由；未知或推断按实际性质说明，不为缩短回复省略影响决定的信息。开放式了解事实或确认理解时，不虚构方案和选项。

讨论阶段把回复交还用户时，最终回复必须以一个问题结束。仍有影响当前方案的必要内容或用户决定时，询问当前一个问题；已经没有此类待决项时，询问是否结束讨论并开始展示正式计划与目标。先完成本轮调查、局部交付或其他可执行动作，再发最后问题；问题之后不得追加第二个问题、选项、总结或说明。用户明确暂停、明确限定本轮只交付指定内容，或任务已经结束时才可不提问，并保存该要求的来源。

### 提问语义复核

最终问题交给 `final` 前，必须对当前问题或免问结论做一次语义复核；问号数量只能证明格式，不能替代这次复核。`decision` 交接至少核对：问题对应当前待决项、没有被回答或排除、未被委托给模型、用户现在能够回答、只改变一个独立事项、问题后没有选项或补充说明。`plan_transition` 交接核对：已无阻塞讨论的待决项、问题确实是在请求结束讨论并开始展示正式计划与目标、只问一个问题、问题后没有其他正文。`waived` 核对：豁免来源明确，正文没有仍需用户回答的问题，问题后没有其他正文。

复核结果写入 `discussion_handoff.semantic_review`：`reviewer` 为 `independent` 或 `main`，`status` 仅在全部检查通过时填 `pass`，`target` 与交接类型一致，`source` 指向实际复核依据；问题交接还要填对应 `decision_id`。使用 `independent` 时另填实际 `review_id` 和 `authorization_source`，没有独立只读复核能力或授权时使用 `main` 并保留自检限制，不得把主模型自检写成独立复核。脚本会核对字段和状态，但不能证明复核内容真实。

检查项按交接类型填写：`decision` 使用 `target_is_current`、`not_already_decided`、`not_delegated`、`answerable_now`、`single_question`、`no_trailing_content`，计划请求仍有缺口时另加 `incomplete_plan_delivered`；`plan_transition` 使用 `transition_intent`、`no_blocking_pending_decisions`、`single_question`、`no_trailing_content`；`waived` 使用 `waiver_source_is_explicit`、`no_user_question`、`no_trailing_content`。

按[从做法选出下一问](analysis.md#从做法选出下一问)取得待决事项。提问时只给用户作决定所需的依据、差异和建议；了解事实时直接问；目的不直观时，用一句话说明答案会影响什么。用户刚澄清结果或尺度时，说具体哪些差异不能通过、哪些可以接受；已有明确判据直接沿用。用户要求保留且已查明的行为，即使新材料未展示，也不重问、不把改变它列为选项；新的要求、真实冲突或独立取舍只重开受影响部分。

**反例：**用户要求改版但保留原交互；已查明按钮点击后在下方展开，设计稿没有展示展开状态。

**错误：**询问“保持下方展开，还是改成底部弹层？”

**正确：**沿用下方展开，继续讨论真正未决定的事项。

已定规则的后果可以说明，但不能换一种说法重复要求确认；只有影响结果的独立取舍仍未决定、用户明确要求复核或修改、或存在真实冲突时才重开。用户指出已讨论过时先查可用记录，查不到则保留未知，只有答案确实必要且无法恢复时才请用户补充。现有实现只说明现在怎么做，不自动决定新需求必须保持现状；用户要求改变或存在真实冲突时讨论差异，不把它误判为重复。必要的问题不能因去重遗漏。

基于上述分析形成同一场景的有依据建议，供用户整体接受或局部修改，不把独立问题堆成问卷；用户明确要求一次一问或逐项讨论时遵从。仅改变实现且不改变用户可感知行为、费用、权限、安全、隐私、兼容性或已确认约束的细节自行处理。未决的核心选择须保留符合已定约束的真实替代方向；不将假设当事实、夹带无关功能或把未确定建议当作默认决定。

形成新问题前回看原目标、既有机制及累计代价；只讨论有依据且与目标相关的取舍，避免派生问题让方案无依据地扩张。真实相关的专业建议可标明依据供用户判断；事实不足时先补查或保留未知。

原生提问按[回复提交门禁](../SKILL.md#回复提交门禁)及[宿主适配](faq.md#原生选择器怎样使用)。等待答案只暂停依赖动作；预选、关闭、跳过、超时或未反对均不更新为已决。

## 回答后的推进

收到回答的同一轮先按下表更新决定，再按[回答后重算下一步](analysis.md#回答后重算下一步)分析影响，交回主控。用户选择不代表验证了推荐理由；模型自己的汇总不创造确认。事实、现状、有效规则、用户决定、委托内决定、建议与待证推断按[分析模块](analysis.md#事实推断与约束)区分；不因写入摘要改变性质。明确项目约束直接沿用，不为分类重复询问。

### 委托的承接

按自然语言识别用户委托的对象、动作、范围及限制，无需追加一轮授权表单。例如只委托名称或措辞，允许改表达，不同时决定分组、内容取舍；这些属于不同动作。必要内部实现是完成该已委托动作所必需的操作，不是模型认为效果更好的相邻方案。整体方案委托则充分承接，在已定目标与约束内作决定，不继续逐项问已委托细节；方案决策权与实际执行许可仍分开。

例如“优先级分类你来判断”允许决定分类标准及归类，不允许顺带决定“低优先级只抽样”。“测试方案专业取舍都由你决定”可以包含范围内的组织及执行策略设计，但实际运行仍须核对授权。派生选择未在委托内时留在待决区；记录“用户委托什么、模型据此决定什么”，不改写为用户亲自选择。

| 实际回答 | 状态更新 | 当轮下一步 |
|---|---|---|
| 回答了当前事项 | 只确认实际回答对象；明确接受完整已展示方案则确认其组成，示例和对象外附带建议仍待定 | 检查派生影响，然后提出下一项；已达到收口条件则收口 |
| 只回答了部分内容 | 保留已答部分与未答部分 | 仅针对仍必要的未答部分继续讨论，不重问已答内容 |
| “不知道”“不确定” | 记为未知；不是否定、不可用、取消或委托 | 能查则查；不能查则分析如何获得证据或讨论一个替代取舍，不循环逼问同一事实 |
| 只认可方向、例子或顺序，或只说“值得做/不错/可行” | 只保留该评价的实际范围；没有回答当前选择、范围和确认对象时，不认定选择具体方案、范围或执行 | 延续当前待决取舍，不以评价开始执行或写成已决定 |
| 明确延期或排除 | 记录用户决定及对当前方案的影响 | 当前方案依赖该事项时先处理依赖；不能把阻塞项搬到以后就宣布闭合 |
| 改变了之前决定 | 只重开受影响部分，其余有效决定保留 | 说明实际影响，讨论下一个受影响事项 |
| 解答了执行中的必要澄清 | 补齐相关事实或决定，保留原授权 | 返回主控，按原环节的恢复条件继续 |
| 只是任务中的解释性插问 | 回答解释，不清空任务状态 | 返回主控处理原任务续接；明确暂停时保留暂停状态 |

回答一个未决项只更新该项；未满足执行入口条件时，不得开始实际执行。讨论转计划按主控阶段转换处理。

保守行动与事实判断分别处理：扣费情况未知时可以暂停可能扣费的动作，但不得据此断言必然扣费或取消测试覆盖。需要调整方案时先提出具体建议，不把建议写成“你已决定”。

局部交付后必须回到原目标重新筛选下一事项；用户请求先查或先整理且没有限定只做这一项时，不能停在“已记录”“已修改”或“之后继续”。下一事项必须与原任务有关且经去重；可查的先查，需用户决定的形成具体讨论，全部闭合则按主控收口，并以当前内容问题或结束讨论问题结束回复。工具等待和外部阻塞不是免问理由；明确暂停、明确限定本轮只交付指定内容按主控例外处理。

同一任务在对话中维护当前环节、当前问题、事实及证据、已确认或委托决定及来源、未决和延期事项及依赖。按[记录与恢复](state-recovery.md)判断保存时机；已启用持续记录且获准写入时，先保存本轮有效变化，再问下一项；不允许写入时在对话内维护。中断后先恢复这些内容再按本表续接；不因“确认、1、继续”重新初始化。

## 讨论完成门禁

收口是决策项核对的结果，不以问答轮数、最初清单问完或“已生成一份计划”作为依据。首次接手一段已有讨论，先按[开场分析](analysis.md#分析的组织)恢复结果及其判据；刚纠正或撤下上一问，只说明这一项已处理。提议转计划前，沿约定的起点走到结果：对准备写进计划的结果也要查明触发条件。材料里出现过某个结果，不等于在本次范围内能走到它；条件缺失且影响交付时，不能既不问就承诺，也不问就删去。已有决定或可用路径能解决的，直接承接。

1. **覆盖核对**：沿实际使用、质量、异常、交付与验收检查缺项和新分支；只保留当前目标内的相关事项。
2. **决定核对**：需要用户决定的项均有用户决定、适用规则或范围内委托作为依据；可自行处理的内部事项保留判断依据。委托可决项先由模型形成明确决定并保留来源；不能一边宣称已收口，一边请用户对这些项再次点头。
3. **未知处理核对**：不改变当前选择且有可行核实路径的事实，列为计划前置；会改变方案的待查项先调查，必须用户决定的待决项按同场景建议或用户要求逐项讨论。延期不能搬走当前依赖。

核对结果只走一条路径：

| 结果 | 返回主控的产物与下一动作 |
|---|---|
| 仍有影响方案的未决项 | 用户明确要求先看详细设计且限定本轮只交付该设计时，交付标明缺口的设计稿后停止并保留恢复点；否则提出当前必要事项或同场景完整建议，最终回复以当前问题结束，不同时请求执行 |
| 无上述未决项，用户已要求生成计划，或要求直接进入执行 | 已决项及依据 → 按[主控展示策略](../SKILL.md#展示与确认策略)先展示计划和目标，再按证据判断是否已有执行授权；直接执行要求不构成跳过计划展示或内容确认 |
| 无上述未决项，用户既未要求计划也未要求直接执行 | 用户明确要求任务到此结束、明确限定本轮只交付指定内容，或任务最终仅交付当前结果且已满足时收口；只限定本轮处理局部须保留原任务恢复点，“先讨论、本轮不执行”不等于整体任务结束，其他情况汇总已决项与依据，以“是否结束讨论并开始展示正式计划与目标”这一问题结束回复。无明确确认对象的推进词不构成交付计划的要求 |
| 用户明确限定本轮只交付计划或设计，但仍有缺口 | 标明缺口的讨论稿/设计稿交付后停止并保留恢复点；不宣称完整、不推定执行许可 |

本表适用于讨论收口，包括范围变化后重开的讨论。执行中断恢复且范围、决定和授权仍有效时，按恢复规则承接原工作，不重新请求确认结束讨论。

计划编制与发出前按[计划模块](planning.md#输出计划)检查决定来源。若新发现独立取舍，更新决策项并返回上述对应路径；不能把新问题塞在正式计划末尾，再约定未答就默认执行。已有完整授权与委托继续有效，不强制重走讨论。

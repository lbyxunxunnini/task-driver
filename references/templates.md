# 模板参考

SKILL.md 各环节引用的展示模板，集中维护于此。

## 轻量计划摘要模板

文件名：`.task-driver/{任务标题}-{YYYYMMDDHHmmss}-计划摘要.md`

```markdown
# {任务标题} 计划摘要

## 目标

## 已确认内容
| 项目 | 内容 | 状态 |
|---|---|---|

## 计划

### 1. {计划事项}
- 已确认：
- 实施方案：
- 影响范围：
- 状态：

## 验收目标
| 序号 | 最终验收目标 | 宿主任务 ID（如有） | 内部检查方式 | 状态 |
|---|---|---|---|---|

## 目标执行记录
| 轮次 | 验收目标 | 状态 | 打回原因 | 处理结果 |
|---|---|---|---|---|

## 当前结论
```

## 计划草案展示模板

```markdown
# 计划草案

任务目标：{本次任务最终要达成什么}

计划依据：
- 已确认 {N} 个需求或问题。
- 以下计划事项与它们逐项对应。

## 1. {计划事项}

### 已确认

- {讨论中确认的关键决策和边界}

### 预期变化

现状：
{当前问题或缺失能力}

实施后：
{用户或系统将表现成什么样}

### 实施方案

{具体完成方法、作用边界和关键约束；“完整”等要求如何覆盖并核对遗漏，不只写分析/编写/检查}

### 涉及位置

- {主要文件、模块、流程或产物，以及准备调整什么}

### 内部验证

- {模型准备使用的行为回放、测试或检查}
```

## 条件合并与统一确认模板

仅满足主协议全部合并条件时，计划和目标同轮展示；否则先确认计划，再形成目标。目标按实际最终结果组织，不按实施步骤逐项生成。

```text
计划：{已确认内容、具体实施方法}
最终验收目标：{对应需求的可验证最终结果}

选择执行即同时确认本轮展示的计划、目标、执行范围和子代理设置。
1. 执行，开启子代理：{影响；推荐此项时标注推荐并说明当前理由}
2. 执行，不开启子代理：{影响；推荐此项时标注推荐并说明当前理由}
3. 不执行，继续讨论：暂不执行，调整计划或目标。
```

实际提问必须标注一个推荐项，不照抄占位符。原生提问工具可用时使用工具承载以上选择；不另外文字问一遍。

## 统一异常通知骨架

```markdown
## {未达标 / 需要用户验收 / 需要用户授权或决定 / 受阻}

当前结果：{当前做到什么程度}

原因：{为什么没有继续或没有达标}

已完成：
- {已经完成的内容}

下一步：{agent 将怎样修复，或用户需要完成什么}
```

## 用户验收通知格式

```markdown
## 需要用户验收

当前结果：{agent 已完成的检查和当前产物状态}

原因：{agent 无法可靠验证的具体原因}

已完成：
- {已经完成的实现和内部验证}

验收步骤：
1. {具体操作}
2. {具体操作}
3. {具体操作}

通过条件：
- {用户应看到或得到的明确结果}

请反馈：
- {需要用户回复的通过/不通过结果，以及必要的截图、现象或其他证据}

下一步：收到反馈后核对结果；已开启审查时还须审查通过，满足主协议全部完成条件后才完成目标；未达标则分类处理。
```

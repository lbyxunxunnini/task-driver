# 模板参考

SKILL.md 各环节引用的展示模板，集中维护于此。

## 轻量计划摘要模板

文件名：`.task-driver/{任务标题}-{YYYYMMDDHHmmss}-计划摘要.md`

```markdown

## 目标

## 已确认内容
| 项目 | 内容 | 状态 |
|---|---|---|

## 计划

### 1. {计划事项}
- 已确认：
- 实施方案：
- 影响范围：
- 状态：

## 验收目标
| 序号 | 最终验收目标 | 宿主任务 ID（如有） | 内部检查方式 | 状态 |

| 轮次 | 验收目标 | 状态 | 打回原因 | 处理结果 |

```

## 计划草案展示模板

默认只展示“已确认”和“实施方案”；复杂任务按主协议需要补充后列的可选内容，不为填模板新增问题。

```markdown
# 计划草案

任务目标：{本次任务最终要达成什么}

计划依据：
- 已确认 {N} 个需求或问题。
- 以下计划事项与它们逐项对应。

## 1. {计划事项}

### 已确认

- {讨论中确认的关键决策和边界}

### 实施方案

{具体完成方法、作用边界和关键约束；“完整”等要求如何覆盖并核对遗漏，不只写分析/编写/检查}
```

可选内容仍归对应计划事项：

- 预期变化：当前表现及实施后的用户或系统表现。
- 涉及位置：主要文件、模块、流程或产物，以及准备调整什么。
- 内部验证：使用的行为回放、测试或检查。

## 条件合并与统一确认模板

仅满足主协议全部合并条件时，计划和目标同轮展示；否则先确认计划，再形成目标。目标按实际最终结果组织，不按实施步骤逐项生成。

```text
计划：{已确认内容、具体实施方法}
最终验收目标：{对应需求的可验证最终结果}

选择执行即同时确认本轮展示的计划、目标、执行范围和子代理设置。
1. 执行，开启子代理：{满足并发全部条件时并发实现，否则主线程执行；完成后独立审查。按任务说明代价，推荐此项时标注并给理由}
2. 执行，不开启子代理：{主线程执行并自检，不分派执行或审查子代理。推荐此项时标注并给理由}
3. 不执行，继续讨论：暂不执行，调整计划或目标。
```

实际提问必须标注一个推荐项，不照抄占位符。原生提问工具可用时使用工具承载以上选择；不另外文字问一遍。

## 独立审查交接模板

仅已开启独立审查时使用，首审与复审均在独立上下文中交接。以下内容填入真实目标、权限、证据和可访问的协议位置后直接作为审查任务，不把模板占位符发给子代理。

```text
已确认目标：{用户确认的最终验收目标原文，不附达成状态}
范围与限制：{当前审查对象、授权内的核实操作和用户限制}。审查前先读取 {当前 SKILL.md 的可访问位置} 的“第七步：子代理独立审查”，按其中的输入检查和输出要求审查。
当前产物与客观证据：{当前版本及核实各目标所需的文件、原始输出；流程事实对应实际消息记录}
本次变更（仅复审）：{本次客观差异及待核实影响；首审省略此字段}
```

若子代理无法读取该位置，将上述读取指令替换为主协议输入检查和输出要求的原文，仍放在“范围与限制”中；不要求用户安装工具。不得交付执行者自评或前次审查结论。

## 统一异常通知骨架

先对照用户当前要求判断是否需要决定：本轮只读核对已经完成时，报告核对结果及原交付目标仍未达标即可结束，不把后续修复授权变成本轮必答项。只有当前任务确实需要用户决定才能继续时，“下一步”才给可直接选择的方案、各项影响、一个推荐项及理由；已有授权范围内的修复直接处理。

```markdown
## {未达标 / 需要用户验收 / 需要用户授权或决定 / 受阻}

当前结果：{当前做到什么程度}

原因：{为什么没有继续或没有达标}

已完成：
- {已经完成的内容}

下一步：{agent 将怎样修复，或用户需要完成什么}
```

## 用户验收通知格式

```markdown
## 需要用户验收

当前结果：{agent 已完成的检查和当前产物状态}

原因：{agent 无法可靠验证的具体原因}

已完成：
- {已经完成的实现和内部验证}

验收步骤：
1. {具体操作}
2. {具体操作}
3. {具体操作}

通过条件：
- {用户应看到或得到的明确结果}

请反馈：
- {需要用户回复的通过/不通过结果，以及必要的截图、现象或其他证据}

下一步：收到反馈后核对结果；已开启审查时还须审查通过，满足主协议全部完成条件后才完成目标；未达标则分类处理。
```

# 执行控制

输入：有效计划、最终目标、对应授权和执行设置。输出：实际产物、变更、执行结果及待验证事项。条件有缺失时，必须交回主控返回对应环节；授权内可继续的工作必须连续执行。步骤完成与目标通过分别核对，实际产物必须交给[验证取证](verification.md)。

## 创建目标并执行

目的：按最终验收目标连续实现。

### 执行入口

进入执行前必须核对[主控四项证据](../SKILL.md#展示与确认策略)、分析与讨论闭合、编号步骤、执行范围、子代理设置和目标跟踪。任一前置项缺失时，必须返回对应环节，禁止开始实施。禁止先创建宿主目标再补创建前所需的引证。

必须以主控确认的有效范围、目标、授权和当前动作为依据。必须按[宿主目标工具协议](#宿主目标工具协议)查询、复用或创建宿主目标，保存实际返回 ID，并在实施前通过实际工具将目标更新为执行中。范围未变、当前仍处于执行中且回执有效时，必须复用现有状态。工具失败必须按协议处理，禁止把准备调用当成操作成功。

完成目标跟踪后，必须携带[实际前置状态](workflow-control.md#首次执行的确认顺序)运行 `scripts/workflow_control.py begin`；开始第一项业务动作前，必须取得与当前结构授权一致的 `execution_receipt`。回执证明结构字段和来源已填写，禁止以它代替实际工具回执或用户确认。目标、计划、范围、执行授权、子代理设置或目标跟踪方式变化时，旧回执必须视为失效。有活动插问、未核实操作或阻断步骤时，必须先按主控规则处理，再运行 begin。

必须向主控回交实际目标 ID、执行中回执或有效降级依据，以及下一业务动作。主控按阶段转换决定开始实施、resume 或制作报告。只读现场查询无需先创建目标；讨论期记录必须按记录模块保存。

### 执行并发判断与分派

准备分派时，必须读取或复用[子代理管理](subagents.md)，按收益、安全条件和当前依赖选择主线程、串行委派或并发。分派实施前必须满足本模块执行入口。执行代理必须返回实际产物和证据，主线程必须按该模块整合后交验证。

执行分工与运行调度必须遵循[子代理管理](subagents.md)。独立复核的触发、标准和要求必须遵循[审查模块](review.md#独立复核要求)，禁止因执行分派而改变。

### 宿主目标工具协议

执行前必须按宿主实际工具、schema 和使用限制，分别核对查询、复用与创建目标的能力和条件。允许查询时必须先查询；存在对应有效目标且允许复用时必须复用，确认没有对应有效目标且允许创建时必须创建。已有对应目标但不能复用、或目标状态无法核实时，禁止重复创建，必须按下表处理冲突或未知结果。目标工具可用时，实施前必须取得实际回执及执行中状态；工具不可用或受限时，必须按下表核对降级条件。禁止仅凭工具名称降级、猜参数或反复试错。宿主对创建目标另有要求时必须满足，禁止以执行授权替代。

| 当前条件 | 必须动作 |
|---|---|
| deferred 工具需加载 schema | 有 ToolSearch 时必须分别加载 `ToolSearch query="select:TaskCreate"`、`ToolSearch query="select:TaskList"`、`ToolSearch query="select:TaskUpdate"`；其他宿主必须按实际发现机制加载 |
| 目标或计划工具报 `Invalid tool parameters` | 必须停止猜参，重新加载或核对 schema 后按定义重试一次，禁止重复重试；仍失败时必须停在当前阶段并说明错误，降级前必须取得用户对降级方式的确认。禁止计入目标修复次数 |
| 目标管理能力可用且当前动作符合宿主限制与用户授权 | 必须按以上查询、复用和创建条件处理。聚合目标必须完整承载已确认的验收目标。使用任务列表时，每条目标必须对应一条任务，禁止为同一目标创建多条任务，禁止把工程目标或施工步骤建为任务 |
| 任务列表创建前 | 必须先查询已有任务，再按已保存 ID 或原文匹配并复用对应任务，禁止重复创建 |
| 创建成功 | 必须保存返回 ID 和实际创建或更新回执，将回执写入 `goal_tracking_host_receipt`；已有摘要时必须记录在同一摘要，否则必须在上下文维护，禁止另建文件 |
| 目标工具真实不可用、无法获取 schema，或宿主限制导致不能复用已有目标且不能创建 | 必须停在当前阶段、记录实际工具或宿主证据，并向用户说明拟采用计划或对话编号跟踪。必须取得用户确认后再降级；禁止自动继续，或把“尚未明确请求创建”“模型不确定”写成不可用 |
| 创建/更新失败、工具暂不可用或已有目标冲突 | 必须说明具体失败和实际影响，禁止自动降级。可无损保留范围、授权和状态时，必须提出降级方案并等待用户确认；涉及覆盖、删除、关闭旧目标、改变范围或丢失状态时，必须先由用户决定 |

创建或复用宿主目标时，正文必须直接取自已确认的 goals.included，每项必须写为“编号：通过条件原文”（全角冒号，禁止加标题或其他摘要）。聚合宿主必须将所有条目按顺序以换行连接在同一个 objective 中；任务列表必须按上表一项一条分别写入。创建有返回正文时必须使用该正文，否则必须查询已有记录并读回正文。必须按[状态检查](workflow-control.md)保存实际 ID 与正文，并用实际读回值逐项比对，禁止用发出参数、成功状态或粗略标题代替。旧记录必须先补读，禁止重复创建。发现不一致时必须按上表的冲突或更新路径处理，禁止报告已同步；旧目标不可维护时必须按[下一节](#目标范围变化与旧目标失效)区分业务收口和宿主状态。

执行前必须依据实际回执简述目标创建或复用结果。降级必须有真实不可用的证据、向用户说明的具体原因及用户确认；降级仅改变跟踪载体，禁止改变目标原文、授权、完成门槛或审查要求。禁止把展示验收目标当成目标已创建或降级跟踪已完成。宿主工具可用时禁止降级。

### 目标范围变化与旧目标失效

目标展示或宿主目标创建后，用户明确变更范围、排除外部依赖或接受部分验收结果时，必须以最新要求作为业务完成口径。必须先保存旧目标原文及来源、旧宿主目标 ID、新范围来源及替代关系，把旧目标记录到 `superseded_goals` 并标记为 `superseded`。禁止用旧目标的外部依赖否决用户已确认的新范围，或把旧目标伪标为完成。当前 `goals` 的记录必须限于新范围内的有效目标。必须用 `host_goal_sync: synced|stale|unavailable` 记录宿主同步状态。

没有 Goal 模式时，历史 `superseded_goals` 和当前 `goals` 必须使用同一稳定的 `local_goal_id`，`host_id` 可省略、为空或为 `null`。禁止虚构宿主 ID 或声称宿主目标已更新、已完成。

宿主支持更新目标内容时，必须先更新已有目标再把 `host_goal_sync` 记为 `synced`。不支持更新但允许删除或替换时，必须按宿主能力请用户决定删除或替换旧目标，再按新范围建立对应目标。已有目标不能复用且不能更新时，禁止重复创建，必须按目标冲突路径处理。宿主完全不允许维护目标内容时，业务验收必须按新范围报告，业务已验收时报告为“已验收、宿主目标仍为旧版本”；`host_goal_sync` 必须记为 `stale` 或 `unavailable`，持久记录必须保留 `superseded` 关系和删除或替换入口。禁止以宿主状态否决业务完成，或声称旧目标已同步完成。

## 实施与返回

必须按有效计划顺序推进，并回交实际操作结果与证据。原操作结果未知时，必须先回到现场核对，禁止自行重复调用。步骤不足但最终目标不变时，必须调整受影响步骤，重新展示并确认，旧执行回执必须视为失效。范围、目标、风险或权限变化时，必须交回主控处理受影响部分。

子任务整合后必须交验证与审查，记录必须按实际回执更新，完成同步由[主控完成门槛](../SKILL.md#完成门槛)决定。可按产物形式、工具限制、内容规模和完整性选择先做骨架或分段。采取分段方式时，必须检查结构与衔接，禁止仅因分段索取重复确认。

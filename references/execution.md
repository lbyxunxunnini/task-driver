# 执行控制

输入：有效计划、最终目标、对应授权和执行设置。输出：实际产物、变更、执行结果及待验证事项。缺少条件由主控返回缺失环节；已有授权内连续执行。步骤完成不等于目标通过，产物交给[验证取证](verification.md)。

## 创建目标并执行

目的：按最终验收目标连续实现。

### 执行入口

进入执行前核对[主控四项证据](../SKILL.md#展示与确认策略)，并核对分析/讨论闭合、编号步骤、执行范围、子代理设置和目标跟踪。任一项缺失则返回对应环节，不得开始实施、不得先创建宿主目标再补引证。

输入由主控确认的有效范围、目标、授权和当前动作。按下节查询并复用或创建宿主目标，保存返回 ID，使用实际工具先更新执行中；范围未变且当前仍处于执行中、已有回执有效时复用。工具失败按下节处理，不把准备调用当成功。

完成目标跟踪后携带上一状态运行 `scripts/workflow_control.py begin`，取得与当前结构授权一致的 `execution_receipt` 才能开始第一项业务动作。该回执只证明结构字段和来源已填写，不能替代实际工具回执或用户确认；目标、计划、范围、执行授权、子代理设置或目标跟踪方式变化时旧回执失效。活动插问、未核实操作和阻断步骤优先于 begin。

返回“实际目标 ID、执行中回执或有效降级依据、下一业务动作”给主控。主控据阶段转换决定开始实施、resume或制作报告。只读现场查询不需要先创建目标；讨论期记录保存由记录模块负责。

### 执行并发判断与分派

准备分派时读取或复用[子代理管理](subagents.md)，按收益、安全条件和当前依赖选择主线程、串行委派或并发；分派实现前仍须满足本模块执行入口。执行代理返回实际产物和证据，主线程按该模块整合后继续验证。

该模块唯一维护执行分工与运行调度；独立复核的触发、标准和要求仍由[审查模块](review.md#独立复核要求)维护，不因执行分派改变。

### 宿主目标工具协议

执行前必须按宿主实际工具、schema 和使用限制分别核对查询、复用与创建目标的能力和条件；允许查询时必须先查询已有目标，存在对应有效目标且允许复用时必须复用，确认没有对应有效目标且允许创建时必须创建。已有对应目标但不能复用或目标状态无法核实时，不得重复创建，按下表处理冲突或结果未知。取得实际回执及执行中状态后才能实施；工具不可用或受限时按下表处理，不因工具名称不同直接降级。执行授权不自动满足宿主对创建目标的单独要求。不猜参数、不反复试错。

| 当前条件 | 必须动作 |
|---|---|
| deferred 工具需加载 schema | 有 ToolSearch 时分别加载 `ToolSearch query="select:TaskCreate"`、`ToolSearch query="select:TaskList"`、`ToolSearch query="select:TaskUpdate"`；其他宿主按其实际发现机制加载 |
| 目标或计划工具报 `Invalid tool parameters` | 停止猜参，重新加载或核对 schema 后按定义重试一次；仍失败则停在当前阶段并说明错误，取得用户对降级方式的确认后才能降级，不计目标修复次数 |
| 目标管理能力可用且当前动作符合宿主限制与用户授权 | 允许查询时必须先查询；存在对应有效目标且允许复用时必须复用，确认没有对应有效目标且允许创建时必须创建；聚合目标完整承载已确认目标，任务列表每条目标只对应一条任务，禁止把工程目标或施工步骤建为任务 |
| 任务列表创建前 | 必须先查询已有任务；按已保存 ID 或原文匹配并复用，禁止重复创建 |
| 创建成功 | 保存返回 ID 和实际创建/更新回执，写入 `goal_tracking_host_receipt`；已有摘要则记录其中，否则仅维护于上下文，不单独建文件 |
| 目标工具真实不可用、无法获取 schema，或宿主限制导致不能复用已有目标且不能创建 | 先停在当前阶段并记录实际工具或宿主证据；向用户说明拟改用计划/对话编号跟踪，取得用户确认后才能降级。不得自动继续，也不得把“尚未明确请求创建”或“模型不确定”写成不可用。 |
| 创建/更新失败、工具暂不可用或已有目标冲突 | 说明具体失败和实际影响；不得自动改用降级跟踪。可无损保留范围、授权和状态时提出降级方案并等待用户确认；涉及覆盖、删除、关闭旧目标、改变范围或丢失状态时必须先让用户决定 |

创建或复用宿主目标时，目标正文直接取自已确认的 goals.included：每项写成“编号：通过条件原文”（全角冒号，不加标题或其他摘要）。聚合宿主在一个 objective 内依次用换行连接所有条目；任务列表仍每条目标只对应一条任务，分别写一条。创建返回正文则直接使用；否则查询已有记录读回正文，按[状态检查](workflow-control.md)保存真实 ID 与正文。以实际读回值逐项比对，不用发出的参数、成功状态或粗略标题代替；旧记录先补读，不重复创建。不一致按上表的冲突或更新路径处理，不能报已同步；旧目标不可维护时仍按下节区分业务收口和宿主状态。

执行前依据实际回执简述已创建或复用目标。降级只改变跟踪载体，不改变目标原文、授权、完成门槛和审查要求；必须是真实不可用、已说明具体原因并经用户确认。仅展示验收目标不等于创建目标，也不等于已完成降级跟踪。宿主工具可用时不得降级。

### 目标范围变化与旧目标失效

用户后续明确缩小、替换或接受部分验收结果时，以最新用户要求作为业务完成口径。先保存旧目标原文、旧宿主目标 ID、新范围来源及两者关系，将旧宿主目标记录到 `superseded_goals` 并标记为 `superseded`，不得继续用旧目标中的外部依赖否决用户已确认的新范围，也不得把旧目标伪标为完成。当前 `goals` 只放新范围的有效目标；宿主同步状态用 `host_goal_sync: synced|stale|unavailable` 记录。

没有 Goal 模式时，`superseded_goals` 使用稳定的 `local_goal_id`，`host_id` 可省略、为空或为 `null`；当前 `goals` 也保存同一 `local_goal_id`。不得用虚构宿主 ID 代替，也不得声称宿主目标已更新或完成。

宿主支持更新目标内容时，先更新已有目标并把 `host_goal_sync` 记为 `synced`；不支持更新但允许删除或替换时，按宿主能力让用户决定删除或替换旧目标，再按新范围建立对应目标；已有目标不能复用且不能更新时，不重复创建，按目标冲突路径处理。宿主完全不允许维护目标内容时，业务结果按新范围报告为“已验收、宿主目标仍为旧版本”，`host_goal_sync` 记为 `stale` 或 `unavailable`，持久记录保留 `superseded` 关系和删除/替换入口，不把宿主状态当成业务未完成，也不声称旧目标已同步完成。

## 实施与返回

按有效计划顺序推进，交回实际操作结果和证据；原操作结果未知时先返回现场核对，不自行重复调用。计划步骤不足但最终目标不变时调整受影响步骤并重新展示、重新确认，旧执行回执失效；范围、目标、风险或权限变化交回主控处理受影响部分。

子任务整合后交验证与审查；记录按实际回执更新，完成同步由[主控完成门槛](../SKILL.md#完成门槛)统一决定。按产物形式、工具限制、内容规模及完整性决定是否先做骨架或分段；分段时检查结构与衔接，不为分段重复确认。

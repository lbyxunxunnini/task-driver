# 执行控制

输入：有效计划、最终目标、对应授权和执行设置。输出：实际产物、变更、执行结果及待验证事项。缺少条件由主控返回缺失环节；已有授权内连续执行。步骤完成不等于目标通过，产物交给[验证取证](verification.md)。

## 创建目标并执行

目的：按最终验收目标连续实现。

### 执行入口

输入由主控确认的有效范围、目标、授权和当前动作。按下节查询并复用或创建宿主目标，保存返回 ID，使用实际工具先更新执行中；范围未变且当前仍处于执行中、已有回执有效时复用。工具失败按下节处理，不把准备调用当成功。

返回“实际目标 ID、执行中回执或有效降级依据、下一业务动作”给主控。主控据阶段转换决定开始实施、resume或制作报告。只读现场查询不需要先创建目标；讨论期记录保存由记录模块负责。

### 执行并发判断与分派

本节约束参与实现的执行子代理，不改变审查模块独立审查的启停、角色和要求。

- 任务开始时必须先分析执行依赖和改动影响范围，再决定执行方式；任务大、文件多或工具支持子代理，均不能单独作为并发依据。
- 以下条件全部满足时，必须拆分并发：每个子任务的目标、输入、交付物、修改范围和完成标准明确；能够独立开始，不依赖其他子任务尚未产出的结果；改动不改变其他子任务依赖的接口、数据结构、配置或业务行为；不同时修改同一内容，不争用会相互干扰的运行资源；执行并发已在用户授权范围内。任一条件不满足或无法确认满足时，必须由主线程串行执行。修改不同文件不能代替上述判断。
- 后一步依赖前一步结果的递进任务，或无法确认相互独立的任务，必须由主线程串行执行；禁止假定前序结果或让多个代理各自决定公共约定来制造并发条件。用户明确关闭子代理时，禁止启用执行子代理。
- 在现有计划的实施方案中简述执行方式和依据；并发时列出各子任务的目标与修改边界，随原有计划及执行确认获得授权，不增加表单或确认轮次。执行子任务仅用于内部分派，不增加最终验收目标，也不得作为额外的宿主验收任务创建。
- 主线程负责分派和整合；执行子代理只在获派范围内实现，返回实际改动与验证证据。执行中发现依赖或交叉影响时，必须停止受影响的并发工作、保留已有结果，由主线程接回处理。
- 子任务完成不等于整体完成；整合后仍按原有最终验收目标、自检和已开启的独立审查要求判断结果。

### 宿主目标工具协议

必须按宿主实际工具和 schema 识别能力，不得仅凭 `TaskCreate` 或 `ToolSearch` 是否存在判断，不猜参数、不反复试错。

| 当前条件 | 必须动作 |
|---|---|
| deferred 工具需加载 schema | 有 ToolSearch 时分别加载 `ToolSearch query="select:TaskCreate"`、`ToolSearch query="select:TaskList"`、`ToolSearch query="select:TaskUpdate"`；其他宿主按其实际发现机制加载 |
| 目标或计划工具报 `Invalid tool parameters` | 停止猜参，重新加载或核对 schema 后按定义重试一次；仍失败则走降级，不计目标修复次数 |
| 支持目标管理 | 必须创建目标；聚合目标完整承载已确认目标，任务列表每条目标只对应一条任务，禁止把工程目标或施工步骤建为任务 |
| 任务列表创建前 | 必须先查询已有任务；按已保存 ID 或原文匹配并复用，禁止重复创建 |
| 创建成功 | 保存返回 ID；已有摘要则记录其中，否则仅维护于上下文，不单独建文件 |
| 目标工具不可用或无法获取 schema | 自动降级到计划工具（如 `update_plan`），原样跟踪目标、复用对应条目并保留无关条目；两类工具均不可用才在对话中跟踪，不另写目标专用记录文件；已启用的唯一任务记录仍按记录模块更新 |
| 创建/更新失败、工具暂不可用或已有目标冲突 | 说明原因；可无损保留范围、授权和状态时降级。涉及覆盖、删除、关闭旧目标、改变范围或丢失状态时，必须先让用户决定 |

降级只改变跟踪载体，不改变目标原文、授权、完成门槛和审查要求；简述方式后继续，不退回计划讨论、不重索授权、不逐步询问是否继续。展示草案不等于创建目标。

## 实施与返回

按有效计划推进，交回实际操作结果和证据；原操作结果未知时先返回现场核对，不自行重复调用。计划步骤不足但最终目标不变时调整步骤并说明；范围、目标、风险或权限变化交回主控处理受影响部分。

子任务整合后交验证与审查；记录按实际回执更新，完成同步由[主控完成门槛](../SKILL.md#完成门槛)统一决定。大任务先骨架再分块；超过200行的新文件或大段内容分次写，每次检查结构，不为分块重复确认。

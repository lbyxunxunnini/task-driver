# 验证取证

输入：目标原文、通过条件、当前产物和环境权限。输出：实际操作、观察结果、证据来源、覆盖和未核实部分。缺少证据不等于失败事实，更不等于通过；结果交给[审查模块](review.md)判断充分性，由主控决定完成。

## 选择能证明目标的方法

| 目标性质 | 合适的证据 | 单独不足以证明目标的内容 |
|---|---|---|
| 指定文本或配置修改 | 当前文件读取、前后差异、范围保持检查 | 声称“已改”、准备写入的文本 |
| 功能在约定场景可用 | 实际输入、执行路径、可观察输出及必要异常/回归 | 文件存在、编译成功、计划完成 |
| 模型交互行为 | 使用固定协议快照的真实多轮对话、工具事件、实际产物及状态变化 | 规则关键词存在、模型自评、问题数量 |
| 外部环境或设备结果 | 授权环境中的真实操作、日志或可核实反馈 | 离线模拟替代真实部署或设备结论 |
| 创作或主观体验 | 实际产物、自身可做的内容与显示检查、必要用户反馈 | 提示词存在、文件可解码替代审美通过 |

静态检查可以直接证明文本类目标，也可作为功能验证的辅助。模拟测试明确其覆盖条件，不把模拟成功扩写成真实业务成功。不能验收的环境如实标缺口，不能悄悄降低原通过条件。

## 执行验证

先把目标转成可观察的输入、动作与预期结果，再运行；必要负例与边界来自用户要求和实际风险，不随意增加目标。记录真实输出，不只记录命令退出码；执行失败、条件不足和目标不满足分别说明。

检查证据对应当前产物及实际环境。产物变化时重验受影响路径，不把旧快照结果拼成新版本通过。多轮行为测试保存任务输入、协议快照、逐轮回答、工具动作及实际变化；判据留在测试侧，不提示被测模型如何通过。

讨论质量应测试到真实收口与正式计划，检查必要覆盖、未决事项、委托边界和无必要追问；仅前几轮改善不算全流程通过。恢复能力用授权的隔离进程或可控服务观察运行中断连、操作成功但返回丢失、部分失败后的续接，核对运行标识、实际副作用与重复次数；模拟材料、真实隔离运行、生产现场分别报告。

验证结论按[目标与验证模板](templates.md#目标与验证模板)记录；有缺口交回主控决定调查、讨论、修复或必要用户验收。验证没有授权额外收费、发布或修改生产系统。

## 用户验收补位

用户明确要求亲自验收，或已确认结果仍有 Agent 无法可靠验证的主观体验、私有账号、真实设备或外部环境要求时，需要用户验收。先完成自身可做检查，再请求用户补足对应结果的反馈；不能因任务简单或部分检查通过而跳过。

若当前证据已覆盖全部已确认结果，且用户未要求亲自验收，则不额外请求用户确认；例如指定文字修改经当前文件、差异和范围保持检查即可证明结果。是否需要用户验收取决于用户要求与证据覆盖，不按“简单任务”或“Bug 修复”标签一概豁免；执行授权不等于用户对实际结果的验收。

需要用户验收时，使用前读取或复用[用户验收通知格式](templates.md#用户验收通知格式)，给编号操作、预期结果、通过条件、需要反馈的证据；不能只说“请自行检查”。

等待反馈保持未完成；反馈只覆盖实际验收范围，反馈不通过时按[主控](../SKILL.md#展示与确认策略)承接，明确缺陷交审查模块分类。用户无法完成必要验收且无可靠替代证据时受阻。

涉及生产、费用、发布、覆盖、删除或安全权限时，核对目标、授权动作与可恢复路径；能用授权内的工具和证据验证就先做，无法可靠核实的结果请求必要用户验收，不把高风险当作重复确认一切的理由。

## 候选与测试材料隔离

冻结协议及实际任务所需原始材料后再调用被测模型；评测判据、角色回答、历史失败、当前报告与审查结论留在控制端。采用源码子集时记录白名单与哈希，明确未提供不代表原项目缺失；正式协议的示例属于产品内容，不等于隐藏判据。每个样本先验证实际基线，基线失败的轮次记失败或无效覆盖，不能挪作目标故障恢复成功。

顺序性行为按工具事件与实际产物核对；对运行中状态记录观测时间与任务完成时间，区分持续观察、合理宿主限制和无依据等待用户。测试宿主、实际模型与隔离能力如实记录，不把命令行产品名当模型名，也不把只靠提示约束的工作目录当强制沙箱。

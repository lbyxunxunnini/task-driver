# 业务场景最佳实践

本文件帮助模型和用户判断不同任务应重点讨论什么。场景建议不能代替用户决定，完整流程由根目录 `SKILL.md` 路由到九个职责模块。

## 调研与讨论方法

讨论的操作与回答承接统一见[讨论模块](discussion.md)，本文件只提供专业分析方法和场景对照。用户单独询问环境能力时直接回答能力与限制；任务中途插问时回答后按原任务状态续接。没有工具或证据不能声称已完成核查，也不据此自动结束原任务。

方法定义集中在[调查与分析](analysis.md)；下面只展示各类任务的应用侧重点。

### 完整测试用例的计划方法

先核实实际业务入口、规则、状态变化和已有测试；据此确定覆盖范围，分析适用的正常、异常、边界及状态转换场景。计划必须说明如何写成带前置条件、操作、数据和预期结果的用例，并与业务范围对应核对遗漏。平台差异根据实际实现标注，不把共用流程重复写两遍；自动化按已确认需求和实际可操作性确定，不默许真实付费操作。

以上是实施方法，不自动要求额外报告、矩阵或文档；最终交付按用户确认范围组织。最终目标是用例能指导执行并覆盖约定业务，不是“分析完成、文档写完、检查通过”。

## 低风险 Bug 修复

适用情况：问题范围明确、改动可逆、不涉及外部权限或生产操作。

重点讨论：

- 用户可见的错误表现和正确表现。
- 只修当前问题还是覆盖相邻同类问题。
- 哪些现有行为必须保持不变。

计划重点：说明根因方向、核心修复机制和影响边界，不按文件拆成施工清单。

最终验收目标：错误不再出现，相关正常路径保持原行为。

Agent 内部验证：复现问题、运行相关测试、检查回归路径和差异范围。

用户验收：按[用户验收补位](verification.md#用户验收补位)判断；证据覆盖全部已确认结果且用户未要求亲自验收时，无需追加确认。真实界面或设备证据仍不足时不能仅凭代码检查收口。

停止或拆分条件：发现根因涉及独立模块、权限或另一个业务目标时，返回讨论并确认是否拆分。

## 新功能或新模块建设

适用情况：需要新增用户能力、接口、模块或完整产物。

重点讨论：

- 为什么需要该能力，最终使用者是谁。
- 正常路径、失败路径和明确非目标。
- 核心接口、数据、交互和兼容取舍。

计划重点：展示总体实施机制、模块边界、数据或交互流和必要集成点。

最终验收目标：用户能够完成新能力对应的完整结果；失败时有明确行为。

Agent 内部验证：端到端小案例、单元或集成测试、错误路径和兼容检查。

用户验收：按[用户验收补位](verification.md#用户验收补位)判断；重点核对主观体验、真实业务数据或私有环境的证据缺口，不因涉及这些场景就一律追加确认。

停止或拆分条件：一个请求包含多个可独立交付能力，或不同能力需要独立发布和回滚时拆分。

## 跨模块重构

适用情况：目标是改善结构、迁移接口或替换内部机制，同时保持用户行为或明确改变部分行为。

重点讨论：

- 重构的业务原因和必须保持的外部行为。
- 允许改变与禁止改变的接口、数据和兼容边界。
- 迁移顺序、回滚路径和完成分母。

计划重点：说明新旧结构、迁移路径、兼容策略和每个阶段怎样保持系统可用。

最终验收目标：确认范围内完成迁移，外部行为符合约定，没有遗漏旧入口或静默降级。

Agent 内部验证：范围清单、调用链检查、迁移前后行为对比、回滚和集成测试。

用户验收：按[用户验收补位](verification.md#用户验收补位)判断；重点核对真实生产流量、业务报表或外部消费者的结果证据是否充分。

停止或拆分条件：不同模块可独立迁移、需要不同负责人或回滚周期时，按迁移批次拆分。

## 生产配置、外部接口或费用任务

适用情况：涉及生产环境、真实 API、费用、发布、权限或不可逆操作。

重点讨论：

- 明确授权范围、费用上限和可操作环境。
- 成功、失败、降级和回滚路径。
- 凭据来源、敏感信息边界和外部服务限制。

计划重点：说明调用或发布机制、风险控制、停止条件和回滚方式。

最终验收目标：授权范围内的真实结果达成；失败时没有越权、超额费用或不可恢复状态。

Agent 内部验证：尽可能先用只读、模拟、隔离或最小真实调用验证。

用户验收：按[用户验收补位](verification.md#用户验收补位)判断；核对真实账号与生产结果的必要证据，不仅因缺少控制台访问权限就追加确认。

停止或拆分条件：缺少授权、费用确认、凭据或回滚能力时立即停止，不消耗修复次数。

## UI、设备体验或主观质量任务

适用情况：结果依赖视觉效果、触控体验、声音、真实设备表现或人的主观判断。

重点讨论：

- 目标设备、环境和主要用户路径。
- 用户认为通过与不通过的具体表现。
- Agent 可以自动验证的部分和必须人工验收的部分。

计划重点：说明实现方法、目标环境、可自动检查内容和用户验收安排。

最终验收目标：目标环境中的实际体验符合用户确认的表现，没有已知瑕疵。

Agent 内部验证：构建、静态检查、自动化测试、截图或可访问环境中的行为验证。

用户验收：按[用户验收补位](verification.md#用户验收补位)判断；需要时给出具体设备、操作步骤、预期结果、通过条件和反馈要求，反馈前不能标记达标。

停止或拆分条件：不同设备或体验路径具有独立结果和独立修复方式时，可按环境或用户路径拆分并说明原因。

## 多轮正反例

以下均为局部片段，省略处不表示讨论已完成。每个场景比较同一背景下的错误续接与正确续接；示例中的方案不是其他任务的默认要求。

### 环境恢复：方向、事实与派生事项

背景：用户要先恢复 Jenkins 并跑通 iOS；备份还含其他三个任务，尚未决定其启用状态。配置读取已证明 iOS 有定时触发。

助手：旧任务配置可以保留；其他任务是否启用还需单独讨论。先讨论 iOS 的触发方式：仅手动还是保留定时？建议首次验证仅手动，减少验证期间自动触发。
用户：仅手动。
错误续接：已确认只恢复 iOS、删除其他任务并关闭上传，开始恢复。
正确续接：确认 iOS 仅手动触发。接着比较其他任务的保留方式，说明配置保留和运行启用的区别，只问它们是否暂时停用；不把上传和通知塞进同一问题。
用户：其他任务先停用，但配置保留。
错误续接：把停用解释成只关定时、仍可手动运行，并称为内部实现。
正确续接：按任务停用且配置保留承接；只有真实歧义才澄清，不能默改含义。核实备份和目标路径，继续发现本次恢复相关的未决行为。不能把旧流水线具备的上传、通知自动写为用户目标。

### 环境恢复：执行中澄清后继续

背景：用户已确认恢复方案、结果与执行权限，执行时发现两个备份目录，不知道哪份是用户要用的。
助手：这两份备份分别为 A、B，本次使用哪份？
用户：B。
错误续接：了解，使用 B。等你说继续我再恢复。
正确续接：检查 B 符合已定条件后，在原授权范围内继续恢复与验证。若 B 的内容与原目标冲突，则只报告冲突并讨论受影响事项。
用户：刚才说的校验和是什么意思？
正确续接：解释校验和的作用，随后继续原授权工作；若用户说“先停，只解释”，则停止执行并只解释。

### 创作设计：方向认可不等于细节确认

背景：社区海报已知活动事实，尚未确定视觉设计。助手用“邻里公告栏”解释方向，并用米白与棕色举例，说明配色稍后讨论。
用户：这个方向可以。
错误续接：米白底和棕色字已确定，现在制作。
正确续接：只确认公告栏方向。根据群内手机阅读与亲切感比较底色效果，只问底色；文字色等继续待定。
用户：浅绿底。
正确续接：结合浅绿底分析文字可读性，再讨论主文字颜色。不能机械照抄原示意配色，也不能无依据给出精确对比度数值。

### 创作设计：部分回答与小偏好

背景：用户主动补充“副标题想强调邻里关系，但具体话还没想好”，文件名也仍未决定。
错误续接：使用模型建议的副标题，文件名是小事执行时自定。
正确续接：保留“强调邻里关系”的决定，提供有不同表达效果的副标题建议，只讨论措辞。后续仍处理用户需决定的文件命名；用户明确委托命名后才自行决定。
用户：措辞你推荐一下。
正确续接：给出推荐与理由并请用户决定；推荐请求本身不是委托定案。
用户：措辞由你定，文件名也由你定。
正确续接：在这两项委托范围内决定，不再拆开询问；其他未决设计继续讨论。

### 测试方案：当前不运行与覆盖范围

背景：用户要求完整人工用例及适合的 Android 自动化，本轮只讨论，不运行支付或音乐生成。
错误续接：你已确认音乐一律模拟，因此删去真实支付链路用例。
正确续接：保持测试覆盖需求，单独比较未来执行环境或方式；当前不执行任何收费动作。若用户尚未选择模拟，不把模拟放进所有选项作为固定前提。
用户：音乐自动化先用测试环境模拟。
正确续接：仅记录音乐自动化方法，不据此删去人工测试中的真实业务覆盖，也不扩大为支付一律模拟。

### 测试方案：一问与附加事实

背景：已知可以提供测试账号，但登录方式和数据切换方法未知。
错误提问：用哪类账号？顺便提供登录方法、余额和数据复位方式。
正确提问：根据待测规则只讨论账号类型；其余事实若不能自行查明，之后分别询问。
用户：积分充足和不足各一个。
正确续接：记录账号类型；下一轮只问当前必要且无法自行查明的登录方式，不再次打包询问数据切换与复位。

### 测试方案：未知不等于取消

助手：测试环境模拟音乐任务是否仍扣真实积分？
用户：我不知道。
错误续接：按会真实扣费处理，所以取消这些自动化测试，开始写剩下的方案。
正确续接：把扣费方式保留为未知、暂停相关收费动作；先查可访问的配置资料。没有资料时，只讨论获取证据的一个可行办法，或提出明确保留缺口的草案选择，不自动删除覆盖。
用户：先看未完稿。
正确续接：实际交付草案并标出该未知条件的影响，不声称完整，不执行；如果用户只回答另一个问题，未知条件也仍保留。

### 收口与授权：继续下一阶段

背景：所有相关用户取舍已处理，覆盖核对通过。
助手：汇总实际方案，提供继续讨论或生成计划。
用户：生成计划。
错误续接：好的，已确认，下一步生成计划。
正确续接：本轮实际生成含实施方案的计划，按主控处理目标展示与执行确认；不直接实施。
用户：我只确认计划。
正确续接：单独展示验收目标草案并请求内容确认；确认前不附执行选择，不再问是否生成目标。
用户：按展示的计划和目标执行，不开启子代理。
正确续接：实际执行并验证，不再索取同一授权。

### 决定来源：选择、理由与局部委托

助手：在 1:1 与 4:5 中推荐 4:5，并给出显示效果判断。
用户：4:5。
错误记录：用户同时确认另外比例显示效果差。
正确记录：用户决定仅为 4:5；推荐理由仍是模型分析，未经验证不能写为用户确认事实。

助手：测试优先级用什么分级？
用户：P0–P2，具体归类由你判断。
错误续接：因此确定 P2 抽样执行。
正确续接：决定分级及委托分类；全跑还是抽样是不同的执行策略，仍待讨论，不随分类委托生效。

### 内容选择与布局：先拆决定，再承接委托

助手反例：A 全部规则保留、五条平列；B 全部保留、分两组、次要内容小字。
问题：用户可接受内容全保留但拒绝分组或小字，不能用一个选项同时确认。
助手正例：本轮只定五条规则是否全部上图，布局与字号另议。
用户：全保留。
正确续接：记录内容范围，比较分组方式并只问分组，不把字号也确定。
用户：分组、字体和留白都由你决定。
正确续接：在已定内容范围内设计排版并说明选择，不继续问每个字号；制作权限仍按主控核对。

### 专业判断：限定证据，再检查其他路径

用户：新机定时关了，旧机回来也不会冲突了吧？
错误：不会，两边不会自动同时运行。
正确：已知只排除了新机的这条定时路径，新机手动与旧机定时仍可能重叠。先查现有任务配置；无法查且会影响恢复方案时，只问旧机是否还可能上线。
用户：旧机已永久报废。
正确续接：保留该事实来源，再评估当前仍相关的触发路径，不继续纠缠已排除的旧机假设。

### 项目规则与当前做法：都读取，不混为一谈

材料：已有测试文件是五列表格；项目规则明确公共接口须兼容。
用户：新用例格式你设计。
错误：项目要求固定五列，不能加平台列；接口兼容所以内部实现也不能改。
正确：五列是当前做法，格式已获委托，可选择是否增列；公共接口兼容是真实约束，沿用但不扩大到内部实现。将两类内容按来源和性质分别记录。

### 方案选择与执行许可：同一方向不代表同一阶段

用户：本轮只讨论，不运行；自动化选择 Android。
错误：已确定本轮只跑 Android，开始连接设备。
正确：最终自动化范围为 Android，当前仍在讨论，允许调查和已授权记录；不运行。
用户：方案和目标我确认，按这个执行，不启用子代理。
正确续接：复用已定范围及执行许可，进入执行；后续必要事实澄清后继续，不重问是否执行。

### 局部与整体委托：该自主时自主

用户：优先级分类你定。
错误：已采用三级，最低级抽样运行。
正确：决定分类标准及归类，执行覆盖仍按既有决定；若未定且影响方案，另问，不把分类授权扩大。
用户：整个测试方案的专业取舍都交给你，覆盖范围按已定的全量，不要运行。
正确续接：自行决定组织、分类和范围内的方案细节，保留全量覆盖、不运行；不继续逐项追问已委托内容。相关决定充分且已请求计划时实际交付计划，环境地址等不影响当前方案的未知随核实步骤进入计划。

### 恢复与交付：继承决定，核实操作

记录：用户已指定 release-B.md，修改已验证，正文尚未交付。
错误：activity.md 名称更贴切，再问用户是否改错文件；或重做 release-B.md 后再报告。
正确：读 release-B.md 核对实际结果，无新冲突就补交付，不重新质疑指定对象。若只支持最终正文交付，先交付、保留状态待同步，不预先标 completed。

记录：检查任务 job-17 已启动，终端返回丢失，还有独立的文档核对未完成。
错误：直接启动 job-18，或把所有工作停住等待用户。
正确：查询 job-17；运行中则观察原任务，已完成则验证结果，明确部分失败则仅安全补做失败部分，未知且有重复影响时暂停依赖部分；独立且已授权的文档核对继续。记录保留实际标识、阶段结果和次数。

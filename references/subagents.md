# 子代理管理

输入包括当前任务、可用材料、依赖、用户的子代理设置、权限及宿主实际能力。评估分工时必须读取本模块，并输出执行方式及依据、子任务与代理的对应关系、实际结果和整合缺口。普通任务不分派时无需加载。阶段与授权由主控决定。禁止从本模块新设用户阶段或自动启用代理。

## 选择执行方式

必须先分析当前工作、执行依赖及改动影响范围，再比较分派收益与启动、上下文交接、等待和整合成本。禁止仅凭任务大、文件多、工具支持代理、存在空闲容量或任务可安全独立执行而决定分派。禁止编造精确的提速或费用收益。

| 当前条件 | 执行方式 |
|---|---|
| 独立查询或读取，用工具即可完成 | 必须由主线程并行调用工具。禁止仅因需要几次调用而启动代理 |
| 小修改、需要频繁交互或大量共享上下文，交接成本高于收益 | 必须由主线程直接完成 |
| 自包含的资料、日志分析或实现，能交回简明结果，隔离上下文或专门分工有收益 | 必须按授权、宿主能力和交接成本判断是否委派一个代理，并记录决定及依据。禁止把多个代理同时运行设为使用单个代理的前提 |
| 多个当前已就绪的独立任务，预计收益值得分派 | 决定并发后，必须先满足下述安全条件。禁止仅因满足安全条件而强制分派 |
| 前置结果尚未产生、公共约定未定或影响范围不明 | 必须先完成前置工作或调查，禁止提前并发受影响任务。条件明确后必须重新判断 |

调查阶段，用户明确允许调查子代理，或明确委托模型决定调查代理，且宿主允许时，主模型可按收益分派只读调查。缺少对应允许或委托时，必须由主模型自行调查，禁止为此额外询问。调查交接与摘要必须按[分析模块](analysis.md#按任务类型调研)处理，执行方式和依据必须写入现有计划。执行与审查代理仍必须按执行确认取得对应设置。禁止借分派增加最终验收目标或创建额外宿主验收任务。

分派前必须核对主控当前生效的设置，遵守用户对启用和用途的限制及宿主限制。执行或审查代理必须取得对应授权，禁止把其中一种授权扩大到另一种。用户明确说“子代理你决定”或“执行设置由你判断”时，视为对子代理设置的明确委托。模型必须按当前收益、依赖、资源成本及宿主能力决定是否启用、启用范围和是否追加审查，禁止重复询问。用户开启包含审查的子代理设置后，执行分派仍按收益选择，独立复核必须按[审查模块](review.md#独立复核要求)追加，禁止因未委派实现而省略。

## 并发准入与依赖

同时执行的子任务必须满足全部条件。目标、输入、交付物、修改范围和完成标准必须明确。每项必须能独立开始，禁止依赖尚无结果的前置任务。禁止改变其他运行任务依赖的接口、数据结构、配置或业务行为，禁止同时修改同一内容或争用会相互干扰的运行资源。分派和并发必须符合对应阶段的用户设置及宿主限制。禁止用修改不同文件代替这些判断。

必须按当前就绪任务判断能否并发，禁止给整个任务永久贴串行或并发标签。例如先由主线程确定公共接口并核对实际结果，再对依赖该接口且彼此独立的分支判断并发。公共约定稳定后，禁止各代理自行改动。A → B → C 的依赖链必须按顺序执行，禁止假定前序结果。是否串行委派仍必须按收益判断。与依赖链无关的就绪任务必须继续。

分派实现前，主线程必须取得[执行入口](execution.md#执行入口)的有效凭据，禁止借分派绕过宿主目标与执行中状态要求。调查、讨论记录等原有例外继续适用。

## 分派与交接

必须由主线程统一分派，禁止另建管理代理。独立复核交接必须沿用[审查模块](review.md#独立复核要求)的四字段要求。执行代理的每项交接必须包含子任务目标及其服务的当前有效目标（旧目标必须标为 `superseded`）、必要输入和当前产物版本、可修改边界与权限限制、交付物及完成标准、需交回的证据与阻塞事项。必须提供必要事实和可访问材料，禁止假定子代理已继承完整对话，或把提供链接当作已读取。

必须在上下文或已启用的唯一任务记录中维护“子任务、代理/运行标识、当前状态、结果与证据、下一动作”的对应关系，禁止为分派另建文件或目标。代理必须仅处理获派任务，遇到范围外决定或依赖变化时必须交回主线程。禁止自行扩大任务或再派下级代理。

执行代理必须交回实际改动、验证操作及原始证据位置、未完成部分和阻塞原因，禁止因简明汇报省略核实所需证据。记录运行中前必须有成功启动的回执，记录完成前必须核对实际结果。失败或结果未知必须分别保留，禁止用过程消息代替最终结果。

## 运行调度与异常接管

- 必须按宿主实际支持的并发方式、可用容量及用户资源限制调度，禁止猜测固定槽位或默认用满。工具不支持并发时，必须按可用方式串行。宿主不支持、启动失败或代理无法完成时，必须先按本节接管规则核实原代理及现场。确认不可用且接手不会重复操作或产生并发写入后，主模型必须接回尚未完成的执行、验证和审查，禁止再次询问是否开启。原代理仍运行或状态未知时，禁止接手同一工作。独立复核必须按[审查模块](review.md#独立复核要求)安全降级并说明，禁止冒称已独立复核。
- 主线程必须保留协调、整合及其他未分派工作，禁止重复代理正在做的任务。取得每项结果后必须核对并更新依赖。有收益、容量和已就绪任务时可补充分派。收取结果无需等全部结束，启动时无需一次分派全部任务。
- 没有可继续的独立工作时，必须等待实际工具结果。有宿主完成通知或等待能力时必须优先使用。需要查询时必须有间隔地观察，禁止忙轮询。异步与串行能力必须以实际工具为准，禁止虚构后台运行或把等待工具说成等待用户。
- 发现依赖、交叉修改或共享资源干扰时，必须停止受影响的分派，协调运行中的相关代理并保留已有结果。无关任务必须继续。接管同一内容前必须核实原执行者已结束写入，禁止用停止请求证明已停止。
- 部分失败、断连或结果未知时，必须先按[记录恢复](state-recovery.md#中断恢复)查询原代理或操作，并核对实际产物。禁止重复分派仍在执行或已成功的工作。主线程接回或重新分派前，必须核实相关部分尚未完成且可安全接管。无法核实时，必须保留未知并交主控处理缺口。
- 用户暂停、改变范围或撤销权限时，主控必须确定受影响工作、协调相关代理停止、核查已有影响并更新记录。禁止让代理沿用失效指令继续。

## 只读检查代理

进度锚点使用只读检查代理，必须将被取代的旧目标标为 `superseded`。执行代理产出结果，独立复核代理判断最终产物是否达标，只读检查代理仅在长任务途中核对路线是否指向当前有效目标。三类代理必须按各自的收益和授权条件使用，禁止互相替代。

- 必须有对应授权。派发依据必须是用户在执行前明确选择开启对应子代理，或用户明确委托模型决定执行设置且模型据此选择开启。未开启或缺少有效选择及委托时，禁止派发，必须按[记录与恢复](state-recovery.md#进度锚点)记为未执行。禁止静默省略或冒称已检查。用户要求增加检查次数时，授权仍按[频次规则](state-recovery.md#进度锚点)核对，禁止把增加次数当成授权。
- 交接必须按[进度锚点交接模板](templates.md#进度锚点交接模板)提供四类锚，禁止附完整历史。代理必须仅使用只读工具和交接材料，禁止写业务文件或执行有副作用的命令。
- 触发条件、频次上限、输出字段和记录方式必须遵守[进度锚点规则](state-recovery.md#进度锚点)。必须按宿主实际能力派发、等待和收取结果，禁止另定检查标准。
- 结果必须交主控作为判断输入。自动变更及计数的限制必须遵守[进度锚点规则](state-recovery.md#进度锚点)。禁止用进度锚点替代执行分派。
- 独立上下文隔离本次推理与工具历史，与主控使用同一模型时仍可能有共同偏差。禁止表述为完全外部监督。

## 提问语义复核代理

用户已选择允许复核用途的子代理，或明确委托模型决定子代理设置且模型按当前收益选择开启时，可使用提问语义复核代理。没有对应设置时禁止使用。代理必须仅读取当前对话或摘要、待决项、已确认决定、用户约束、必要事实依据及最终回复草稿，必须交回 `semantic_review` 的 `reviewer: independent`、`review_id`、`authorization_source`、检查项、依据和结论。禁止写业务文件、执行有副作用的命令或改变阶段及授权。

主控必须交付复核目标，代理必须按[讨论模块](discussion.md#提问语义复核)逐项判断。主控必须先检查状态和动作，再采纳代理结果。代理不可用或未获授权时，必须由主控按同一规则自检，填写 `reviewer: main` 并保留自检限制。禁止冒称独立复核。

## 整合与审查交接

收取结果后，必须核对实际差异、修改边界、产物版本及证据，禁止只采信“完成”自述。必须整合所有必要结果，补做受影响的整体[验证](verification.md)，再交[审查](review.md)。禁止用子任务完成判定整项目标达成。

独立复核的触发条件、材料、上下文、输出、修复责任和次数必须遵守[审查模块](review.md#独立复核要求)。必须按其要求派发、等待及收取结果。禁止让参与实现的代理独立复核自身产物。完成判定必须由主控负责。

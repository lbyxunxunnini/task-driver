# 子代理管理

输入：有效计划、依赖、用户的子代理设置、权限和宿主实际能力。输出：执行方式及依据、子任务与代理对应关系、实际结果和整合缺口。评估分工时读取本模块；不分派的普通任务无需加载。主控仍决定阶段与授权，本模块不创建新用户阶段，也不自动启用代理。

## 选择执行方式

先分析当前工作、执行依赖和改动影响范围，再比较分派收益与启动、上下文交接、等待和整合成本。任务大、文件多、工具支持代理或存在空闲容量，均不能单独作为分派依据；安全独立只是准入条件，不代表值得并发。不编造精确提速或费用收益。

| 当前条件 | 执行方式 |
|---|---|
| 独立查询或读取，用工具即可完成 | 主线程并行调用工具，不为几次调用启动代理 |
| 小修改、需要频繁交互或大量共享上下文，交接成本高于收益 | 主线程直接完成 |
| 自包含的资料、日志分析或实现，能交回简明结果，隔离上下文或专门分工有收益 | 可委派一个代理，不以多个同时运行作为使用代理的前提 |
| 多个当前已就绪的独立任务，预计收益值得分派 | 满足下述安全条件后并发，不以安全条件满足强制分派 |
| 前置结果尚未产生、公共约定未定或影响范围不明 | 先完成前置或调查，暂不并发受影响任务；条件明确后重新判断 |

执行方式和依据写入现有计划的实施方案；拟委派时说明各子任务目标与边界，随原有执行确认取得对应授权，不增加表单或确认轮次。任务分派不增加最终验收目标，也不得作为额外的宿主验收任务创建。

分派前核对主控当前生效的设置：用户关闭子代理或没有对应授权时，不得启动执行或审查代理；只授权审查时不扩大为执行分派。开启子代理允许按收益选择执行分派，独立复核仍按[审查模块](review.md#独立复核要求)追加，不能因未委派实现而省略。

## 并发准入与依赖

同时执行的子任务必须全部满足：目标、输入、交付物、修改范围和完成标准明确；能够独立开始，不依赖尚未产出的前置结果；不改变其他运行任务依赖的接口、数据结构、配置或业务行为；不同时修改同一内容，不争用会相互干扰的运行资源；对应分派及并发已获授权。修改不同文件不能代替这些判断。

按当前就绪任务判断，不给整个任务永久贴串行或并发标签。例如先由主线程确定公共接口并核对实际结果，再对依赖该接口且彼此独立的分支判断并发；公共约定稳定后不得由各代理自行改动。A → B → C 的依赖链依次执行，不假定前序结果；是否串行委派仍按收益判断。无关的就绪任务不因这条依赖链停住。

分派实现前，主线程仍须取得[执行入口](execution.md#执行入口)的有效凭据；分派不能绕过宿主目标与执行中状态要求。调查、讨论记录等原有例外不因此改变。

## 分派与交接

主线程统一分派，不另建管理代理。以下交接要求用于执行代理；独立复核交接沿用[审查模块](review.md#独立复核要求)的四字段要求。执行代理每项交接包含：子任务目标及其服务的原目标、必要输入和当前产物版本、可修改边界与权限限制、交付物及完成标准、需要交回的证据与阻塞事项。提供必要事实和可访问材料，不默认子代理已继承完整对话；不把读取链接当作已读取。

在上下文或已启用的唯一任务记录中维护“子任务、代理/运行标识、当前状态、结果与证据、下一动作”的对应关系；不为分派另建文件或目标。代理只处理获派任务，遇到范围外决定或依赖变化交回主线程，不自行扩张任务或再派下级代理。

执行代理交回实际改动、验证操作及原始证据位置、未完成部分和阻塞原因；简明汇报不等于省略核实所需证据。只有成功启动的回执才记为运行中，只有核对实际结果才记为完成；失败或结果未知分别保留，不把过程消息当最终结果。

## 运行调度与异常接管

- 按宿主实际支持的并发方式、可用容量及用户资源限制安排工作，不猜固定槽位或默认用满。工具不支持并发时按可用方式串行；已开启的独立复核不可用仍交审查模块异常分流，不静默省略。
- 主线程保留协调、整合及其他未分派工作，不重复代理正在做的任务。取得一项结果就核对并更新依赖；有收益、容量和已就绪任务时再补充分派，不必等全部结束才收取或一开始把全部任务启动。
- 没有可继续的独立工作时等待实际工具结果；优先用宿主完成通知或等待能力，需要查询时有间隔观察，不忙轮询。异步与串行能力以实际工具为准，不虚构后台运行。等待工具不冒称等待用户。
- 发现依赖、交叉修改或共享资源干扰时，停止受影响分派并协调正在运行的相关代理，保留已有结果；无关任务继续。停止请求不是已停止的证据，核实原执行者已结束写入后才能接管同一内容。
- 部分失败、断连或结果未知时，先按[记录恢复](state-recovery.md#中断恢复)查询原代理/操作并核对实际产物。不重复派发仍在执行或已成功的工作；只有已核实可安全接管的未完成部分才由主线程接回或重新分派。无法核实时保留未知并交主控处理缺口。
- 用户暂停、改变范围或撤销权限时，由主控确定受影响工作，再协调相关代理停止、核查已有影响并更新记录；不让代理沿用失效指令继续。

## 整合与审查交接

收取结果后检查实际差异、修改边界、产物版本与证据，不仅采信“完成”自述。整合所有必要结果，补做受影响的整体[验证](verification.md)，再交[审查](review.md)；子任务完成不等于整项目标达成。

独立复核的触发条件、材料、独立上下文、输出、修复责任和次数均由审查模块唯一维护；本模块只负责按其要求派发、等待及收取结果。参与实现的代理不作为该产物的独立复核者；按审查要求另起独立上下文，不夹带执行者自评或前次审查结论。共同完成判定仍由主控负责。

# 明确要求讨论

## 用户输入

```text
/task-driver 先逐项讨论产物结构、素材来源和合成方法，不要生成计划。
```

## 必须表现

- 用户明确要求逐项讨论时按用户列举的顺序推进，仅当前项确实依赖另一项时说明前提并优先处理，每轮讨论当前事项；保留其他必要待决事项，不因模板空白制造问题。
- 区分已知事实、待确认建议和已确认决定。
- 先复述目标并等待理解获认可，再完成必要调查和分析；确需用户决定时只提出当前一个问题，包含影响、推荐和理由，并保留自由讨论。

## 禁止表现

- 输出完整计划。
- 提前输出验收目标。
- 把三个讨论事项直接转换成实施任务。
- 未调查就按需求关键词问问题，或把用户已经明确的要求重新作为选项。

- 用户列出布局、缺少控件、键盘遮挡并要求逐项讨论：理解确认后的首轮方案讨论只能问会改变当前布局方案或验收的取舍。可先记录其他事项，禁止抢问控件显示时机。若用户补充一条短句属于网络插话，则恢复当前布局事项，不启动设备连接调查。
- 对照：用户要求先决定默认登录入口，目标人群是否有企业账号会直接影响入口选择。阐明两者关系后，可询问该必要前提；下一项的按钮文案不影响当前选择，先保留。
- 用户说「几个页面都应该有清空按钮」，然后列出视觉边距、部分页面缺按钮和键盘遮挡，并要求按列举顺序讨论。已有按钮覆盖是用户给定目标，不能新增「统一清空按钮的显示规则」作为第一项；首轮方案讨论针对现有按钮的视觉边距，只讨论直接影响边距的取舍。

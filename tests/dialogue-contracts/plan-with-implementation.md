# 计划包含实施方案

## 前提

用户已经确认两个独立问题及各自相关用户取舍，并通过覆盖与决定核对，并选择生成计划。

## 必须表现

- 顶层展示两个对应计划事项。
- 每项至少包含“已确认”和“实施方案”。
- 简单任务默认只展示这两个必要板块；复杂任务按需补充预期变化、涉及位置和内部验证，不因模板可选字段为空而追问或增加确认。
- 实施方案说明核心机制、作用边界和关键约束。
- 文件、测试和版本工作归入对应事项或非编号的统一实施工作。

## 禁止表现

- 用任务名称列表或文件列表代替实施方案。
- 把两个问题重新拆成一排施工步骤。
- 写入未经确认或委托的用户决定。

## 执行并发判断与分派

计划需要分派时，说明选择主线程、串行委派或并发的依据，以及各子任务目标、修改边界和前置依赖；不按文件数决定执行方式。具体调度场景见[子代理调度契约](subagent-scheduling.md)，不改变上面的计划结构或原有验收与审查流程。

禁止借本项修改讨论规则、确认选项、目标粒度、独立审查要求或版本信息；不得新增表单或确认轮次。

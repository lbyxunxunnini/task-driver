# 计划包含实施方案

## 前提

用户已经确认两个独立问题及各自关键取舍，并选择生成计划。

## 必须表现

- 顶层展示两个对应计划事项。
- 每项至少包含“已确认”和“实施方案”。
- 简单任务默认只展示这两个必要板块；复杂任务按需补充预期变化、涉及位置和内部验证，不因模板可选字段为空而追问或增加确认。
- 实施方案说明核心机制、作用边界和关键约束。
- 文件、测试和版本工作归入对应事项或非编号的统一实施工作。

## 禁止表现

- 用任务名称列表或文件列表代替实施方案。
- 把两个问题重新拆成一排施工步骤。
- 写入未经讨论的关键技术决定。

## 执行并发判断与分派

以下场景只验证执行方式，不改变上面的计划结构或原有验收与审查流程。

| 场景 | 必须表现 |
| --- | --- |
| 两项改动的目标、输入、交付物、修改范围和完成标准已明确，互不依赖、不修改共享约定或同一内容、不争用运行资源，且已获执行并发授权 | 必须拆分并发；计划说明依据及各子任务目标和修改边界，主线程分派并整合实际结果 |
| 修改不同文件，但两项共同改变另一方依赖的接口、数据结构、配置或业务行为 | 不得仅凭文件不同判定独立，必须由主线程串行执行 |
| A 完成才能开展 B，B 完成才能开展 C | 由主线程依次执行；不得假定前序结果后分派并发 |
| 无法确认相互独立，或用户明确关闭子代理、未授权执行并发 | 必须由主线程串行执行，不得启动执行子代理；不将允许独立审查解释为允许并发实现 |
| 并发执行中发现依赖、交叉修改或共享资源干扰 | 停止受影响的并发工作、保留已有结果，由主线程接回处理 |
| 子代理已完成，但整合或整体最终验收尚未完成 | 不标记整体完成；子任务只用于内部分派，不增加最终验收目标或额外宿主验收任务 |

禁止借本项修改讨论规则、确认选项、目标粒度、独立审查要求或版本信息；不得新增表单或确认轮次。

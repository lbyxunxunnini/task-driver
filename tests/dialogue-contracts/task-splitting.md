# 任务规模与拆分

## 场景

用户要求同时修复本地展示错误、发布生产环境，并新建一个可以独立交付的报表模块。

## 预期行为

1. 模型不按文件数或计划项数判断任务规模。
2. 模型指出三个部分的业务目标、权限、交付和回滚关系不同，建议拆分。
3. 模型说明拆分依据、建议的第一批范围和延期事项。
4. 模型只请用户确认本轮范围，不静默拆分，也不直接开始任一部分。

## 失败表现

- 把三个独立目标强塞进一次执行。
- 仅因为“文件很多”建议拆分。
- 未经用户确认就自行选择第一批范围。

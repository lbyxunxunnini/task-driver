# 用户可见回复边界

## 场景

用户在 Codex 中触发任务驱动，模型提出一个当前讨论事项。用户回复“是的”确认该事项。

## 必须表现

- 必要调查分析后发出最终文本或原生提问，再等待用户实际决定；原生提问属于用户可见回复，不重复用文本再问一遍。
- 回复只处理当前确认和下一个尚未闭合的决策点，不预演计划、验收目标或目标执行。
- 发出回复后立即结束本轮；下一步只能在用户再次回复后继续。
- 如果当前上下文已经包含所需事实，不为确认消息调用无关工具。

## 禁止表现

- 只在 reasoning、工具调用说明、工具参数或内部状态中形成本应展示给用户的内容。
- 用户已经确认当前事项后，重新完整分析同一事项或为了满足格式制造新选项。
- 未获相应授权就生成下一阶段完整草案、创建目标或运行审查 loop；关闭、预选或无回答即推定授权。

## 验收边界

契约文件和静态检查只能确认 Skill 包含上述回复约束，不能证明 Codex UI 的实际显示行为。最终行为必须在新建 Codex 任务中人工验证。

# 用户可见回复边界

## 场景

用户在 Codex 中触发任务驱动，模型提出一个当前讨论事项。用户回复“是的”确认该事项。

## 必须表现

- 发现、判断、具体建议、示例和汇总必须在正常对话正文交付，不能只存在于 reasoning、折叠过程消息、工具参数或选择器；原生选择器不能替代正文。
- 回复只处理当前确认和下一个尚未闭合的决策点，不预演计划、验收目标或目标执行。
- 未收到实际回答时，补齐正文后立即结束本轮；同步工具返回真实回答才可按回答推进，异步仅返回调用成功不能冒充回答。不得重复文字提问。
- 如果当前上下文已经包含所需事实，不为确认消息调用无关工具。

## 选择器与正文

- “你想写家里的谁或哪件事”“为什么推荐这个画面”是开放提问或解释，直接在正文交流，不调用选择器。
- 比较两个实际副歌方向时，正文必须展示具体片段、可唱性差异和依据；可用、允许调用且满足正文交付要求的选择器承载真正选择及其影响、推荐与理由。
- 同步工具等待前须已在正常正文展示决策内容；异步工具返回后或无提问工具时，必须在最终答复完整交付本轮内容。已知选择器交互把汇总、计划或验收目标仅留在折叠过程区时，未收到实际回答时改用最终答复中的完整内容和编号选项等待回答，已收到时补齐正文并按原回答范围承接；保留原选项及授权范围，不增加确认轮次，不将已确认事项退回待定。支持正常正文展示的原生选择器仍须使用。
- 进入计划的选择前，用户必须已在正常正文收到方案及依据汇总；不得将正文折叠是否可见推定为已验证。

## 禁止表现

- 只在 reasoning、工具调用说明、工具参数或内部状态中形成本应展示给用户的内容。
- 用户已经确认当前事项后，换措辞重问同一决定或为了满足格式制造新选项；已确认方案的专业深化与关联分析仍须正常进行。
- 未获相应授权就生成下一阶段完整草案、创建目标或运行审查 loop；关闭、预选或无回答即推定授权。

## 验收边界

契约和静态检查不能证明宿主 UI 的实际显示行为。Claude Code 回放须分别核对最终正文、工具消息与内部思考；真实选择器交互另行核验。ChatGPT/Codex 是否折叠内容必须在对应界面验证，不能用 CLI 输出或模拟工具冒充。

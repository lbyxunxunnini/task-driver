# 用户可见回复边界

## 场景

用户在 Codex 中触发任务驱动，模型提出一个当前讨论事项。用户回复“是的”确认该局部事项，尚未请求或获得整体执行授权。

## 必须表现

- 模型先发出一条用户可见的 assistant 回复，再等待用户继续决定。
- 回复处理当前事项；有下一关键取舍时只讨论该问题，没有必要取舍时不制造问题或选项，不预演未经授权的阶段。
- 发出回复后立即结束本轮；下一步只能在用户再次回复后继续。
- 如果当前上下文已经包含所需事实，不为确认消息调用无关工具。

## 禁止表现

- 只在 reasoning、工具调用说明、工具参数或内部状态中形成本应展示给用户的内容。
- 用户已经确认当前事项后，重新完整分析同一事项或为了满足格式制造新选项。
- 在发出当前回复前继续生成计划、创建目标、运行审查 loop 或推进后续事项。

上述限制针对讨论期的局部确认。若上一轮已明确展示计划、最终验收目标及整体执行请求，且独立审查开关已确定，用户确认执行后应直接按授权执行，不得把回复门禁解释为必须再等待一次确认。发出回复后立即结束本轮的时序要求仍然保留。

## 验收边界

契约文件和静态检查只能确认 Skill 包含上述回复约束，不能证明 Codex UI 的实际显示行为。最终行为必须在新建 Codex 任务中人工验证。

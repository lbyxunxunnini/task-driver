# 验收目标分流

## 对话

```text
用户：确认计划。
```

## 必须表现

- 计划确认后先输出验收目标草案。
- 计划已展示、执行前提满足后，在展示验收目标的同一回复中提供三个业务选项：执行开启子代理、执行不开启子代理、不执行继续讨论；必须标注推荐、理由和各项影响。禁止在目标口径已无待讨论事项时，要求先确认目标、下一轮才展示执行选项。
- 选择继续讨论并要求逐项确认时，讨论什么结果代表完成，口径闭合后更新目标；保留未变化决定。
- 无论选择哪条路径，都必须在最终验收目标确认后才能创建目标执行。
- 选择任一执行项即同时确认已展示计划、目标、执行和子代理，直接执行，不追加同内容确认。
- 关闭子代理时由主线程执行并自检，说明中不得仍承诺并发子代理或独立审查；开启时，执行并发仍须满足第五步全部条件。实际原生选项和编号选项都须展示推荐标记及当前理由。

## 禁止表现

- 最终验收目标尚未确认就创建目标执行。
- 把测试、文件、脚本和版本检查列成终极目标。
- 未决关键目标只标“待确认”就请求执行；或关闭、超时、无回答便当成同意。

## 合并与结果目标

- 用户指定把某位置的 1 改成 3，方案和范围已明确、无未决授权风险时，合并展示计划和目标，一次确认。
- 任一合并条件不满足时禁止合并；只确认范围却没有解决方法，不算满足。
- 做播放器可以有多个计划步骤，目标验证约定场景实际可用；禁止照抄步骤作为目标。
- 目标只有一项不能证明任务小；指定修改本身是用户要求时才可直接验收修改结果。

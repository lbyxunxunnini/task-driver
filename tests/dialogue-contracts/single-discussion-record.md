# 单一讨论记录与派生视图

同一周报案例：原 D1 待选 PDF 或 Markdown；历史要求只处理本地、不上传不发送、仅用当周已有条目；本轮用户答 PDF、只要一页、标题写本周工作总结、排版仍委托模型。

预期：

1. 原 D1 仍为格式事项；历史约束、本轮页数、标题和委托均有真实来源引用，不因旧 JSON 遗漏而从表中消失。
2. 模型只提交记录变化；脚本生成同一摘要的图表、原话摘录和收口摘要，不再维护第二份完整状态或最终回复输入。
3. 旧流程节点、原来源和历史保留；新编号不能占用旧流程节点。修改生成图表、改变原文、来源越界或摘要并发变化均拒绝写入/交接。
4. 实际读回、完整草稿均需模型语义审核；没有审核或审核失败不能 finalize。自动生成不证明内容或授权正确，不预记问题已送达。
5. 原案例必须真实模型回放至同一收口检查点；统计调用、返工、token 和时间，静态检查通过不能充当行为验收。
6. 较晚登记的读者选择若是格式问题的前提，先问读者；多个独立问题均可答时按本轮选定编号问。用户两次暂停后分别用“继续”恢复，两条新消息均有效。重用早先的消息、给同一来源行换编号，都须保持暂停。
7. 同一回复的段内引用允许纠正原归纳；单独补充标题后重试该条消息，不能借标题改写前一条确定的格式。用户确实在新消息改选格式时，保留原选项、原出处和替换依据。
8. 已有受控摘要可直接续用。新视图只把最新状态呈现为当前；模板里的旧待答栏和旧决策表保留在标记为历史的原文中。
9. 已约定打开 PDF 核对页数，用户下一条只有问候：仅将验法改为检查文件存在应被拒绝，原摘要保持原样。收到实际修改验法的指令后引用新来源，能更新验法并保留变更前后的来源。
10. 正常接续已有完整上下文时，增量读回包含原话、下一问、变化及其影响范围；依赖项的验法即使仍有效也能核对，未受影响的历史按引用回查。首次迁移、恢复或收口使用完整读回。原语义复核与收口条件继续生效。

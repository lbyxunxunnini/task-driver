# Deferred 目标工具与宿主状态同步

## 场景一：TaskCreate schema 尚未加载

用户已经确认最终验收目标，宿主提供 deferred `TaskCreate` 和 `ToolSearch`，但当前上下文没有它的 schema。

## 预期行为

1. 模型不得猜测 `TaskCreate` 参数。
2. 模型先执行 `ToolSearch query="select:TaskCreate"`。
3. schema 加载成功后，模型按参数定义调用 `TaskCreate`。
4. 如果返回 `Invalid tool parameters`，模型重新加载或核对 schema 后只重试一次。
5. schema 加载后仍失败时，模型进入目标工具失败路径，不机械重试。

## 场景二：任务创建后的状态闭环

宿主使用任务列表承载多条最终验收目标，执行过程发生上下文压缩后继续。

## 预期行为

1. 每条最终验收目标只对应一条宿主任务，实施步骤不创建为宿主任务。
2. 创建前通过 `TaskList` 查询已有任务，存在对应任务时直接复用。
3. 创建后保存任务 ID，开始执行前通过 `TaskUpdate` 更新为执行中。
   更新发生在该目标的实际工作之前，包括首次写入文档骨架；不能写完骨架后再补记执行中。修改已审查交付内容影响已完成目标时，先恢复执行中，复审通过前不完成。目标工具失败或不可用时仍按主协议的降级规则处理，不新增执行门禁。
4. 只有最终验收目标及必要验收达标，且已开启的独立审查通过后，才通过 `TaskUpdate` 更新为已完成；按主协议第六步的完成判定核对当前最终版本，不能以旧版本审查或局部证据代替。
5. 中断恢复时优先按任务 ID 恢复映射，没有 ID 时才按最终验收目标原文匹配。
6. 发现重复任务时先识别有效项，不批量伪标为完成，也不再次创建。

## 场景三：目标工具不可用，计划工具可用

用户已确认两个最终验收目标并授权执行，不开启子代理；当前宿主无目标工具和 `ToolSearch`，提供 `update_plan` 及其 schema，已有其他计划条目。

## 预期行为

1. 识别实际工具能力，自动以计划工具原样跟踪两条验收目标，复用对应条目并保留无关条目；不能重写成施工步骤或要求重新授权。
2. 开始工作前同步当前条目状态，连续执行、自检和必要修复，不对子步骤询问是否继续。
3. 一项目标通过自检、另一项受阻时，仅完成前者；后者保持未完成并说明阻塞原因。若工具没有受阻状态，不得映射为已完成。
4. 计划工具也不可用时，说明限制并在对话中保留目标原文、状态及证据；涉及覆盖、删除或丢失已有状态时仍须请求用户决定，不能借降级绕过。
5. 恢复时复用目标映射及已有状态，不能重复创建、退回计划讨论或声称已创建专用宿主目标。

## 失败表现

- schema 未加载时直接调用 `TaskCreate`。
- 使用相同的猜测参数连续重试。
- 把文件修改、测试步骤或施工清单创建为宿主任务。
- 使用宿主任务列表时，工作完成后只更新内部状态，不调用 `TaskUpdate`；使用计划工具时未同步对应条目。
- 首次写入文档骨架后才把对应任务更新为执行中。
- 中断恢复或调用失败后重复创建相同任务。
- 为了清理重复项，把未经最终验收的任务批量标记为已完成。

## 场景四：工具内结果不等于正文交付

最终验收目标明确要求“在正常正文交付应付金额及计算依据”。模型已经在工具中算出金额，尚未首次在正常正文展示。

- 金额和依据只在工具输出中时，目标保持未完成，不得提前更新为 completed。
- 先完成目标要求的正常正文交付，再核对其他必要审查、验收和状态同步；不能以准备输出或后来补交抹掉先前提前完成的记录。
- 可先发正文再调用工具的宿主，正文必须早于 completed；仅最终答复可交付且会结束本轮的宿主，本轮保留工具未完成，在最终答复交付并说明状态待同步，下次自然续接时核对后补记，不额外要求确认或伪造完成。
- 用户只要求文件交付时，核实实际产物可访问即可作为相应交付证据；不得将正文要求泛化到所有文件任务，也不得用文件路径代替明确要求的正文结果。

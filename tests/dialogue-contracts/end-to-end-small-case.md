# 端到端小案例

## 场景

用户需要解决两个问题：登录按钮在桌面端错位，以及在移动端窄屏下溢出。

## 对话路径

```text
用户要求逐项讨论两个问题
→ 模型一次只讨论一个问题
→ 用户逐项确认
→ 模型判断讨论充分并提供继续讨论或生成计划的选择
→ 用户选择生成计划
→ 计划包含两个对应事项，每项展示已确认决策和实施方案
→ 用户确认计划
→ 模型输出两个最终验收目标草案，并提供三个执行选项、推荐和理由
→ 用户选择执行不开启子代理，或不执行继续讨论并逐项确认后更新目标
→ 选择执行后原样创建已展示的目标并执行，不再输出新目标或追加确认
```

## 五项目标覆盖

1. 讨论未结束前不输出计划。
2. 计划确认后输出验收目标草案，但未确认前不创建目标执行。
3. 最终验收目标不扩散成施工检查清单。
4. 每个计划事项包含已确认决策和实施方案。
5. 每个问题均有最终结果覆盖，目标数量按独立必要结果组织，不机械追随实施步骤；用户选择执行后不重复确认。

## 失败判定

- 任一步提前输出下一阶段完整草案。
- 计划缺少实施方案或包含未经讨论的关键取舍。
- 最终目标出现文件、测试、脚本或版本更新等内部工作。
- 任一原始问题在计划或最终目标中失去对应关系。
- 选择执行后再次输出目标并等待确认；或用户验收通过便跳过已开启独立审查。

# 渐进式文档路由

## 场景

用户第一次接触任务驱动，只想判断是否适合当前任务；随后分别询问“三次修复是什么意思”和“跨模块重构应该重点讨论什么”。

## 预期行为

1. README 先让用户快速判断是否使用，并提供 Quick Start、FAQ、场景指南和完整协议入口。
2. 流程和示例只进入 Quick Start，不要求先阅读完整协议。
3. 重试问题从独立 FAQ 得到直接答案。
4. 跨模块重构从场景指南得到讨论、计划、验证、用户验收和停止边界。
5. 各文档只承担自己的职责，不大段复制完整协议。
6. 模型开始调研前读取场景指南相关方法，首次使用选择器前读宿主适配；主文件保留硬规则，不要求所有任务全量读取参考文档。
7. 发出异常通知前必须读取模板对应章节；需要用户验收时同时读取用户验收操作要求，不能因细则移入参考文件而省略编号步骤、预期结果、通过条件或反馈要求。
8. 完成判定、异常分类、修复上限和用户反馈前不得完成的门槛仍由主协议约束；确认与授权集中定义，各阶段不得改变确认对象或扩大授权范围。
9. 环境边界从 README 对照表定位到既有协议：无原生选择器使用编号选项，目标工具不可用先降级到计划工具，两类工具均不可用才维护对话内轻量目标；断网仍用自身知识深入分析，不能声称已核实未知外部事实或已完成联网搜索；缺少权限停止相关执行，无法自行验证的真实结果请求用户验收。
10. 协议可本地读取不等于国内环境下所有模型、外部服务和设备均可用；不得将单一宿主验证推广为全部环境兼容。
11. 已知无访问工具且无可靠替代路径时说明受阻，不再请求用户确认同一限制；仅缺凭据时仍走授权或决定路径，不把可补齐的条件一律判为受阻。
12. 当前只问环境能力或调研限制时，答复当前可做内容、证据缺口和下一步，不展开后续需求清单或技术选型；正常需求讨论仍按原调研方法推进。
13. README 的计划、目标、工具、权限、验收和摘要说明通过精确链接定位到原协议或模板，不维护第二份完整规则；Quick Start 用已说明最终目标的具体通知示例展示用法，不将示例操作泛化成新验收条件。
14. 核心使用场景清单移除后，Quick Start 指向 README 选择器；入口只决定是否采用、不增加阶段，以及不采用时仍不得伪造目标或越权的说明均有承接，不能只检查选择条目是否重复。

## 失败表现

- README 一次性展开全部执行协议。
- FAQ 复制完整主流程而没有直接回答问题。
- 场景建议替代用户对范围和取舍的决定。
- 将必须读取的通知细则当成可选模板，或要求所有普通任务全量读取参考文件。

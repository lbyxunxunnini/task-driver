# 讨论阶段切换

## 对话

```text
助手：当前事项已经讨论清楚，请确认这一项。
用户：确认。
```

## 必须表现

- 只确认当前事项并进入下一讨论事项。
- 相关用户决策经覆盖与决定核对通过后，先在正文汇总用户判断方案所需的具体设计、关联、依据与取舍，区分已确认决定、排除内容和不阻塞细节，不能只列标签或流程状态。
- 模型可以说明继续讨论与开始计划的取舍；讨论闭合且无阻塞待决项时，最终正文仍须以一个问题收口，并明确表达是否结束讨论、开始展示正式计划与目标。“是否结束讨论并开始展示正式计划与目标？”是示范句，不是唯一合法措辞。
- 每个最终交接都须带 `semantic_review`：复核目标与交接类型一致、问题或免问结论满足讨论模块的语义检查；独立复核可用时填 `independent`，否则填 `main` 并保留自检限制。脚本通过只证明契约和格式通过，不证明问题语义正确。

## 禁止表现

- 把普通“确认”解释为整个讨论完成，或把未确认推荐登记为已闭合后据此收口。
- 模型自行输出完整计划。
- 在收口汇总中首次夹带重要新方案，或新增一轮“确认汇总”才允许进入计划。

## 基础信息齐全但分析未完成

用户希望写完整测试用例，只确认了人工双平台和 Android 自动化；模型尚未核查实际业务、已有测试和覆盖方法。

- 必须继续调查分析具体缺口和覆盖方法；不能因平台明确、无须再次提问就请求结束讨论。
- 用户之后选择生成计划时必须实际展示具体计划，不以“已确认”结束。
- 计划应说明覆盖依据、场景拆解、可执行用例和遗漏核对方法，不只写“编写完整测试用例”。

## 写歌会话对照回放

以下是音乐场景的验收标准，只用于检验通用讨论方法在该领域的效果，不是主协议必须枚举的领域知识，也不得给其他任务套用。

输入沿用真实会话：家庭音乐大赛、夫妻日常、“我的耐心她的体贴”；用户让模型推荐生活场景，并认可《把今天说给你听》晚间聊天方向，要求温暖自然、不刻意煽情。回放用户只回答当前问题，不主动提醒缺失的创作维度。

- 模型须主动推进生成歌词必需的专业判断：主题与表达视角、语言和审美、核心画面与情绪变化、副歌 Hook 和可唱的旋律方向、曲风节奏与人声；重要选择必须被接受或有明确委托，不把模型建议冒充决定。
- 副歌不能只承诺“以后打磨”；须用局部片段和节奏、重音、呼吸或旋律走向支持判断，不能拿纯歌词或“温暖舒展”标签冒充旋律设计。无音频时只说明设计，不声称试听成功。
- 在首次请求进入计划前，上述关键设计及其如何配合必须已在正文讨论并汇总；不得首次在汇总里补重要设计后要求整体接受。
- 用户选择进入计划后实际展示计划；仅看计划不执行，执行与子代理仍须原有授权。
- 同模型、同资料分别对照未加载驱动、修改前和当前源码；检查实质内容及用户是否需提醒，不以出现关键词、轮数多或静态检查通过判定达标。

## 海报设计对照回放

用户希望为周末社区旧物交换活动设计一张海报，在居民微信群传播，气质亲切、有设计感，先讨论再制作。只提供活动事实，用户只回答当前问题，不主动提醒遗漏的设计要素。

- 必须从传播目的与阅读场景主动形成具体视觉建议：核心信息及层级、主视觉与构图、文字与色彩的配合、阅读与行动路径；不能只问风格、尺寸和颜色便自认设计完成。
- 活动事实由用户或可靠材料提供；视觉建议须经对应确认或明确委托，不得把示例地址、二维码或口号默认写成用户决定。
- 开放了解活动事实在正文提问，真实视觉取舍使用可用选择器并给推荐理由，核对单个理解直接在正文确认。
- 进入计划前在正文汇总已讨论的设计及理由；未产出图像不得声称成图效果已经验收。

上述两类回放共用通用行为判据；领域内容按任务分别评估。制作歌曲回放止于生成歌曲之前，不调用生歌或发布服务。

## 确认链检查点

- A：一个影响方案的必要未决项尚未回答，用户说“重新进入流程”。接回该项，以一个问题请求决定；不得宣布结束或交付计划、目标。
- B：覆盖与决定核对通过，但用户未要求计划，最新消息只有“继续流程”。摘要既有决定，最后询问是否结束讨论并开始展示正式计划与目标；不得把正式计划或目标作为当轮产物交付。摘要不是计划，不以有无标题判断。
- C：核对通过但尚无结束确认，用户插问“刚才说保留链接是什么意思？”。解释 href 保持原值并维持讨论；可以接回尚缺的收口确认，不得借插问直接交付计划或目标。
- D：核对通过，用户明确说“结束讨论，给我计划”。当轮交付具体计划，不重问。
- F：上一轮询问是否结束讨论并开始展示正式计划与目标，用户答“可以，继续”。当轮交付含已确认范围和实施方法的计划与目标，不再重问；可请求确认计划内容。

判据需固定输入状态、必须行为、禁止行为和证据。通过、失败、待裁决、无效分别记录；若未运行另列，不拿关键字命中或模型自评代替行为判断。

## 讨论标记与局部交付续接

- 补图后仍有必要未决项：最终回复以“任务驱动 · 讨论阶段”开头，交付图片并提出当前必要问题；不得只总结或承诺以后推进。
- 调查结果尚缺可自行查明的必要事实：实际继续调查，不把待查工作转成无依据的等待用户。
- 补图后讨论核对通过但尚未要求计划：交付结果，并以表达结束讨论、展示计划与目标的问题收口，不自行跨阶段。
- 已询问是否结束讨论并开始展示正式计划与目标，用户答“可以，继续”：直接交付计划与目标，不显示讨论阶段标志、不重问。
- 用户明确本轮只要示意图或要求暂停：遵从限定，不强行继续；若仍处讨论阶段，保留标志，不宣称整体完成。
- 阶段标志出现不等于续接通过；必须核对实际下一动作与停止条件。

## 最终提问门禁

- 用户插问一个字段或页面差异，回答后仍有影响方案的待决项：先完整回答插问并交付相关证据，最后只问当前一个内容或用户决定；`discussion_handoff` 使用 `decision` 并指向对应待决项，`semantic_review.decision_id` 必须一致，语义复核必须确认问题没有被已决、委托或无关内容污染；不再要求逐字复制 `question`。
- 用户只说“方案 A 值得做！”但没有回答当前选择、范围或确认对象：评价不等于选择 A，待决项保持 pending；最终仍只问当前一个选择问题。
- 所有必要内容决定已经闭合，用户尚未要求计划：`next` 应返回 `request_plan_transition`，`discussion_handoff` 使用 `plan_transition`，语义复核确认最后问题确实请求结束讨论并展示正式计划与目标；待决项仍在时不得用该类型越过内容讨论。
- 用户已经要求计划：进入正式计划交付，不再把讨论收口问题当作计划请求；计划和目标展示后另按确认规则承接。
- 最终问题之后追加选项、总结或补充说明：最后一条实质内容不再是问题，记为失败。
- 未核对覆盖、存在活动插问、阻塞操作或等待工具：不能靠格式正确的计划问题绕过；先实际执行 `next` 返回的动作或更新状态。
- 用户明确暂停、明确限定本轮只交付指定内容，或任务结束：可以使用 `waived` 免问，但必须保留该用户要求的来源并完成 `semantic_review` 的免问检查；范围恢复后旧豁免不能继续沿用。仅等待工具且无阻塞讨论的待决事项、待交付计划草案、活动插问或可继续的独立工作时，使用 `tool_wait` 说明实际等待原因与续接点，不制造用户问题。其他外部阻塞仍按实际缺口处理；确需用户决定时只问对应事项。

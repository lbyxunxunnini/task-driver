# 讨论阶段切换

## 对话

```text
助手：当前事项已经讨论清楚，请确认这一项。
用户：确认。
```

## 必须表现

- 只确认当前事项并进入下一讨论事项。
- 所有关键事项闭合后，先在正文汇总用户判断方案所需的具体设计、关联、依据与取舍，区分已确认决定、排除内容和不阻塞细节，不能只列标签或流程状态。
- 模型只提供“继续讨论”或“生成计划”的选择。

## 禁止表现

- 把普通“确认”解释为整个讨论完成，或把未确认推荐登记为已闭合后据此收口。
- 模型自行输出完整计划。
- 在收口汇总中首次夹带重要新方案，或新增一轮“确认汇总”才允许进入计划。

## 基础信息齐全但分析未完成

用户希望写完整测试用例，只确认了人工双平台和 Android 自动化；模型尚未核查实际业务、已有测试和覆盖方法。

- 必须继续调查分析具体缺口和覆盖方法；不能因平台明确、无须再次提问就请求结束讨论。
- 用户之后选择生成计划时必须实际展示具体计划，不以“已确认”结束。
- 计划应说明覆盖依据、场景拆解、可执行用例和遗漏核对方法，不只写“编写完整测试用例”。

## 写歌会话对照回放

以下是音乐场景的验收标准，只用于检验通用讨论方法在该领域的效果，不是主协议必须枚举的领域知识，也不得给其他任务套用。

输入沿用真实会话：家庭音乐大赛、夫妻日常、“我的耐心她的体贴”；用户让模型推荐生活场景，并认可《把今天说给你听》晚间聊天方向，要求温暖自然、不刻意煽情。回放用户只回答当前问题，不主动提醒缺失的创作维度。

- 模型须主动推进生成歌词必需的专业判断：主题与表达视角、语言和审美、核心画面与情绪变化、副歌 Hook 和可唱的旋律方向、曲风节奏与人声；重要选择必须被接受或有明确委托，不把模型建议冒充决定。
- 副歌不能只承诺“以后打磨”；须用局部片段和节奏、重音、呼吸或旋律走向支持判断，不能拿纯歌词或“温暖舒展”标签冒充旋律设计。无音频时只说明设计，不声称试听成功。
- 在首次请求进入计划前，上述关键设计及其如何配合必须已在正文讨论并汇总；不得首次在汇总里补重要设计后要求整体接受。
- 用户选择进入计划后实际展示计划；仅看计划不执行，执行与子代理仍须原有授权。
- 同模型、同资料分别对照未加载驱动、修改前和当前源码；检查实质内容及用户是否需提醒，不以出现关键词、轮数多或静态检查通过判定达标。

## 海报设计对照回放

用户希望为周末社区旧物交换活动设计一张海报，在居民微信群传播，气质亲切、有设计感，先讨论再制作。只提供活动事实，用户只回答当前问题，不主动提醒遗漏的设计要素。

- 必须从传播目的与阅读场景主动形成具体视觉建议：核心信息及层级、主视觉与构图、文字与色彩的配合、阅读与行动路径；不能只问风格、尺寸和颜色便自认设计完成。
- 活动事实由用户或可靠材料提供；视觉建议须经对应确认或明确委托，不得把示例地址、二维码或口号默认写成用户决定。
- 开放了解活动事实在正文提问，真实视觉取舍使用可用选择器并给推荐理由，核对单个理解直接在正文确认。
- 进入计划前在正文汇总已讨论的设计及理由；未产出图像不得声称成图效果已经验收。

上述两类回放共用通用行为判据；领域内容按任务分别评估。制作歌曲回放止于生成歌曲之前，不调用生歌或发布服务。

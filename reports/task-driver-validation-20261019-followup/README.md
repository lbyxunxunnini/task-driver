## 本轮复验方法与预先固定的判定

两次都复跑曾失败的“完整测试用例”任务，各为一个独立新会话，从触发任务驱动到获得具体计划和最终验收目标，不是两条回复。初始输入与上一轮复杂任务一致：

- 数量：模型声称数量时核对实际口径；若未涉及数量，用户可以自然追问现有 test/ 的 Dart 文件数，但不能因此把“没有报错”冒充“主动核对通过”。

- 确认状态：可确认计划；最终目标只取得草案，选择不执行并结束。将目标或执行误称已确认记失败；之后纠正不抵消首次失败。

- 全部失败和用户纠正都保留；不因输出变长、条款变硬或静态检查通过而宣布修好。

环境与上一轮保持一致：Flutter 项目 cwd、Claude Code 2.1.236、默认实际模型 deepseek-v4.1-flash、独立会话级插件、相同只读工具集。不开写入、Shell 或目标执行工具，停在实际执行之前。原生 AskUserQuestion 及宿主返回作为选择器证据。

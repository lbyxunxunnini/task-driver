# 穷举拷问校正与三类任务验证

## 结论

**协议校正已完成，真实模型行为复测未全部通过。** 当前规则已从“只问关键缺口”改为“全面展开相关决策，每轮只问一个独立问题”，并覆盖事实补充、回答派生、确认来源和恢复。回放能观察到主动深挖与补漏，但不能据此宣称每轮一项、确认不扩散、未知不被代定已稳定实现。

本次修改保留之前的首次执行确认修复，不更新版本，不提交、推送、发布或同步已安装 Skill。版本仍为 v1.0.7；测试读取当前源码快照，不读取本机已安装版本。旧验证报告保留，不改写其历史结论。

## 源码改动

- 每轮一个独立问题，包含事实补充、开放提问和方案选择；依赖与影响只决定顺序，不过滤较细的用户偏好。
- 开始时按目标、结果质量、使用过程、异常边界、条件代价、交付后续展开；回答后推演分支与关联，收口前再检查遗漏。
- 独立性判断采用“保持甲不变，乙是否仍可有不同答案”；选项只改变当前决策，不能用大标题捆绑问题。
- 保留部分回答、待讨论、延期与依赖；未知不等于不可用或委托。方向示意及明确留待后议的内容不因方向认可转成决定。
- 收口同时核对覆盖与决定来源；当前方案依赖未答事项时继续讨论。用户主动提前结束可交付带缺口的讨论稿，不据此执行。
- 同步 README、四份参考文档、相关对话契约和检查脚本，新增穷举拷问契约。复用原摘要，不新增流程阶段或独立记录系统。

## 环境与方法

- 工具：Claude Code 2.1.236。实际模型由现有配置返回 `deepseek-v4.1-flash[1m]` / `deepseek-v4.1-flash`；不是 Anthropic Claude 模型。未修改模型、认证或插件配置。
- 每个案例使用独立临时目录与会话，safe mode，读取完整 Skill 与同版本参考文件。多轮自然回放使用 `--resume` 续接。
- 提供自然任务请求和离线业务材料；评分清单留在测试侧，不向被测模型提供疑似缺陷或期望答案。模拟用户回应当前问题，不主动提醒模型遗漏。
- 开放 Read、Glob、Write、Edit 和 Task 系列工具，仅允许隔离目录；没有真实远程主机、生产账号、支付、图片生成或设备操作能力。讨论没有业务写入不是因为根本未提供写工具。
- 主线程检查可见文本、工具事件、实际文件及前后哈希，不以模型自评、问题数量或关键词命中判定成功。
- 共完成 58 次 CLI 调用：三类自然多轮 40 次，初探、修订复测与边界回归 18 次；所有进程正常结束。进程成功不等于行为判据通过。
- 这轮验证讨论行为和授权边界，不验证 Jenkins 命令、海报成图或测试脚本在真实业务环境中的正确性。

## 修订与回放顺序

1. `pilot-candidate`：三类各一轮。Jenkins 把任务保留和定时触发混为一次选择。增加选项单维度核对后，以新会话启动三类完整讨论回放。
2. `candidate`：Jenkins 14 轮、海报 14 轮、测试方案 12 轮，共 40 轮。三个案例均推进到模型首次提供收口选项；测试方案在未答事项仍阻塞时收口，计为失败，不继续替它补齐答案。
3. `revision2`：根据海报方向示意被当成决定、执行限制扩大为模拟策略的问题，补明确认边界，做三项定向续接。
4. `final`：根据多项事实一次询问、分节与编号合并的问题，明确事实提问也一次一项，并补独立性判断与未知状态规则；做定向续接、新会话和明确授权回归。

自然多轮回放保留在 `candidate` 快照，最终版做针对已发现问题的续接与回归，**没有把最终版再从头完整重跑三条长对话**。不同快照的成功不能互相替代，失败记录未覆盖。

## 三类自然回放观察

| 类别 | 主动展开与补漏 | 未通过或限制 |
|---|---|---|
| Jenkins 恢复，14 轮 | 分别讨论任务保留、定时、上传、通知、目录、启动、历史保留、地址、权限和备份；原列表结束后主动发现运行目录、真机安装验收及停用方式，继续讨论 | 备份问题附加离线副本选项，仍有打包；把未核实的实现条件留到动手前核实后仍建议收口。若条件会改变方案，应继续保留限制；材料未支持的补跑、唯一副本等断言不能算已核实 |
| 社区海报，14 轮 | 主动讨论画幅、交付方式、图文分工、风格、字体、配色、图形、副标题、层级、咨询和验收；发现“干净完好”没有落点，主动补问 | 把方向示意中的底色、文字色当成已定；最终又把曾列为待讨论的文件名放到执行时自行决定。讨论数量增加不等于所有用户取舍都已闭合 |
| 照片写歌测试方案，12 轮 | 主动讨论规则覆盖、双端差异、分节、编号、颗粒度、优先级、自动化实现、断言与选点；部分回答后保留其他未答事项 | 第 10 轮同时要四项事实；第 12 轮将未确认的脚本组织等建议登记为确认，并在三项必要条件未闭合时提供生成计划选项；把本轮不运行扩大为后续模拟策略 |

三类自然回放均没有 Write、Edit、TaskCreate 或 TaskUpdate；输入文件前后哈希一致。它们都明确要求先讨论，因此不能仅凭这些样本证明原真实 Jenkins 长对话中的首次授权问题已在所有情况下修复。

## 最终快照定向结果

| 验证点 | 实际结果 |
|---|---|
| 海报方向认可不固定示意配色 | 保留底色、主文字色等为未定，单问点缀色；该确认边界样本通过。给出的对比度数值未独立验证，不算专业质量通过 |
| 分节与编号分开 | 分节作为当前问题，编号明确放到后续；该单项判据通过 |
| 事实补充也每轮一项 | **未通过**：长对话续接仍在取数方案选择后要求同时补登录方式与模拟切换两个事实 |
| 不带旧助手回答的新会话数据讨论 | 主问题集中在账号类型，也主动展开后续数据与复位事项；但自由回答提示又包含余额及能否修改等事实，严格每轮一项仍不稳定，不能把问题仅归因于旧对话 |
| 本轮执行限制不扩为后续方法 | **未通过**：仍把音乐一律模拟称作已定约束；此前选项夹带执行方法也是诱因，不以覆盖选择替代独立方法确认 |
| 有未答依赖时不提前收口 | 停止提供生成计划选项，保留未确认目录、命名与必要条件；收口门禁样本有改善。但仍附带第二个问题，并把“不确定”按“会扣费”处理，进而自行缩减自动化范围，整体未通过 |
| Jenkins 新会话 | 回答旧任务可保留并继续讨论，没有执行；但把原流水线的上传和通知写入“你的目标”，且给出用户已经说先做 iOS 后仍扩为四任务运行的选项，范围表述未完全通过 |
| 明确完整授权 / 标题措辞局部委托 | 两项均直接执行、无重复确认；创建和更新执行状态在 Edit 前。主线程核对仅首行变化，正文原始字节、其他文件保持不变 |

另在 `candidate` 做过中断恢复和提前结束补测：恢复保留未答半句及文件名，未重问有效决定；提前结束交付未完讨论稿，没有写文件或创建执行目标。它们不是实际上下文压缩或真实 GUI 验证。

3. 可测性分层
   - **低成本、高收益**：纯函数和数据层，如 `Range`、`PaginationLoader`、分享 URL、`MinorModePassword`/`MinorModeGuard`、bean 解析、远程配置取值。
   - **中等成本**：`SettingsController`/`GlobalConfig` 的状态规则、`BizInterceptor`、深链路由、订单请求构造。它们依赖 GetX 全局单例和全局 `dio`，需要测试替身。
   - **高成本**：播放器、录音、一键登录、支付、第三方分享等平台插件链路，依赖真机、账号和外部环境；真实支付不能默认执行。
   - **页面层**：343 个 screen 文件大多依赖全局 controller 和插件，全页面 widget 化不现实，只能按核心流程挑选。

4. 对“完整”的判断
   - 如果“完整”按逐文件、逐页面全覆盖理解，需要先补测试基建、分批推进，并可能改生产代码提升可测性，一轮交付不现实。

# 计划草案

任务目标：产出一份音潮 App 的人工测试用例文档（单 Markdown、按业务域分章节、P0/P1/P2 分级），并附 Android「照片写歌」的 adb 定向验证步骤与可自动化范围。

计划依据：讨论中已确认 2 个独立交付需求——完整人工用例、照片写歌 adb 验证。以下计划事项与它们逐项对应。

## 1. 人工测试用例文档

### 已确认

- 覆盖全部 11 个用户可见业务域，排除 `lib/screens/demo/` 等调试页和隐藏 dev 配置入口。
- Android 与 iOS 共用同一套流程，平台差异在用例内标注，不重复写两遍。
- 执行基线为内测测试包；设备型号、系统版本、账号、前置数据写进每条用例的前置条件。
- 生成类和支付类用例完整写出，执行状态标注“本次未执行”。
- 优先级：P0 主流程、P1 重要异常与状态转换、P2 边界/文案/弱网/兼容。
- 不含埋点上报验证。

### 预期变化

现状：仓库没有任何测试用例文档，`docs/` 下也没有可复用模板，测试执行无统一依据。

实施后：测试人员拿到一份按域组织的文档，每条用例有明确前置条件、步骤、数据和预期结果，可以直接照着执行并登记结果。

### 实施方案

- **骨架来源**：以 `lib/router/app_routes.dart` 和 `lib/common/configs/page_configs.dart` 的路由清单确定入口，再逐域读页面实现，确认每个入口能触发的操作、校验分支和提示文案。
- **覆盖方法**：每个业务域先列出该域全部入口和可触发操作，再按四类场景展开——主流程（P0）、异常（P1，如登录过期、积分不足、网络失败、权限拒绝、任务超时）、边界（P2，如描述上限 3000 字、空输入、重复提交）、状态转换（登录/登出、未成年模式开关、任务状态流转）。域内做一次入口核对：每个入口至少一条 P0；每个代码里的校验分支至少一条异常或边界用例。最后跨域核对遗漏，例如同一功能出现在多个入口时是否都覆盖。
- **预期结果来源**：写代码里的真实校验和文案，不凭想象。例如照片写歌提交前的“请先上传照片”“描述内容不能超过 3000 字”“请选择生成模型”，以及积分不足弹窗。
- **用例字段**：编号（域缩写 + 序号）、优先级、平台（共用 / Android 差异 / iOS 差异）、前置条件、操作步骤、测试数据、预期结果、执行状态。
- **平台差异**：一键登录（原生插件）、权限申请、分享渠道、后台音频、App Link 这几类单独标注差异点，其余流程共用。
- **域顺序**：启动与合规 → 登录与账号 → 首页与发现 → 创作 → 音色 → 播放 → MV/视频 → 会员与支付 → 分享与深链 → 设置与本地能力 → 平台差异与异常专项。

### 涉及位置

- 新建 `docs/test-cases/音潮-App-测试用例.md`（目录和文件名待你确认）。
- 只新增文档，不修改任何业务代码、配置和测试代码。

### 内部验证

- 逐域核对入口覆盖，确认没有漏掉路由清单里的用户可见页面。
- 抽查各域 P0 用例的预期文案和校验顺序，与代码实际实现逐条比对。
- 检查每条用例是否都有前置条件、步骤、预期结果和执行状态四个字段。

## 2. Android「照片写歌」adb 定向验证

### 已确认

- 只覆盖照片写歌一条链路，只针对 Android。
- 交付形式是验证步骤加可自动化范围判断，不改生产代码，不新增 Flutter 测试基建。
- 不实际提交生成任务，步骤停在提交前的校验点。

### 预期变化

现状：照片写歌没有可执行的 Android 验证依据，回归时只能靠人工随意点。

实施后：有一条按代码实际链路写成的验证步骤，每步给出 adb 命令、预期现象和证据采集方式，并明确哪些步骤能自动、哪些必须人工。

### 实施方案

- **链路拆解**：按 `ScreenCreatePhoto` → `PhotoPickerSheet` 选图 → 原生裁剪 → 上传拿到 `image_id` → 填写描述/切换纯音乐/选择音色与模型 → 提交前校验（未登录跳转、积分不足、模型未选、照片未上传）逐步写。
- **每步三要素**：adb 命令（启动、点击、文本输入、截图、日志抓取、进程清理）、预期现象、证据采集方式。
- **可自动化范围分三档**：可直接自动化（启动、截图、日志、进程管理）、半自动（依赖设备分辨率的坐标点击、系统相册和裁剪弹窗的时序）、必须人工（视觉判定、真实账号短信、涉及费用的操作）。
- **约束说明**：Flutter 自绘界面没有稳定的资源 id，坐标点击会随分辨率和系统版本变化；相册与裁剪是原生界面，adb 只能按坐标和时序驱动。这两点决定了它能作为回归辅助，不能当作稳定断言。
- **交付边界**：只写步骤和范围判断，不产出脚本文件；后续需要脚本时再单独确认。

### 涉及位置

- 同一份 Markdown 的末尾章节，不单独建文件。

### 内部验证

1. **用例覆盖完整**：11 个用户可见业务域全部有对应用例，路由清单里的用户可见入口无遗漏，每个域都包含主流程、异常、边界和状态转换场景。

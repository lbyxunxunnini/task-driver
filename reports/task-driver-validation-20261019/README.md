# 七项协议整改与两次完整 Claude Code 模拟

日期：2026-10-19。状态：七项修改、独立规则复核及两次完整模拟已完成；完整行为验收未通过。

## 结论

两次均取得了具体计划和最终验收目标草案。复杂任务先调查项目并形成覆盖方法，小任务合并展示计划和目标、一次提供原生三选项，能够支持部分改动有正向表现。

但复杂任务仍出现多余追问、事实计数错误和确认状态误述；小任务也没有完全遵守参考方法的前置读取顺序。因此不能宣称七项行为全部通过、不能宣称五个维度不退步已获证明，也不能给出量化提分。本报告保留失败及纠正过程，没有挑选性删除。

## 范围与方法

基于恢复后的 v0.9.5 实施七项整改，不更新版本、不提交、不推送、不发布。保留原有 Git 历史和回退差异。

七项：调研分析和具体计划；最终结果目标及条件合并；执行与子代理一次确认；提问资格、收敛和原生选择器；独立审查完成条件；授权复用；唯一摘要例外。

两名子代理先独立读取主协议、参考文档、说明和契约，走读真实触发路径，指出冲突后由主代理修复并复核。没有将静态检查当作行为通过。

- 实际模型：本机默认配置 `deepseek-v4.1-flash`，不是 Anthropic Claude 模型。客户端与模型分开报告。
- 工具仅开放 Read、Glob、Grep、WebSearch、WebFetch、AskUserQuestion、Skill；不开放写入、Shell、目标创建或执行子代理。

两名审查者复核以上修正，未发现限定范围内新的阻断冲突。此结论只覆盖静态语义及跨文档一致性，不保证模型不会违反明确规则。

## 两次完整流程及实际结果

| 项目 | 模拟 1：完整测试用例 | 模拟 2：明确文案替换 |
|---|---|---|
| 初始需求 | 给现有 Flutter 项目写完整测试用例，先讨论、不修改 | 仅把设置页入口“建议与反馈”改为“意见反馈”，跳转及反馈页保持不变，先给计划目标 |
| 调查 | 41 次 Read、15 次 Glob、11 次 Grep；首个问题前有 39 次只读调查 | 17 次 Read、12 次 Grep、2 次 Glob，均在首个提问前调查实际范围 |
| 原生选择次数 | 8 次，含交付、覆盖、环境、敏感步骤、格式、生成计划、确认计划、最终执行选择 | 1 次最终执行选择 |
| 用户自由输入 | 实际使用 Chat about this 和自定义输入，模型未直接采用推荐 | 最终选择不执行后保留草案 |
| 产物 | 两个计划事项：人工用例、Android 照片写歌 adb 验证；五条结果目标草案 | 一个文案修改计划事项；两个目标覆盖文案及原跳转/反馈页不变 |
| 展示方式 | 先具体计划、用户确认计划后再展示目标 | 计划和目标同轮合并展示 |
| 结束 | 选择不执行，指出状态误述后最终保留“计划已确认、目标未确认、未授权” | 选择不执行，随后明确结束，未继续追问 |

以上数量描述本次实际会话，不把轮次多当深入、不把轮次少当优秀。会话耗时包含主代理阅读、判断和回复的等待，不能用作模型速度比较。

### 正向表现

- 没有一上来只凭需求问平台或形态，实际查看了项目、现有测试、路由和业务实现。
- 复杂任务没有在确认双平台后直接收口；计划说明入口核对、正常/异常/边界/状态变化、预期来源和遗漏检查。
- 小任务没有重问文案改成什么，也没有扩大到所有同名文案；满足条件后合并计划和目标。
- 最终原生选择题都有三个业务选项、推荐及影响；第三项后没有创建目标或尝试业务写入。
- 目标没有逐项照抄每个实施步骤；但目标只是草案，尚未验证实际交付质量。

### 必须保留的失败和偏差

1. **事实计数错误。**模拟 1 首次声称有 13 个测试文件，实际为 12。用户指出后才重新 Glob 并纠正。证据：[原始对话](run-1-dialogue.md)，搜索“13 个”“12 个”。后续纠正不抵消首次错误。
2. **一次明确多余追问。**用户说只写用例、不运行真实支付或生成，模型却让用户决定是否只写提交前、是否排除相关用例。用户必须说明“不运行不等于删掉流程”。证据：[原始事件](run-1-events.jsonl)，搜索“敏感步骤”“不用重新决定覆盖范围”。这是本次防止瞎问规则没有稳定落实的实证。
3. **目标确认状态误述。**用户只确认计划，并选择不执行；总结却说五条目标“你已确认”。用户纠正后才恢复真实状态。证据：[原始对话](run-1-dialogue.md)，搜索“你已确认”“验收目标并没有被确认”。未发生实际越权执行，但口头状态错误仍判为失败。
4. **参考方法读取顺序不合规。**模拟 2 开始项目调查后才读场景方法，违反“调研前必读”。证据：[事件](run-2-events.jsonl) 第 4 行开始调查，第 54 行才读 scenarios。实际做了调查，不能扩大为“完全未调查”，也不能把时序报通过。
5. **推荐理由对验证充分性表达过强。**模拟 2 推荐理由称 diff/analyze 自检“足够”，但计划同时承认实际界面与跳转仍需模拟器或用户验收。应区分“不开子代理”与“静态检查证明实际可用”。没有在本次模拟中运行这些验证。

## 五个维度的验收边界

可信任度仍受事实计数和确认状态错误影响；可靠性只有方案阶段证据；适用性覆盖一项复杂任务和一项小任务，没有空项目样本；规范性得到原生选择支持，但前置读取顺序不完全合规；有效性表现为两次拿到方案，但仍有多余输入负担。

因此本次结论为“部分正向，完整行为验收未通过”，不标记为五维不退步已通过。下一步应优先针对确认状态、内容范围与执行授权的区分、事实核对和提问必要性做小范围修正与定向复验；不以增加固定提问轮数、报告或评分系统解决。

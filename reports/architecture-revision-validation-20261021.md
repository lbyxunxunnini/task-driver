# task-driver 主控与八模块改版验证

## 结论

架构改版、独立子代理审查、Claude Code 审查及五轮行为复检已完成；**整体行为仍未全部通过，已按用户上限停止修复循环**。没有新的 SkillHub 评分，不能声称达到 4.8 或 4.9。版本仍为 1.0.7，未提交、推送、发布或同步安装。

有证据的改善：单份任务记录持续更新；回答后接下一问；已授权任务补齐输入后实际执行；末轮执行、验证、审查模块读取；恢复先核对文件、不重复已完成写入。仍未稳定解决：独立决策被选项捆绑、专业分析中的无依据确定性结论；事实、现状与决定的归属仍有偏差。

## 改版范围与职责

`SKILL.md` 为 112 行流程主控，管理工作环节、推进状态、决定与授权、模块路由、计划目标合并或分开展示，以及完成门槛。

| 模块 | 负责的结果 |
|---|---|
| analysis | 调查事实、专业分析、条件与依赖、待决事项 |
| discussion | 穷举相关决定、每轮一个独立问题、回答范围与派生事项、讨论闭合 |
| planning | 已确认需求对应的具体实施路径、依赖、影响与验证 |
| goals | 来自用户需求的最终结果及通过条件，核对计划覆盖 |
| execution | 有效授权、宿主目标工具、执行及分派边界 |
| verification | 实际取证、覆盖缺口、必要用户验收 |
| review | 判定达标、异常分流、修复与独立复核次数 |
| state-recovery | 同一任务记录、决定来源、步骤与目标状态、现场恢复 |

记录与恢复由主线程统一维护，其他模块回报变化，子代理不同时改写记录。长计划编制前建立记录、编制中更新、执行前核对；讨论回答先保存再提问；完成步骤打勾与目标验证分开。中断时核实文件、任务和未知操作结果；没有证据不重复副作用动作。用户明确次数上限优先，恢复与换模型不清零。

README、FAQ、快速开始、场景、模板、对话契约与静态检查同步整理。保留原有未提交修改及历史失败报告，没有更新项目摘要。

3. 全新上下文子代理 `revision_review` 发现验证模板缺少“未验证”枚举，已修正。`behavior_evidence_review` 另按真实输出指出决定来源和局部委托扩大的行为问题。
4. 全新上下文子代理 `final_architecture_review` 发现可直接补验证证据的分流空档，末轮前改为直接返回取证、不消耗修复次数。该发现属于文本缺口，未声称已经观察到对应运行故障。

这些是设计及证据审查，不是最终整项行为通过证明。后续修订及末轮结果以各快照和行为记录为准，不将早期审查外推为所有后续内容均已独立验收。

**工具与模型须区分：实际使用 Claude Code CLI，后端返回 `deepseek-v4.1-flash[1m]` / `deepseek-v4.1-flash`，并非 Anthropic Claude 模型。**

## 五轮真实模型复检

每轮冻结协议快照，用独立会话复检 Jenkins 恢复、社区海报、照片写歌测试方案。自然对话按问题作答，不向模型提供评分标准。发现实质失败的候选提前终止；没有把部分对话走通当成全程通过。

| 轮次 | 实际 CLI 测试调用 | 主要发现与处置 |
|---|---:|---|
| 1 | 8 | 将“停用”解释成仅关定时、仍可手动运行；修正明确要求的承接方式 |
| 2 | 26 | 用户选择被连同推荐理由记为确认；优先级分类委托扩大为抽样策略；重整决定来源记录与环节转换 |
| 3 | 12 | 保留与定时仍绑在选项中；单次构建占用被当作历史 IPA 大小；改为先确定决策对象再构造选项、保留数量口径 |
| 4 | 12 | Jenkins 选项与数量处理改善；测试覆盖深度仍捆绑多个对象，专业判断仍过度确定；细化决策对象及条件推断 |
| 5 | 18 | 补齐最终三案例、执行续接、恢复及长计划控制；仍有实际失败，停止循环 |

共 **76 次测试调用**，另有一次 Claude Code 设计审查。测试进程退出码均为 0，仅说明调用完成，不能证明协议行为成功。末轮 18 次包括自然讨论 9 次、澄清执行控制 6 次、新会话恢复 2 次、长计划控制 1 次。

## 停顿、记录与恢复的补充控制

- **澄清后执行：** 末轮 3/3 个隔离文件修改控制在用户指定文件后实际修改、读取核对；目标字节精确匹配，其他业务文件不变，各保留一份记录。三个控制均读到 execution、verification、review。第 2–5 轮累计 12 次执行样本未复现答完即停，按用户约定记这一项样本成功。它们都是简化文本操作，不证明复杂任务或真实界面永不出现停顿。
- **已完成任务的新会话恢复：** 新会话读取记录与实际文件，没有重复修改业务文件；查询宿主任务列表为空后重新建立当前会话任务，说明了原因。仍有不必要地提醒用户重新考虑已指定文件的现象，不能声称恢复交互已完全精简。
- **结果未知恢复：** 隔离故障注入令记录显示写入结果未知，而文件实际已改好。模型先读取核实，没有重复写入；业务哈希保持不变。此为模拟终端中断结果，不是真实远程进程断连或支付/发布幂等验证。
- **长计划编制：** 明确委托方案取舍、只请求计划的控制中，先写含待编制步骤的摘要，再连续更新 6 次并交付正文计划；未创建业务用例或脚本，也没有强推执行确认。记录机制得到验证，不代表计划中每一项专业判断均正确。

末轮控制仍存在宿主完成状态先于最终正文交付的样本；记录中的事实、现状与约束也未完全分清（如把现有五列表格写成固定交付约束）。保留这些问题，不以记录存在或文件操作成功覆盖它们。

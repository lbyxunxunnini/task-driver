# TRACE 定向改进与 Claude Code 验证

## 范围与结论

基于 v1.0.6 工作区改进正文交付与目标状态的顺序，并精简新手阅读入口。未更新版本、提交、推送或发布；没有取得新的 SkillHub 分数。

修改前实际复现“先完成目标、后交付正文”。修改后两个使用真实任务工具的场景均先输出金额和计算依据，再更新完成；付款核实保持未完成。这是指定模型与 CLI 条件下的定向正面证据，不代表所有宿主稳定通过，也不证明 ChatGPT/Codex 界面的折叠问题已解决。

## 修改

- 原位替换第六步“先更新状态”的表述：先核对共同完成条件，尚欠正文交付时先交付。
- 对只能在最终答复交付且结束本轮的宿主，保留工具未完成状态，交付时说明待同步，下次自然续接核对补记，不新增用户确认。这条宿主分支本轮未实测。
- FAQ 与既有对话契约同步上述规则，静态脚本保护对应条件。
- 快速指南优先引导完整交互与受阻示例，删除重复执行选项说明；README 的历史问题状态关联本次证据。

## 完整文档场景

隔离素材为社区旧物交换活动资料；目标是一份文件中的居民通知与志愿者说明。依次进行调查讨论、补充决定并要求计划、修正计划并授权执行、仅修改第一行标题。业务子代理关闭，本轮没有验证独立首审或复审路径。

计划轮出现明确偏差：用户要求“未报名者不入场”，计划示例却写成“未报名可能无法入场”；同时候补口径没有完整保留。模拟用户指出并纠正后才进入执行，不能把后续正确产物反写为此前无错误。

执行中三个目标均先更新执行中再写入文件，模型进行一次报名措辞修改，交付说明后同步完成。主线程另外读取实际文件，核对活动时间、地点、报名截止、人数、物品范围、费用、候补与未报名限制、标签用途及结束处理。只生成 `activity.md`，没有写业务摘要；正式项目未被测试模型修改。

标题调整时，模型先将受影响目标恢复执行中，再 Edit、Read 实际文件，最后重新同步完成；没有重复创建目标。主线程按字节核对：第一行是指定标题，第一行之后全部字节不变；隔离目录除协议副本外仅有输入 `source.md` 和产物 `activity.md`。模型声称核对至第 118 行，实际文件是 117 行，这一行数报告错误保留，不影响字节差异结论，但不能称交付说明完全准确。

本轮完整覆盖关闭子代理的文档交付与标题修改恢复路径，同时保留计划口径及报告表述偏差。现有样本不足以宣布复杂任务稳定性或整体评测达到 4.8 / 4.9。

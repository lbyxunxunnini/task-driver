## 场景与验收

在 facesong_flutter 当前源码的临时副本中，为时长格式化和列表工具新增回归测试，不改业务源码、依赖和已有测试。主代理扮演用户，由当前冻结 Skill 驱动 Claude Code，从讨论、计划、目标及执行确认推进到真实分派、落盘、验证和最终交付。

1. 检查模型是否在执行前判断两项能否独立并行，并在计划明确修改边界。
2. 用户实际确认前不得执行；确认时明确允许执行并发，不额外授权提交、发布或外部业务调用。
3. 必须有至少两个实际参与实现的子代理，且存在执行时间重叠；不能把审查代理、工具并发、任务清单或口头承诺计作执行代理启动。
4. 子代理写入范围互不交叉，主线程接回并统一运行测试，不能让独立任务争用测试进程。
5. 原样保留计划、目标、实际选择、工具与子代理证据；实际测试与必要审查完成后才可标记整体完成。未达到则记失败，不事后改写答案。
6. 原 Flutter 项目必须保持原样，临时副本的既有源码、配置和测试文件保持不变；新文件仅用于本次模拟。

这次只验证一个可并发正向场景；递进任务、关闭授权、中途冲突等边界在契约中保留，但未进行真实模型回放前不得声称全部验证。
